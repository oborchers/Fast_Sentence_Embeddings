FastText parameters accept NumPy integers like other integer API parameters, check their
types and bounds before conversion, and store them as Python integers. Invalid types,
including booleans and floats, raise an error naming the affected parameter instead of
failing during JSON serialization.

Batch calls with a resume sink now explain the supported `positions=True` route for
Encoder, Classifier, Regressor and Heads, alongside the eager and non-resume alternatives.
