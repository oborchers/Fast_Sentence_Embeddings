## Model2Vec models and from_pretrained

Binding for every 2.0 module (formerly under "2.0 design").

`Encoder.from_pretrained(repo_or_path, *, revision=None, token=None, cache_dir=None, local_files_only=False, truncate=True, max_length="model", truncate_dim="model", normalize="model", mmap=False)` gives the encoder of a pretrained model. It converts a model of another library on every call, in memory (nothing is hosted, the license of the model applies unchanged), or loads an fse encoder.

- **Where.** An existing local path is a `.safetensors` file (an fse encoder, `Encoder.load`) or a folder. Anything else must be a Hub id `namespace/name`, read by `fse._hub` with huggingface-hub (a dependency, 1.0 or newer, imported only there and only on first use, so `import fse` and local models never load it). `revision`, `token`, `cache_dir` and `local_files_only` are for the Hub and raise with a local path.
- **What** (`fse._encoder._pretrained`), in this order:
  - `"model_type": "fse"`: an fse folder (*Hub folders*): its `config.json` names `model.safetensors`, an encoder (a linear head raises, naming `Classifier.from_pretrained` and `Regressor.from_pretrained`), and the encoder loaded from it must have the config's fingerprint. `mmap` maps a local one.
  - a `config.json` with model_type `model2vec` or none: a Model2Vec model, as model2vec 0.10.0 finds one (`config.json`, `model.safetensors` and `tokenizer.json`; a missing file raises), also with a `modules.json` next to it (as the potion repos have), which must then list only StaticEmbedding and Normalize: behaviour is defined per format, and this one is model2vec's;
  - otherwise a `modules.json`: a sentence-transformers model (*sentence-transformers models*); a `config.json` of another model_type next to it is ignored, as sentence-transformers ignores it, and only named in errors;
  - `config_sentence_transformers.json` without `modules.json`: refused (sentence-transformers builds a Transformer and Pooling for it);
  - anything else: "no static embedding model", naming the model_type and files.

  `truncate` and `max_length` are for Model2Vec and sentence-transformers models, `truncate_dim` and `normalize` for sentence-transformers models, `mmap` for fse encoders; the other combinations raise.
- **One read per file.** Every file of a model is read once, through one handle of a regular file (never a link, FIFO or other kind), within its size limit (`config.json` and `modules.json` 1 MiB, `README.md` 16 MiB, `tokenizer.json` 64 MiB), into immutable bytes, and a file that changes while it is read raises. Those bytes are what is checked against the Hub commit and what is parsed, so a blob changed after its check changes nothing. An fse encoder of the Hub is therefore read into memory; `mmap` is for local files and raises for a Hub repository (save the encoder and load the file with `mmap`).
- **The Hub at one commit.** `revision` (None: the default branch) is resolved to its commit by `model_info` once, and every file comes from that commit (`hf_hub_download(revision=<commit>)`). The commit pins every file, and each is checked after the download: an LFS file by its `lfs.sha256`, any other by its git blob sha1, only the one that pins the file (or, with `local_files_only`, the one its blob name is) is computed, once, over the bytes read, in `fse._container._hash`. Every `.safetensors` file (the table of a Model2Vec model, an fse encoder) must be an LFS file; one without `lfs.sha256` raises. A file may lie in a folder of the repository (`0_StaticEmbedding/model.safetensors`). With `local_files_only` nothing is asked of the Hub: the commit is the cached snapshot of `revision`, found in the documented layout of the cache (a commit hash names `snapshots/<commit>`, any other revision, `main` for None, is the commit in the file `refs/<revision>`; `fse._hub.cached_snapshot`) and not through `snapshot_download(local_files_only=True)`, which huggingface-hub 2 refuses when the cached tree listing of the commit names a file the snapshot lacks, although the model needs none of them (DR-183); the snapshot needs no file of the model to be found, a missing ref or snapshot raises `FileNotFoundError`, and a ref that is a link or holds no commit hash raises `CorruptArtifactError`. The files are those below the snapshot, a file the model needs that is not there is missing as for any layout (the model is read as the files it has), and every blob is checked against its name, which is its sha256 or git sha1 (this detects damage, not forgery); a snapshot that holds a copy instead of a link raises then. To make that flow work after an online load, fse records the ref itself (DR-184): huggingface-hub writes `refs/<revision>` only for a download by name, fse downloads at the commit it resolved, so once the first file of a load by revision name (None is `main`) is checked against the commit, `fse._hub.write_ref` writes `refs/<revision>` with that commit exactly as huggingface-hub does (`_cache_commit_hash_for_specific_revision`, private and unable to pin a commit): a temporary file renamed over the ref, untouched when it holds the commit already, never for a commit hash, never offline; a link or another kind of entry in `refs` raises `CorruptArtifactError`. Of two processes the later rename wins, each having resolved a real commit of the revision.
- **Cache links.** A snapshot file of the Hugging Face cache is a link to `<repo>/blobs/<etag>`, the blobs of the same cached repository; with huggingface-hub 2 that entry is itself a link into the cache-wide store of Xet files, `<cache>/blobs/<2 hex digits>/<64 hex digits>`. Exactly these two steps are followed, compared as written and never resolved, and no folder from the cached repository down to a blob (`<repo>`, `snapshots`, the snapshot, `<repo>/blobs`, `<cache>/blobs` and its prefix folder) may be a link, so nothing leads out of the cache (the cache folder itself may be one). The per-repository etag is the name that is checked, and the regular file at the end is read; any other link raises. The folders are checked before the blob is opened by its path, not through held descriptors; a folder swapped in between is no gap of integrity, because the bytes that are read are hashed and compared with the commit (with `local_files_only`, with the etag resolved before), so a swap yields the pinned bytes or a refusal. Local folders make no such claim: their files are the caller's. A local folder that is a snapshot of the cache is read the same way.
- **The Model2Vec reader** (`fse._encoder._model2vec`, the rules of model2vec 0.10.0, `model.py` and `persistence/`):
  - `config.json`: strict JSON. `normalize` (default false) sets the step `normalize@1`; `max_length` (an int of at least 1, or null for none; default 512) the length rule; `hidden_dim` and `embedding_dtype` must match the table. `model_type`, `architectures`, `tokenizer_name`, `apply_pca`, `apply_zipf`, `sif_coefficient`, `seq_length` and `pooling` are provenance and ignored (`seq_length` is no length rule). `vocabulary_quantization` and `head_config` raise, and so does any other key, so a new key that changes encoding cannot be ignored silently.
  - `model.safetensors` (`fse._container._foreign`: the structural checks of safetensors 1 without fse's integrity keys; `__metadata__` may be absent and is ignored) holds exactly the tensor `embeddings`, a float32 matrix with one row per token. `weights` and `mapping` (vocabulary quantization) raise. float16 and int8 tables of the source raise: model2vec computes their mean in their own dtype, so the bound of a comparison would not hold. The refusal concerns the table of a foreign model; an encoder quantized by fse (`Encoder.quantize`) is not compared with model2vec and is not refused.
  - `tokenizer.json` (`fse._tokenizer_json`, strict JSON of at most 64 MiB with exactly its keys): a Unigram model gives `unigram@1` with the rules of `fse._tokenizer_json_unigram` (only the forms of potion-multilingual-128M; [Tokenizers](tokenizers.md#tokenizers)); otherwise a WordPiece model with dense ids and its unknown token in the vocabulary, a BertNormalizer (`strip_accents` null follows `lowercase`), a BertPreTokenizer, added tokens with `normalized`, `lstrip`, `rstrip` and `single_word` false that are vocabulary tokens with the same id, and a post-processor that is null or a TemplateProcessing whose template of a single text holds the sequence `$A` once. tokenizers 0.23.3 runs the post-processor also without special tokens: it then drops the special tokens but keeps every sequence, so `[CLS] $A [SEP]` leaves the ids unchanged while `$A $A` doubles them (tested); other templates and post-processors raise until their path is checked. `truncation` and `padding` are ignored, as model2vec overrides both (the sentence-transformers reader reads `truncation`), and `decoder`, as nothing decodes.
  - The encoder: `wordpiece@1` with `fse.unknown=drop` (model2vec removes every unknown id after the cut). With `truncate`, `fse.max_tokens` is `max_length` (the model's, or the argument; None: none) and `fse.max_chars` is `max_length` times the median length of the tokens in code points, as model2vec computes it (`int(np.median(...))` over every token in id order, in integers). `truncate=False` reads texts whole. `fse.source` records the format, repo and commit, and `fse.license` the `license` of the YAML front matter of `README.md` (at most 16 MiB; a larger card raises): a quoted or plain license id, or a block or flow list of them (all kept, in order); null, `~` or no value is no license, and so is a card without front matter or without the key; YAML values that are no string (bools, numbers), an empty list, the key twice and anything else raise. The own parser was kept on purpose after a measurement: the largest real card takes 4 ms with it, against 261 ms for PyYAML in pure Python and 25 ms for its C loader, which segfaults on deeply nested input and has no cp315 wheel; rapidyaml takes 3 ms but is looser and has no cp315 wheel either; all three agreed on the 62 cached cards.
- **Equality with model2vec.** The ids are those of the model's tokenizer (wordpiece@1). The rows are model2vec's within the tolerance bound (`tests/support/converted.py`: `(τ + 2 γ_K) m + δ K sqrt(d)` before normalize and `2 E / r` plus the rounding of both normalizations after it), because both are float32 sums of the same K rows in another order: model2vec takes numpy's mean and divides by `norm + 1e-32`. Not reproduced: a nonzero row whose sum of squares underflows or overflows float32 raises in `normalize@1` (the step is unchanged), where model2vec gives `[1e-30, 0]` as `[100, 0]` and a huge row as no unit row. Rows that tiny or that large do not occur with the POTION tables.

## model2vec compatibility (fse.StaticModel)

Binding for every 2.0 module (formerly under "2.0 design").

`fse.StaticModel` (`fse._static_model`) has the API of `model2vec.StaticModel` 0.10.0 (the pin of the test group): `from_pretrained` with its parameters in its order (fse's `revision`, `cache_dir` and `local_files_only` keyword-only after them), `encode`, `encode_as_sequence`, `tokenize`, `tokenizer`, and the attributes `dim`, `tokens`, `embedding`, `config`, `unk_token_id`, `median_token_length`, `base_model_name`, `language`, `embedding_dtype`, `weights`, `token_mapping`, `vocabulary_quantization` and `normalize` and `max_length` with setters. `tests/test_static_model_model_api.py` compares the signatures with model2vec's and lists every public name that is not provided with its reason, so a new pin fails loudly. It wraps fse `Encoder` objects and adds no arithmetic: under the model's own settings its rows are those of the `Encoder` bit for bit.

- **Rules of model2vec, not of the format.** `fse._encoder._model2vec_rules` reads a model as `model2vec.persistence` does: the first of three layouts whose three files exist (`config.json`; `config_sentence_transformers.json`; the same in `0_StaticEmbedding/`, each with `model.safetensors` and `tokenizer.json`) decides, `modules.json` is not read for that decision, the config of the layout gives `normalize` (default false) and `max_length` (default 512, null for none), the unknown id is dropped, the truncation of the tokenizer.json is ignored, and the table of an ST layout is `embedding.weight`. The same sentence-transformers repository therefore gives other rows in `StaticModel` (`[UNK]` dropped, the cut) and in `Encoder.from_pretrained` (sentence-transformers' rules), and both are tested. It adds two refusals model2vec does not have: a module other than StaticEmbedding or Normalize, and every config of a Model2Vec layout with an unknown key. `dimensionality` keeps the first columns, `subfolder` is a path of plain names read below the model's folder, `base_model` and `language` come from the card.
- **fse encoders.** A `.safetensors` file or an fse folder loads if it fits a closed profile (`fse._static_model._profile`): `wordpiece@1` or `unigram@1` on a float32 table without FastText, the unknown id dropped, `max_chars` equal to `max_tokens` times the median token length (or no cut), at most `normalize@1`. Anything else raises `UnsupportedArtifactError`.
- **Variants.** An `Encoder` is immutable, so each pair (`max_length`, `normalize`) is an encoder of its own (`fse._static_model._variants`): the same table and `Vocabulary`, another length rule or step, made on first use in a cache of 8, the model's own never evicted. The setters replace the current one by one reference assignment; model2vec is not thread-safe here either, but a running `encode` keeps the encoder it started with.
- **Neutral arguments and refusals.** `show_progress_bar`, `batch_size`, `use_multiprocessing` and `multiprocessing_threshold` change no row and are accepted after a strict check (`use_multiprocessing=False` means `workers=1`; rows are bit-identical across workers). The `**kwargs` of model2vec's `encode` are a closed list: `convert_to_numpy=True`, `convert_to_tensor=False`, `device` None or `"cpu"`. Another name is a `TypeError` of the signature (`encode` is not decorated, as it is called per batch: the checks are made by hand and the wrapper adds about 1 us to a one-sentence call), a neutral name with another value a `ValueError` naming what to use. `from_pretrained` is validated; `quantize_to` may be `"float32"`, `vocabulary_quantization` None.
- **Ids, sequences and the tokenizer.** `encode_as_sequence`, `tokenize` and the tokenizer need the ids a text is pooled from. `fse._static_model._ids` takes them from the code `encode` runs: the lookup of stage 2 (`fse._text.make_lookup` on the model's shared `Vocabulary`, one per length rule `(max_tokens, max_chars, unknown)`, a cache of 8) and the text source of stage 1, chunk by chunk with a workspace of its own. The three differ in the rule only: `encode` and `encode_as_sequence(max_length=n)` cut the first `n * median_token_length` code points and then `n` tokens and drop the unknown id, `encode_as_sequence` without `max_length` cuts nothing (the model's `max_length` does not apply to it), `tokenize` cuts `max_length` tokens of the model with no character cut and drops the unknown id, and the tokenizer does the same with the unknown id kept. `encode_as_sequence` gathers `table[ids]` and nothing else, so its rows are model2vec's bit for bit (`tests/test_static_model_model_sequence.py` compares bit patterns); only the rows of a text without tokens differ in dtype (float32, model2vec float64). The tokenizer facade (`fse._static_model._tokenizer`) is read-only and reads the model's current `max_length` at every call. It gives `.ids` only: fse has no post-processor, so `add_special_tokens=True`, the default of `tokenizers`, raises `ValueError`, and it has no offsets and no `.tokens`, because `tokenizers` names an unknown Unigram piece by the characters it matched, which only offsets could give back. chonkie calls `encode(text, add_special_tokens=False).ids` and `encode_batch(texts, add_special_tokens=False)` on it, which the facade answers, but chonkie chooses its adapter by `isinstance(model, model2vec.StaticModel)` and by `"tokenizers" in str(type(tokenizer))`, so the integration needs a change there.
- **Persistence and its compatibility limit.** `save_pretrained(path, model_name=None, subfolder=None)` and `push_to_hub(repo_id, private=False, token=None, subfolder=None)` have model2vec's signatures but write the folder of *Hub folders* (below) through `Encoder.save_pretrained`/`push_to_hub` (`fse._static_model._save`): the encoder of the model's current `normalize`, `max_length` and dimensions, the language of the card, one commit on push. model2vec cannot read that folder (its `config.json` is `model_type` fse), and `subfolder` other than None raises. Nothing is added to the format (no `fse.` key, no tensor): a reload through `StaticModel.from_pretrained` rebuilds what the folder determines. `normalize` and `max_length` are those of the encoder (the rows are bit-identical to the model before saving on the cpu backend, after setter changes too); `config` holds exactly these two keys, not the other keys of the original model2vec config; `base_model_name` is the Hub repository of `fse.source` (None for a table converted from a local folder), not the `base_model` of the original card; `language` is read from the new card (the language the model had; a code the card of fse cannot write raises on save); further card fields (datasets, tags) are not carried (DR-157). The license is that of the source card in `fse.license`; a model without one saves (the card says so) and `push_to_hub` raises, pointing to `model.encoder.push_to_hub(repo_id, license=...)`, because model2vec's signature has no license. Every field would be frozen from the release on and changes no result. The methods return the path and the URL of the commit where model2vec returns None.

## sentence-transformers models

Binding for every 2.0 module (formerly under "2.0 design").

`fse._encoder._sentence_transformers` reads a sentence-transformers model of one StaticEmbedding with the rules of sentence-transformers 6.2.0 (`StaticEmbedding`, `SentenceTransformer.encode`); parity is defined against that version and tested against it (the group `st`, `make test-st`, the CI job `test-st`).

- `modules.json` (strict JSON, 1 MiB): a non-empty list of modules, each with exactly `idx`, `name`, `path` and `type` (and optionally `kwargs`, which is refused), taken in list order as sentence-transformers does. Exactly one module, a StaticEmbedding, spelled as sentence-transformers up to 5.3 writes it (`sentence_transformers.models.StaticEmbedding`, both target repos) or as 5.4 and later do (`sentence_transformers.sentence_transformer.modules.static_embedding.StaticEmbedding`). Its `name` is a non-empty str without `.` (sentence-transformers keys modules by name); its `path` is the model's folder (`""` or `"."`) or one folder in it, nothing that leads out. Refused, with the reason: a Normalize module after it (in any of its three spellings: sentence-transformers divides by `max(norm, 1e-12)`, which `normalize@1` does not reproduce for tiny rows; `normalize=True` is fse's own choice instead), a Dense module after it (with or without an activation, refused without reading its folder or config: a fold would round `W x` per token and needs a bias step), and any other module or sequence: "no static embedding model", naming the modules.
- `config_sentence_transformers.json` (optional, strict JSON, 1 MiB), every key known: `model_type` absent or `SentenceTransformer`; `prompts` only empty strings (sentence-transformers 6.2 writes `{"query": "", "document": ""}`) and `default_prompt_name` null or one of them, so encoding needs no prompt; `truncate_dim` null or an int of at least 1; `__version__`, `similarity_fn_name` and `requirements` are provenance; any other key raises.
- In the folder of the StaticEmbedding: `model.safetensors` with exactly one float32 matrix, `embedding.weight` or `embeddings` (the two names sentence-transformers 5.4 to 6.2 load alone), one row per token, checked by its header before its data, `mapping` or `weights` refused as vocabulary quantization; without it a `pytorch_model.bin` is refused as pickle. `tokenizer.json` as for Model2Vec, except `truncation`: null, or the plain form `{"direction": "Right", "max_length": n, "strategy": "LongestFirst", "stride": 0}` that keeps the first n ids (`fse.max_tokens`, no `fse.max_chars`), as tokenizers applies it in sentence-transformers (which disables only padding); any other form raises.
- The encoder: `wordpiece@1` with `fse.unknown=keep` (sentence-transformers pools the row of `[UNK]`; added tokens typed in the text, such as `[CLS]` or `[PAD]`, are matched and pooled as there), no length rule but the plain truncation (`truncate=False` reads texts whole; `max_length` raises), the mean of every id (`EmbeddingBag` in mode mean, an empty text the zero row). `truncate_dim` (the argument; `"model"` the config's; None all) keeps the first k columns of the table, which is sentence-transformers' `truncate_dim`, the prefix of the mean, value for value; k equal to the width keeps all, a larger k raises. `fse.source` records the format `sentence-transformers`, repo, commit and the `dims` of a cut. `normalize=True` adds `normalize@1` after the cut (sentence-transformers' `encode(truncate_dim=k, normalize_embeddings=True)`, up to its floor of 1e-12); without, rows are not normalized, as the target models are not.
- **Equality with sentence-transformers.** The ids are those of the model's tokenizer, `[UNK]` included. `EmbeddingBag` sums the rows in token order in float32 and divides by n, fse sums them in the same order (`fma` with the factor 1 is the same addition) and multiplies by `1/n` rounded once, so the rows differ by at most about one ulp (measured on torch 2.15.0, macOS arm64: at most 1 ulp). The tests rely on the bound of the tolerance contract only (`tests/support/converted.py`), which holds for any order of the sum. Rows that are zero before normalize (an empty text, a zero table, opposite rows) are zero on both sides.

| | Model2Vec format | sentence-transformers format |
|---|---|---|
| `[UNK]` | dropped after the cut | pooled |
| length | 512 tokens and a character cut | none, or the plain tokenizer.json truncation |
| normalize | `config.json`, `norm + 1e-32` in model2vec | a Normalize module (refused); `normalize=True` is fse's |
| first dimensions | none | `truncate_dim` |

## Hub folders

Binding for every 2.0 module (formerly under "2.0 design").

A model is shared on the Hugging Face Hub as a folder of exactly these files (`fse._encoder._folder`, `fse._encoder._card`, `fse._hub_push`); `save_pretrained(path)` of `fse.Encoder`, `fse.Classifier` and `fse.Regressor` writes one, `from_pretrained` reads it from a local folder or a Hub repository, and `push_to_hub(repo_id)` publishes it:

- **`config.json`**, strict JSON with exactly `{"fingerprint", "fse_config_version": 1, "fse_format_version": 1, "fse_kind": "encoder" | "linear_head", "model": "model.safetensors", "model_type": "fse"}`, written with sorted keys and an indent of 2. It is the query file by which the Hub counts downloads: "Every HTTP request to these files, including `GET` and `HEAD`, will be counted as a download. By default, when no library is specified, the Hub uses `config.json` as the default query file" ([Models Download Stats](https://huggingface.co/docs/hub/models-download-stats)); `library_name: fse` registers no rule of its own. `from_pretrained` reads it first, so a load that downloads it is counted; a cached load is not, because huggingface_hub serves a cached file at a commit hash without a request (and `local_files_only` makes none). Its values come from the header of the model file actually written, so a standalone head names its folded file. Another key, `fse_config_version`, kind or format version raises; the provisional config of a pre-release (the file under the key `encoder`) raises by name. The loaded model is compared with the config by the fingerprint of the metadata it was actually loaded with, so a file swapped after a first look cannot pass; this cross-checks the folder and authenticates nothing ([Identities](persistence.md#identities)).
- **`model.safetensors`**: exactly what `save` writes (complete, or `standalone=True` for a head on raw means), self-contained; `load` reads it alone.
- **`README.md`**, the model card, made from the header of that file without a template engine: front matter with `library_name: fse`, the license, `base_model` (the Hub repository a converted model came from) and, only with it, `base_model_relation: quantized` when the table of the file written is int8 (`fse.dtype=int8`, stored by `quantize_rows@1`; the Hub's values are `adapter`, `merge`, `quantized` and `finetune`, [Model Cards](https://huggingface.co/docs/hub/model-cards), "Specifying a base model"); in every other case, float16 included, the relation is left unset for the Hub to infer, as none of its values names a plain conversion, `language` if given, `pipeline_tag` (`feature-extraction` for encoders, `text-classification` for classifiers, none for regressors) and tags; every string double-quoted. The license is the one the model records from its source (`fse.license`); `license=` is taken only when it records none, and one that differs raises. The text states the facts of the file, how to load it, its source and where a converted model differs from its library. For a float16 or int8 table it names the rule and, when recorded, the float32 table it was stored from (`fse.quantized_from`), and says that the vectors are those of the quantized table, on the cpu backend bit for bit as its reference computes them (a device backend within its tolerance); it promises no closeness to the model before quantization, which is measured, never promised by the file. A folder holds exactly one `model.safetensors`, so every dtype of a model is a repository of its own.
- **Extra files** (`extra_files={"LICENSE": path}`): plain names that are not the model's own, regular UTF-8 files of at most 1 MiB, copied as the bytes that were read.

**Atomic write.** `path` must not exist (also no empty directory or link). The folder is written into `.<name>.writing-<random>` beside it (the model file through its container, the other files created exclusively and synced, then the directory synced) and published by the exclusive rename of `publish_directory`, so `path` is complete or absent and never replaced; a second writer of the same path gets a `FileExistsError`. A failure before the rename removes the temporary folder; a failed sync of the parent after the rename raises `fse.PublishedNotDurableError` (an `OSError`): the folder is complete at `path` and stays, but its rename is not confirmed durable.

**Push.** `push_to_hub` saves into a new subfolder of a temporary directory and requires a license. `fse._hub_push` reads the repository at one commit (`model_info(files_metadata=True)`) and compares every file of the folder with the file of the same name there by its digest (`lfs.sha256` of an LFS file, else the git blob id): an equal one is left as it is (a `.safetensors` file only as an LFS file; one stored as a plain git blob counts as different, since fse cannot read it), a different one is refused unless `replace=True`. License files already there (LICENSE, NOTICE, COPYING, with any suffix) that the folder does not bring are kept, `.gitattributes` always; any other file is refused unless `replace=True`, which deletes exactly those names (`CommitOperationDelete(is_folder=False)`, no patterns). Before any commit, a push into a commit that has a `.gitignore` (huggingface_hub drops the files it matches from a commit without an error) or a `.gitattributes` whose rules (the last matching line decides, as in git) give an added `.safetensors` file no `filter=lfs` is refused, and so is one with a line the reader does not read (a quoted or escaped pattern, a macro definition, a negative pattern), rather than skip a rule that could change how the file is stored; the `.gitattributes` is read at that commit into a temporary cache. The operations go into exactly one `create_commit` with `parent_commit`, so a branch that moved meanwhile fails the push instead of mixing (with `create_pr=True` the pull request starts from that commit and the branch does not move); a push without operations checks the commit it read; `upload_folder` is not used, because with hf-xet it commits large folders in batches and its `delete_patterns` are patterns. At the returned commit the file set and every digest are checked, every `.safetensors` must be an LFS file; a mismatch raises and says that the commit stays. The tests replace huggingface_hub by a fake and check the signatures of the installed version; a real upload is a step of its own, with the maintainer's approval.
