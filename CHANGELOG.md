# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

- Add two native-file classification headline cells for 100 million texts (DR-314: Kopfzeile für 100 Millionen klassifizierte Texte in der Veröffentlichungsstudie anbieten), with labels and probabilities, configurable head labels (default: toxicity and insult), resource admission before input preparation, per-round warmup, and sample bit checks against cpu and numpy. The untrained placeholder is restricted to functional rehearsals. Publication waits for a pinned real toxicity head. Protocols expose comparison-arm, resource-plan, and quiet-cell properties. Measurement tooling only; no library change.

- Raise `fse_revision` in `benchmarks/config/pins.json` from 624251df (fse 2.0) to a1e9bf50, the master after DR-317 (DR-320: Pin der fse-Revision für die Linux-Studien auf den aktuellen master heben), so the Linux studies install an fse with `fse.Heads`. Historical results keep their own pin. The speed allocation gains a `base` environment (fse 2.0 at 624251df, lock `speed-base.lock.txt`) passed as `--base-python`, so `--study all` is no longer refused for its `versions` cells; the plans of the existing cells are unchanged. The development `Dockerfile` now uses the image of `pins.json` (CPython 3.13.18) instead of 3.13.16-slim. The speed rehearsal machine check allows 6 GiB instead of 4 GiB, because the bekko cells fail in 4 GiB with a `MemoryError` (maintainer approval 2026-11-08). Measurement tooling only; no change to the library.

- Start sink threads only with their first work (DR-317: Sink-Threads eines nicht geschlossenen Sinks nicht unbefristet weiterlaufen lassen). Constructing or inspecting a `ShardSink` or `ScoreSink` starts no thread. Write and hash start at the first commit, publish at the first finished shard. Used sinks still require `close()` or a `with` block. Thread-start failures follow the shared writer error and cleanup protocol.

- Return `(result, vectors)` from `Heads.predict`, `Classifier.predict` and `Regressor.predict` with `return_vectors=True` and no sinks (DR-312: return_vectors=True in Heads.predict ohne Sinks nicht still übergehen); previously the call raised ValueError. With lengths the return is `(result, vectors, LengthReport)`. Outputs and encoder vectors match `predict_batches(return_vectors=True)` bit for bit, including the unfolded path of raw-mean heads. Resume sink returns stay unchanged. Standalone heads, VectorStore inputs and `Regressor.predict(sink=...)` refuse this switch.

- Serve development lock waiters in registration order and report queue position (DR-315: Wartende an der Heavy-Sperre in Ankunftsreihenfolge bedienen). Canceled and crashed waiters leave the queue; existing lock owners are never taken over. FIFO requires draining old waiting controllers and wrappers before rollout. Measurement tooling only.

- Reuse the shared pool for text scans and add `pool=` to `fse.add_sign_bits` (DR-309: Gemeinsamen Pool auch für die Text-Zerlegung und add_sign_bits nutzen). File, encoded-string and Arrow scans use the pool threads and task places before encoding. Batch iterators scan on their iteration pool; `StreamSource` collections still scan inline. Sign-bit backfills share the pool limits and leave it open, including after failures. Chunks, error order and output bytes stay unchanged.

- Evaluate a named `cells@1` decision across development cells (DR-298: Gesamtentscheidung über mehrere Zellen im Mess-Kern auswerten). Main cells must pass their existing noise and confirmation gates plus the declared practical saving. Edge cells must meet their factor bound in comparison and confirmation. Four explicit changes: optional automatic early stop after a final rejection (disabled in the local int8 study), exit 1 for an overall rejection or inconclusive result including partial selections, `decision.json` also after preparation failure or budget exhaustion, and per-edge factor bounds without a global minimum. Cell decisions are unchanged. Measurement tooling only.

- Document named linear heads, score stores, document IDs and later filtering, add the Civil Comments filtering recipe, and extend the classification and folding recipes (DR-230: Kopf-Dokumentation und Toxizitäts-Beispielkopf vorbereiten). Documentation only; no change to the library.

- Add `VectorStore.search(..., mode="binary", oversample=None)` (DR-267: Binäre Suche mit search(mode="binary", oversample=) anbieten, part of DR-255: Binäre Vorsuche mit exaktem Nachrechnen als Opt-in anbieten). Stage 1 ranks the selected rows by the Hamming distance of their sign bits to the bits of the query (numpy, `fse._reference_bits`) and keeps the best `oversample * k` per query (default 40, provisional until DR-264: Recall der Varianten und Kosten der Bitsuche gegen den int8-Vorfilter messen); stage 2 scores only those rows exactly with the path of `rescore`, so the result is `search(mode="exact", rows=sorted(C))` for the candidates `C` bit for bit, and `oversample` at least the selection gives `mode="exact"`. `rows=`, `doc_ids=`, `max_per_doc=1`, `workers=` and `pool=` work; a shard without sign bits is derived from its rows with one `store.bits_derived` WARNING per store. New events `store.binary` and `store.bits_derived`. `"binary"` and `oversample` are public values and freeze with 2.1; no new persistence name; `score` and score stores are unchanged.

- Add `ShardSink(sign_bits=True)` (DR-266: Vorzeichenbits beim Schreiben mit ShardSink(sign_bits=True) mitschreiben, part of DR-255: Binäre Vorsuche mit exaktem Nachrechnen als Opt-in anbieten). Default False; without the switch the bytes written are those of before. With it each shard gets its `sign_bits-<first row>` artifact: the bits are derived in the hash thread from the codes committed, and published as a step of its own after the shard is renamed and its rows are counted, with the durability of the sink (`none` tags the artifact). A failure of the bits is an error of the sink that never changes the rows already counted; a stop between a shard and its bits leaves a valid store. A sink made with `resume=True` writes the bits that the published shards it keeps lack (checked as `fse.add_sign_bits` checks them), so any stop resumes to the bytes of an uninterrupted run; a sink that only appends does not. The bits equal those of `fse.add_sign_bits`. Adds the fields `sign_bits` (`store.sink_opened`) and `sign_bits_shards` (`store.sink_closed`). No new persistence name. No timing was measured; the write cost follows later.

- Add `fse.add_sign_bits(path, *, durability="full", workers=None)` and the companion artifact `sign_bits-<first row>` of the sign bits of a shard (DR-265: Vorzeichenbits als Begleitdatei je Shard lesen und mit fse.add_sign_bits nachrüsten, part of DR-255: Binäre Vorsuche mit exaktem Nachrechnen als Opt-in anbieten). The artifact is an NpyContainer with the tensor `sign_bits` (rule `sign_bits@1`), bound to its shard by `fse.shard_fingerprint`; shards and `store.json` are unchanged. `VectorStore.open`, `refresh`, `verify`, views and `repair_store` read and check it (a bound, damaged or unknown artifact is `CorruptArtifactError` or `UnsupportedArtifactError`, never skipped; a shard without it stays valid; repair moves bits before their shard, and alone when they do not fit). `add_sign_bits` writes the missing artifacts after hashing the vector bytes against the checksum of the shard, and returns their number. Adds the event `store.sign_bits_added` and the fields `sign_bits_shards`, `sign_bits_bytes` (`store.opened`), `added_sign_bits` (`store.refreshed`) and `moved_sign_bits` (`store.repaired`). Nothing searches with the bits yet. New persistence names, which freeze with 2.1: `sign_bits-`, `sign_bits`, `fse.kind=sign_bits`, `fse.bits=sign_bits@1`, `fse.shard_fingerprint`. v2.0.0 reads such a store and passes over the entries.

- Name the claim classes of measurements correctness, descriptive, regression, optimization and publication (previously K/D/R/O/P) (DR-294: Messklassen mit lesbaren Namen statt Einzelbuchstaben benennen), in the contributor guides, the measurement guide, the study descriptions and the local quality runs, whose rows now record `"class": "correctness"`. Results written before keep their one-letter value; `benchmarks/quality.py --summarize` maps it to the same class, so old and new rows of one configuration give the same summary.

- `VectorStore.search`, `score` and `rescore` take `pool=` (DR-283: Gemeinsamen Pool für search, score, rescore und Köpfe über einen Store annehmen): with an `fse.Pool` their tasks run on its threads, at most `workers` (default `pool.workers`) at once, instead of threads of each call, so concurrent calls of a service share one set of threads. Bit-defined calls (`mode="exact"`, `"auto"` for at most 8 vectors, the int8 prefilter, `rescore`, head store mode) give the bits of a call without a pool, `mode="blas"` stays close as before, and a call without `pool=` behaves as before. `workers` above `pool.workers` raises `ValueError`, a closed pool `RuntimeError`, before a row is read. A call takes a place of the pool per task until the task ends, and an error, a prefilter that gives up or a stream ended early cancels its unstarted tasks, waits for its running ones and leaves the pool open. Fixed: the store mode of a head (`predict`, `predict_proba`, `decision_function` and `predict_batches` of a `Classifier` or `Regressor` given a `VectorStore`) accepted `pool=` and ignored it; it now runs on that pool. See docs/architecture/store.md, "Concurrency".

Rows record the MTEB training relation, the execution path and the snapshot file hashes; summaries add coverage by set equality, tables per language and language pair, a common zero-shot set and reproduction against published MTEB results. - Exact searches of int8 stores (`mode="exact"`, and `"auto"` up to 8 queries) on arm64 CPUs with the dot-product extension skip rows that a provable int8 bound rules out and rescore the rest through the exact path of `rescore`; ids and score bits are unchanged, and anything outside the proven domain takes the previous path (DR-168: Suche mit int8-Vorfilter und beweisbarer Fehlerschranke beschleunigen, part 3, DR-278: int8-Vorfilter in die exakte Suche einbinden). - Read sentence-transformers models whose table is float16, such as `hotchpotch/bekko-static-embedding-v1`, as fse float16 tables (DR-274: float16-Tabellen von sentence-transformers-Modellen als fse-float16 laden): `Encoder.from_pretrained` keeps the table unchanged (half the memory of float32), the kernel widens it exactly and every sum runs in float32, so the rows are the bits of the encoder of the widened table; `truncate_dim` and `normalize` work as for float32. sentence-transformers itself takes the mean of such a table in float16, so the comparison is with its weights made float32, within the bound of the float32 tables. Additive: models that loaded load as before, bit for bit; int8 and float64 tables of sentence-transformers models and every non-float32 table of Model2Vec models are still refused. - Create the GitHub release in CI for every `v*` tag (DR-261: GitHub-Release bei jedem Release automatisch anlegen und den Ablauf als Skill festhalten): a new job `github-release` runs after the PyPI upload and is the only job with `contents: write`. - Allow `Encoder.from_pretrained(..., truncate_dim=k)` for Model2Vec models (DR-260: truncate_dim auch für Model2Vec-Modelle erlauben): the encoder keeps the first k dimensions of the table, as it already does for sentence-transformers models, before `normalize@1`, and `fse.source` records the `dims` of the cut, which `save`, `load`, `save_pretrained` and `quantize` keep. `"model"` (the default) and None keep all dimensions, k equal to the width too, a larger k raises. The columns a cut drops are checked for NaN and infinity, so a corrupt table is refused with or without a cut (also for sentence-transformers models). fse encoders still refuse `truncate_dim`; without the argument nothing changes.

- Add `fse.Pool(workers=None, *, start=False, max_tasks=None)` and the keyword-only `pool=` of the ten methods that tokenize text (DR-241: Heißen Pfad vor 2.1 profilieren und die besten ein bis zwei Engpässe beheben, rank 2, with DR-185: Optionalen Thread-Pool über mehrere Aufrufe anbieten). A pool is a set of threads that runs the tasks of any number of calls, so a server that encodes many small requests, or a loop over many small batches, no longer starts threads for every call; `start=True` starts them when the pool is made. A stream (`encode_batches`, `predict_batches`) now runs all its batches on one pool that lives for the iteration and is closed when it ends, fails, is closed or is collected, where each batch made its own threads before (the profile of the stream cells showed 59 to 81 % waiting and 15,000 to 28,000 thread entries for 3,660 calls). The default stays that no thread outlives a call; a pool passed with `pool=` is closed by its owner. `workers=` may not exceed `pool.workers`. Bits, errors and the order of commits are unchanged. Additive: `v2.0.0` behaves exactly as before.

- Add the guide [External indexes on fse shards](docs/external-indexes.md) and recipe 10 (`recipes/10-external-ann-indexes.ipynb`, helpers in `recipes/_ann.py`) (DR-169: Shards optimal für externe ANN-Indizes vorbereiten, part 4): how FAISS, USearch and hnswlib take the rows of `iter_batches` (`VectorBatch.normalized()`, int8 codes without a copy), how `VectorStore.rescore` gives their hits the exact score, and how to add rows, continue after a stop, repair and use views. Documentation only; no change to the library.

- Add `VectorBatch.inv_norms` and `VectorBatch.normalized()` (DR-169: Shards optimal für externe ANN-Indizes vorbereiten, part 3): every batch of `VectorStore.iter_batches` now holds the stored inverse norms of its rows as a read-only float32 view, and `normalized()` returns a new float32 array of approximately unit-length rows for an external index (FAISS, hnswlib): `float32(stored) * inv_norm` per element, int8 from the codes without the scale. The bits are fixed in the default IEEE environment; a batch built by hand is checked and refused with `ValueError` or `TypeError` if it does not fit. No new persistence name.

- Add `VectorStore.rescore(queries, candidates, /, k=10, *, workers=None, max_per_doc=None)` (DR-169: Shards optimal für externe ANN-Indizes vorbereiten, part 2), which scores the hits of an external index (FAISS, hnswlib, USearch) exactly: for every query it returns the best `k` rows among its own candidate positions (`-1` marks a gap; the lists may be unsorted, hold duplicates, be empty or shorter than `k`), bit for bit as `search(query, k, mode="exact", rows=sorted(candidates without -1))`, also with `max_per_doc=1` and on views. A matrix result is filled up on the right with ids `-1`, scores `-inf` and document IDs `-1`; a single query is not. uint64 candidates are rejected. It adds the log event `store.rescore` (DEBUG: `queries`, `k`, `pairs`, `read_rows`, `workers`, `max_per_doc` when set), and no persistence name.

- Make the task of a head give up the GIL far less often (DR-241: Heißen Pfad vor 2.1 profilieren und die besten ein bis zwei Engpässe beheben, rank 1): the checks of the backend methods compared arrays with `np.may_share_memory`, which releases the GIL, up to 20 times per task of `fse.Heads` (11 for one `Classifier`); they now compare the byte bounds without a numpy call (`fse._backends._base_checks.overlaps`, and `_overlaps` in the extension), with the same result. A task whose heads read only the folded table also pools in one section without the GIL, as `Encoder.encode` does, instead of building and checking a `Batch` with about ten more numpy passes over its tokens; a failed task is run again on the old path, which raises the error of its row. No arithmetic, API or format changes: the outputs are bit-identical to those of the numpy reference.

- Add resuming of endless streams at a position that can be read again (DR-252: Unendliche Streams an einer wiederlesbaren Position fortsetzen, part 5 of DR-165: Shards und Resume für große Jobs einführen): `Encoder.encode_batches(batches, sink=, positions=True)` and `predict_batches(..., positions=True)` of `Heads`, `Classifier` and `Regressor` take batches `(texts, position)` (or `(texts, doc_ids, position)`) into sinks made with `resume=True`, a store of the new mode `fse.resume=source_position@1`. A position is an opaque text of 1 to 65,536 UTF-8 bytes (a Kafka offset, a byte offset); fse stores it and never reads it. Every shard keeps the position of the batch it ends in under `fse.source_position` and `fse.source_position_row`, and the root keeps the start of the stream. After a crash `sink.source_position`, also `VectorStore.source_position` and `ScoreStore.source_position`, is `(P, skip)`: seek the source to `P`, give its batches again, and the first `skip` records, which the store holds, are dropped without being encoded; every other record is written as an uninterrupted run writes it, bit for bit. Every batch of the replay gives one result: `first_row` is the replay row of its first computed record, `n_rows` the records computed (0 for a batch the store holds) and `durable_rows` the replay rows that are durable, so a consumer commits its input up to there. A vector store and a score store written together resume together, also when they hold different numbers of rows (seek by the one that holds fewer). A store of this mode has a `store.json` of up to 1 MiB, `members` of a view show the `position` of each member, and a view reads stores of streams in the order given. A store of one resume mode is not resumed by the other: `encode(texts, shard=)` and `predict(..., shard=)` write `source_rows@1`, the batches with `positions=True` write `source_position@1`.

- Add resumable score stores and resumable heads (DR-250: Score-Stores und Köpfe wiederaufnehmen, part 3 of DR-165: Shards und Resume für große Jobs einführen): `fse.ScoreSink(..., resume=True)` writes a score store of the mode `fse.resume = source_rows@1` (the same six keys as a vector store). `Heads.predict`, `Classifier.predict` and `Regressor.predict` take the new keyword-only `return_vectors=`, `vector_sink=`, `score_sink=`, `doc_ids=` and `shard=`: with a sink made with `resume=True` the call resumes, runs only the rows the stores do not hold yet, bit for bit as an uninterrupted run, and returns `None` (with `lengths` the pair `(None, LengthReport)`). A vector store and a score store of one call may hold different numbers of rows: a first phase catches the shorter one up, a second runs the rest into both. The outputs of the heads are dropped, so the memory of a call does not grow with the rows. A sink made with `resume=True` is refused by `predict_batches` and by every other entry. Without the new keywords nothing changes.

- Add resumable vector stores and fixed partitions (DR-248: Vektor-Stores wiederaufnehmen und feste Partitionen schreiben, part 1 of DR-165: Shards und Resume für große Jobs einführen): `fse.ShardSink(..., resume=True)` writes a store of the new mode `fse.resume=source_rows@1`, and `Encoder.encode(texts, sink=sink, shard=(i, n))` takes part `i` of `n` of a source that can be read again (a list, tuple or array of `str`, token lists or the path of a text file; parts are whole blocks of 16,384 rows). The call hashes the whole source and compares its fingerprint, the encoder, the dtype and the partition with the store: another source or setup is a `ValueError` before any row is reserved. A stopped run continues with only the missing rows, bit for bit as an uninterrupted run, and a store that is complete is left alone. Under `durability="full"` the sink syncs the store directory once when it appends. A report of `lengths=` covers the rows of that call and its `first_row` is their source row. Streams and Arrow text columns are refused with a `TypeError`; `encode_batches` and the heads refuse a sink made with `resume=True`. The format (six keys: `fse.source_fingerprint`, `fse.source_form`, `fse.execution_fingerprint`, `fse.source_first_row`, `fse.source_rows`, `fse.source_shard`) is also read and repaired for score stores; their sink follows. These names freeze with 2.1. Recipe 03 uses the new calls.

- Add `VectorStore.open_view(paths)` and `ScoreStore.open_view(paths)` (DR-251: Mehrere Stores als eine Sicht lesen, part 4 of DR-165: Shards und Resume für große Jobs einführen), which read several stores as one store whose rows follow each other, without merging anything on disk. Search and score with `mode="exact"`, `take_*`, `get_*`, `iter_batches` and `predict_batches` give the bits and the order of ties of one store that holds the same rows (BLAS blocks follow the shards, so `mode="blas"` and `"auto"` above 8 queries differ in the last bits, as between two shard sizes). The stores must hold the same encoder, dtype, dimension and document-ID mode (scores: the same heads, columns and paths, and the same thresholds across each boundary); stores written with `Encoder.encode(shard=)` must be parts of one source (each part at most once, not mixed with stores without a source) and are read in the order of the parts; parts may be missing or unfinished (a snapshot, positions are the concatenation, `source` is `None`), and only if all parts are there and finished is a position a row of the source. A view has no `path` and no `refresh` (`ValueError`), `verify` runs over each store, and `close` closes them all. New read-only helpers on both store classes and views: `paths`, `members` (one mapping per store: `path`, `first_row`, `rows`, `source`), `source` (a mapping for a store written from a source, and for a view of all its parts) and `locate(ids)`, which names the store and the row of each position. New events `store.view_opened` and `scores.view_opened`.

- Add `VectorStore.refresh()` and `ScoreStore.refresh()`, which take the shards a writer has published since the store was opened into the store itself and return the number of new rows (an int; 0 if there are none). A reader of a store that is still written sees new shards without opening it again, and only the new shards are checked and, if tagged `durability="none"`, hashed. Searches, scores and reads that run, and generators already made, keep the rows they started with: every public read now takes its shards and row count once, when it is called (a generator of `iter_batches` or `predict_batches` at the call, not at its first block). A gap, an orphan or a break of the chain raises `CorruptArtifactError`, a store whose root or last shard changed since it was opened raises `RuntimeError`; in both cases the rows stay as they were. A repair meanwhile is detected at best (`repair_store` stays offline). `VectorStore.close` raises while a refresh runs. New events `store.refreshed` and `scores.refreshed` (DEBUG). (DR-249: Stores während des Schreibens mit refresh() nachladen)

- Add `lengths=`, `count_truncated=` and `on_truncation=` to the ten methods that tokenize text (`Encoder.encode` and `encode_batches`, `Heads.predict` and `predict_batches`, `Classifier.predict`, `predict_proba`, `decision_function` and `predict_batches`, `Regressor.predict` and `predict_batches`), which show what the length rule of the model cut. `lengths="summary"` or `"per_row"` returns `(result, fse.LengthReport)` (a 2.0 return type becomes a pair, with a sink `(None, report)`), makes every batch of a `*_batches` call the pair `(batch, report)` and gives `HeadsBatch` the field `lengths`; `EncodedBatch` and `PredictedBatch` are unchanged. The report holds the sums (rows cut by characters, by tokens, empty rows, tokens, unknown ids dropped) and with `"per_row"` the same per row; `count_truncated=True` adds the tokens and characters cut. `on_truncation="raise"` raises the new `fse.TruncationError(ValueError)` (`row`, `cut`, `limit`) for the first sentence the rule would cut. Without the keywords nothing is recorded and every result is bit for bit the same; a `VectorStore` input with them raises before a row is read. A sentence that reaches `max_tokens` costs at most one more word for the flags, and counting tokenizes the rest of a cut sentence. (DR-163: Sichtbar machen, was beim Tokenisieren gekürzt wurde)

- Let `Classifier.predict_batches` and `Regressor.predict_batches` write to sinks without `fse.Heads` (DR-243: Umwege über fse.Heads bei einzelnen Köpfen entfernen): the new keyword-only `vector_sink=`, `score_sink=` and `doc_ids=` work as on `Heads`, and a single head and a group of one write the same files and append to each other's stores. `sink=` keeps exactly its role and behavior of 2.0 and excludes the new keywords; a `VectorStore` input refuses them (the outputs of a store keep going to `sink=`). `ScoreSink(path, model, name=...)` and `ScoreStore.open(path, heads=model, name=...)` take a single head; the name is required, because it is written to the store. `ScoreSink(store=...)` is now `stored=...` (unreleased, no alias). New `LinearModel.path(return_vectors=...)` names the path a head takes, as `Heads.paths` does for a group. - `fse.Encoder`, a finished model: a table of word rows (with FastText ngrams, as float32, float16 or int8), its tokenizer and whether every row is normalized, saved as one self-contained `.safetensors` file (`save`, `Encoder.load(path, mmap=)`). `Encoder.from_word_vectors(wv, tokenizer=, normalize=True, max_ngrams=, oov_weight=)` and `Encoder.from_arrays(vectors, words=, ...)` make one; every word weighs 1, so weights, removed components or projections of a model are folded into its rows before. `Encoder.encode` takes lists of sentences, a path of a text file, token lists (read in one native pass) or any iterable, in parallel, and returns float32 or float16 rows, or `fse.QuantizedRows` (int8 codes with a scale per row) computed in the workers at about the speed of float32.
- Stores of sentence vectors. `fse.ShardSink` writes the rows of an encoder straight into a store of immutable shards while it encodes (`encoder.encode(texts, sink=sink)`): a directory of plain `.npy` files that `np.load(mmap_mode="r")` opens, as float32, float16 or int8, with appends as new shards. A shard is published whole once its rows are written and synced, and `durable_rows` says how many rows are safe, so a stream confirms its input only up to there; after an error the finished rows are kept. `Encoder.encode_batches` encodes an endless stream batch by batch (as a queue consumer polls it). `fse.VectorStore` opens a store and searches it on the stored float16 or int8 rows, without a float32 copy, and scores it with linear weights: with `mode="exact"` the cosines, scores and order of the reference bit for bit, with `mode="blas"` faster for many queries, and by default (`"auto"`) the faster of both for the number of queries. `fse.Sink` documents the interface for other sinks, such as a vector database; `fse.MemorySink` keeps the rows in memory.
- A collection passed to `encode` that mixes str and token lists raises naming both rows.
- `fse.MemorySink.result()` gives int8 rows as `fse.QuantizedRows`, as `encode` does.
- `fse.FastTextParams` (for `WordVectors.from_arrays` of FastText vectors), `fse.CorruptArtifactError` and `fse.UnsupportedArtifactError` are public. Stored rows are `WordVectors.stored_vectors` and `stored_ngrams` (codes for float16 and int8), decoded rows `get_vectors` (`VectorStore.get_vectors(start=, stop=)` too), and a store or sink names the encoder it takes by `encoder_fingerprint`: a custom sink names it so for its check to apply. `WordVectors` are made only with `from_arrays` and `load` (the constructor raises), and the internal state of `VectorStore` (`info`, `shards`) and `ShardSink` (`info`, `reserved_rows`, `committed_rows`) is not public.
- Linear heads: `fse.Classifier` and `fse.Regressor` hold an encoder and one linear head `z = A x + b` trained elsewhere; fse trains none. `from_sklearn` reads a fitted scikit-learn estimator by its attributes, without importing scikit-learn (LogisticRegression and LogisticRegressionCV with the probability rule of the installed version, SGDClassifier, LinearSVC, the ridge classifiers, Perceptron, the linear regressors, and a Pipeline with an optional `StandardScaler`; a `Normalizer` is refused, as its rule for tiny rows is not `normalize@1`), `from_arrays` takes A, b, the labels and the link. They predict as scikit-learn names it (`predict`, `predict_proba`, `decision_function`, `classes_`) from texts, files, streams or the rows of a `fse.VectorStore`, and `predict_batches` predicts a stream batch by batch, optionally with the encoder's own vectors from the same pooling (`return_vectors=True`, which a `fse.ShardSink` can store). A head trained on raw means (an encoder with `normalize=False`) folds into the table on first use, so it predicts faster than `encode`; one trained on normalized vectors runs on the full mean in the worker. `save` writes the complete model or, for a head on raw means, a standalone file of the folded table and the bias with the same predictions (file kind `linear_head`, format 1). The logits and probabilities are bit-identical across CPU backends, worker counts and input classes, with the new identifiers `linear@1`, `exp@1` (an exp defined by its operations, within 0.94 ulp of exp on every float32 input it takes), `sigmoid@1`, `softmax@1` and `ovr@1`; the folded path and the vectors' path of a head on raw means agree within rounding, not bit for bit.
- `encode`, `encode_batches` and the heads take Arrow string columns: any object that exports one through the Arrow PyCapsule interface (`__arrow_c_stream__`, `__arrow_c_array__`), such as a pyarrow `Array` or `ChunkedArray`, a table column, a pandas 3 `Series`, a Polars `Series`, or a Hugging Face dataset as `dataset.with_format("arrow")["text"]`. fse reads `string`, `large_string` and `string_view` columns where the producer holds them, without copying the text and without pyarrow as a dependency, and gives the rows of the same texts as a list bit for bit. A null raises with its row; tables, binary, dictionary-encoded and extension columns raise with a hint.
- `save_pretrained(path)` and `push_to_hub(repo_id)` on `fse.Encoder`, `fse.Classifier` and `fse.Regressor` write and publish a Hugging Face folder: `config.json` (`model_type` fse, `fse_config_version` 1, `fse_kind`, `fse_format_version`, `model`, `fingerprint`; the file by which the Hub counts downloads), `model.safetensors` (exactly what `save` writes) and a `README.md` model card with the license the model records (and `base_model_relation: quantized` when a model converted from the Hub is stored as int8), plus checked extra files such as LICENSE. `from_pretrained` reads such folders locally and from the Hub (`Classifier.from_pretrained`, `Regressor.from_pretrained` are new) and compares the config with the model it loaded. A folder is written atomically and never replaces anything; `fse.PublishedNotDurableError` says that a folder (or a shard of a store) is published but its rename not confirmed durable. `push_to_hub` needs a license, publishes exactly one commit on top of the commit it read, refuses other content under the same names and other files unless `replace=True`, keeps license files already there, and checks every file at the new commit.
- `Encoder.quantize("float16" | "int8")`: any encoder with a float32 table, whatever its tokenizer (`fse_words@1`, `external`, `wordpiece@1`, `unigram@1`, FastText, a cut `truncate_dim`), becomes a new encoder with a float16 or int8 copy of its table by `quantize_rows@1` (int8 with one scale per row), which `save`, `save_pretrained` and `push_to_hub` write like any encoder; `Encoder.load` and `from_pretrained` accept such files for `wordpiece@1` and `unigram@1` too. Its rows are bit-identical on every CPU backend to the reference applied to the quantized table; how close they are to the float32 encoder is measured, not promised (rows below 2**-25 become zero in float16, an int8 row keeps its resolution per row, a sentence of only such rows is the zero row). The model card names the rule and the float32 table the rows were stored from. Quantizing a float16 or int8 encoder again raises, and so does a table with values beyond the float16 range. The tensors held besides the table are checked against their load checksums first, and a changed mapped file is never carried into the new encoder.
- `Classifier.quantize("float16" | "int8")` and `Regressor.quantize(...)`: a new model of the same class whose encoder is quantized by `Encoder.quantize` and whose head (A and b) is copied unchanged. On the cpu backend its predictions are bit-identical to the reference applied to the quantized table, for heads on raw means (folded) and on normalized rows, in store mode (with a store written by the quantized encoder; a store written by the float32 encoder is refused), after `save` and `load`, and in a standalone file made of the quantized model. How close they are to the float32 model is measured, not promised. A standalone model, or one of a float16 or int8 encoder, raises `ValueError`.
- Python 3.14 and 3.15, with pre-built wheels. On 3.14 and newer, `fse.gensim` needs gensim, which does not build there yet; everything else works.

### Changed

- The native `unigram@1` offers trie matches directly to its float64 Viterbi, avoiding temporary candidate arrays with unchanged token ids and rounding behavior.
- Loading `unigram@1` checks its charsmap once, creates the reference search list lazily, and avoids repeated JSON and vocabulary work. Native buffers stay independent. Strict input validation, token ids and persisted data stay unchanged.
- The native `unigram@1` normalizer combines independent consecutive single-byte Replace steps into one pass and caches single-byte ASCII charsmap matches, with unchanged normalization and token ids.
- The native `unigram@1` finds candidates with the vocabulary double-array trie, built at load, instead of repeated hashes and a Python set of proper prefixes. Its construction sorts binary keys and reuses their common prefixes to avoid repeated sibling searches on large vocabularies. Candidate order, float64 scores and token ids are unchanged. Nothing new is persisted.

- Loading a model from the Hugging Face Hub hashes each file once, with the one digest the commit pins it by (the sha256 of an LFS file, else the git blob id), where it computed both; the checks and their messages are unchanged. The `pin` of the `hub.file` record names that digest for every LFS file, also a `tokenizer.json` stored in LFS, which it used to name `git_sha1`.
- The automatic task plan (`chunk_bytes=None`) splits the last `workers` chunks of a run into two parts each when both keep the minimum chunk size (64 KiB), so fewer workers idle at the end of a run. Its numerical results are unchanged. An explicit `chunk_bytes`, inline runs and streams keep their cuts.
- fse logs through the standard library on fixed component loggers (`fse.artifact`, `fse.hub`, `fse.backend`, `fse.runtime`, `fse.store`) with an `fse_event` and `fse_`-prefixed fields on every record, which hold no paths, texts, Hub tokens or repository ids (docs/architecture/logging.md, "Logging"). `fse.enable_logging(level="INFO")` prints them to stderr in one line each, `fse.disable_logging()` undoes it. The `NullHandler` on `fse` is gone: without a logging configuration, fse's warnings now reach stderr. Logging never changes a result or an exception, whatever the application's handlers do.
- The failed removal of a temporary file or directory (a failed write of an artifact, a Hub folder, a shard or a store) is no longer ignored: while another error is raised, that error is raised unchanged with a note naming the path, and the failure is logged; otherwise, such as at the close of a `ShardSink` that dropped an empty shard, it raises.
- On the cpu backend every task of a text source tokenizes, checks its batch, pools and normalizes in one native call without the GIL in between (one section without the GIL instead of three, and none of the numpy checks that released and took back the GIL). Rows, errors and their messages are unchanged.
- `encode` of inputs below about 20 MiB at 10 workers runs fewer and larger tasks (about two per worker instead of eight), cut from the offsets of a list into chunks of about equal bytes, and a list of str or of token lists that fse joined natively is no longer scanned a second time before the first task, because the join gives valid UTF-8 by construction. Rows and token ids are unchanged.
- The error a run raises no longer depends on its task boundaries or its number of workers: it is the error of the earliest failing row, and for one row that of its earliest stage (a row that cannot be normalized is raised before a later row that overflows in pooling, also within one task). An invalid sentence that the scan finds is raised after the rows before it, so an earlier row that fails later in its pipeline is raised first. The messages of the tokenizers name the row of the run (`in sentence 7 (byte 512 of the source)`) instead of the position within a task (`in sentence 2 of the range`), also in later batches of `encode_batches`. An Arrow null is raised after the rows before it.
- The native `wordpiece@1` uses tables for ASCII normalization, skips impossible added-token starts and matches vocabulary pieces through a trie built at load. Token ids and persisted artifacts are unchanged.
- `fse_words@1` tokenizes plain words (only a-z and 0-9) without the rules of step 5, unless their length and first letter could make them one of the contractions without an apostrophe (`cannot`, `gimme`, `gonna`, `gotta`, `lemme`, `wanna`). The tokens are unchanged.
- On macOS a `ShardSink` publishes a shard with two full syncs (`F_FULLFSYNC`, which flushes the drive cache) instead of six or seven, with the same durability: the files and the manifest are sent to the drive with `fsync`, one full sync of the shard's directory makes them durable before its rename, and one of the store the rename. Linux and Windows sync as before.
- Normalization runs in place on pooled rows without two intermediate copies. Store inverse norms avoid repeated work. Every vector is unchanged bit for bit.
- A list or tuple of str passed to `encode` is converted to UTF-8 in parallel native threads instead of one `str.encode` per sentence. Subclasses of str, numpy arrays and invalid input (a row that is no str, a lone surrogate) take the former path, so the errors of invalid input are raised as before; every vector is unchanged. On macOS the join of token lists no longer keeps about the size of the joined text resident after every call.
- Pooling float32 word vectors on arm64 (NEON) keeps the sums of 32 values at a time in registers over up to 64 words instead of reading and writing them for every word. Every vector is unchanged bit for bit. Float16 and int8 vectors, x86 and more than 1024 dimensions keep the previous loop.
- gensim is no longer a dependency: install `fse[gensim]` for `fse.gensim`.
- Building from source needs MSVC on Windows, or GCC or Clang elsewhere; MinGW is refused, because its `fmaf` rounds twice.
- Checksums and fingerprints of every artifact are xxh3-128 (`xxh3-128:` and 32 hex digits) instead of sha256, computed by one harness. Artifacts written by a pre-release of 2.0 with sha256 checksums raise `UnsupportedArtifactError` and must be written again; there is no migration. The values identify content against accidents, not against an attacker (docs/architecture/persistence.md, "Identities").
- The only dependencies are numpy, pydantic, xxhash (`xxhash>=3.2.0`) and huggingface-hub (`huggingface-hub>=1.0`, imported only when a model of the Hub is loaded, so `import fse` stays as fast as without it). scipy, smart_open, wordfreq, psutil and threadpoolctl are no longer needed.
- The scan of a file, a string collection or an Arrow column, which validates the UTF-8 and cuts the chunks, no longer counts the tokens and empty sentences it never used; it returns only the sentences, chunks and the first invalid sentence. No result, error message or chunk changes.
- A sentence-transformers model with a Dense module after its StaticEmbedding is refused as "the model has a Dense module" whatever its activation or config, without reading the folder or `config.json` of the module (a root `config.json` that every model's loading reads first still applies when the module's path is the model's own folder; a Dense module with an activation, or without a config, said "no static embedding model" before). A Dense module with a broken `config.json` in its own folder or an invalid `path` raises `UnsupportedArtifactError`, not `CorruptArtifactError`, and one file fewer is fetched from the Hub.

### Removed

- The 1.x API: the 1.x models `Average`, `SIF` and `uSIF`, `SentenceVectors`, the input classes, `Vectors` and `FTVectors`, and the modules `fse.models`, `fse.inputs` and `fse.vectors`. Accessing one of the removed 1.x names on `fse` raises an `AttributeError` that points to fse 1.1.0 on PyPI and the branch `1.x`.
- Training. fse 2.0 is an inference engine for finished static embeddings and learns nothing: the 2.0 recipes `Average`, `SIF` and `USIF` with `fit` (word weights from counts, the Gram matrix and its components, projections, folding), `fse.Corpus` (its reason was the passes of fit), stored recipes and learned components, word counts in `WordVectors` (`counts=`, `.counts`, and `from_gensim(counts=)`), and encoders that reference a separate table (`Encoder.load(path, word_vectors)`, `Encoder.folded`, `Encoder.recipe`, `Encoder.input_dim`): every encoder holds its own table, so two encoders of the same word vectors hold two copies. The postprocessing steps `remove_components@1` and `project@1` are gone from the contract and the kernel; `normalize@1` remains. SIF and uSIF tables are made offline with the 1.1.0 recipe, in a notebook that follows before the release. Encoders and word vectors written by a development version of 2.0 before this change (with recipes, weights, learned or folded steps, counts, or without their own table) raise `UnsupportedArtifactError`: rebuild them.
- The 1.x notebooks; they stay on the branch `1.x`.

### Fixed

- `Encoder.from_pretrained` and `StaticModel.from_pretrained` with `local_files_only=True` load a cache that holds only the files fse reads. The cached snapshot is found in the layout of the cache (a commit hash, or the commit in `refs/<revision>`) and no longer through `snapshot_download`, which huggingface-hub 2 refuses when the cached tree listing of the commit names any file missing locally, such as the evaluation files of `minishlab/potion-multilingual-128M`. A missing ref or snapshot still raises `FileNotFoundError`, every file is still checked by its blob name, and a revision that leads out of `refs` raises `ValueError`.
- `Encoder.from_pretrained` and `StaticModel.from_pretrained` load offline without a revision after fse loaded the model online. fse downloads at the commit it resolved, and huggingface-hub records `refs/<revision>` only for a download by name, so such a cache had no `refs/main` and `local_files_only=True` raised `FileNotFoundError`. After the first file of a load by revision name (None is `main`, a branch or a tag) is checked against the commit, fse now writes `refs/<revision>` with that commit, atomically and in the format of huggingface-hub (a ref that moved on the Hub is updated to the commit fse resolved). A commit hash writes no ref, an offline load writes none, and a link in `refs` raises `CorruptArtifactError`. On Windows, where a rename over a ref that another process renames over or reads at that moment is refused, the write is tried again for a short time.
- An interrupt (Ctrl+C) while a `ShardSink` closes no longer leaves threads running and temporary shard directories behind. When `close` runs in the main thread with Python's default SIGINT handler, the work still waiting is dropped, the piece each thread runs is finished (a shard being published is published if all its rows were written), further interrupts are deferred, and one KeyboardInterrupt is raised once every thread has ended and the temporary directories are removed; a piece that blocks, such as a write to a drive that hangs, still keeps `close` waiting. With another handler, or from another thread, nothing is deferred.

## [1.1.0] - 2026-10-27

1.1.0 is the last feature release of the 1.x line; 1.x receives bug and compatibility fixes from here on, while fse 2.0 is developed as a rewrite.

**Upgrading from 1.0:** SIF and uSIF give different vectors than 1.0, because their principal components are computed exactly and uSIF weights the removed components like the reference implementation; retrain such models for comparable vectors (see Changed and Fixed). Arguments are validated strictly and raise a `pydantic.ValidationError`. fse requires Python 3.11 or newer and adds the dependencies pydantic and threadpoolctl.

### Added

- **Smaller sentence vectors:** `sv_dtype="float16"` or `"int8"` on `Average`, `SIF` and `uSIF` (`dtype` on `SentenceVectors`) stores the sentence vectors in half or a quarter of the memory. They are computed in float32, and every read returns float32. Training, `train(update=True)`, `infer`, the similarity searches, `save`/`load` and `sv_mapfile_path` support both formats. int8 keeps one float32 scale per vector. On the STS Benchmark over the 15 vector sets of the README with CBOW, SIF-10 and uSIF, float16 changes the scores by at most 0.01 points and int8 by at most 0.02 points; float16 changes at most 0.4 % and int8 up to 7 % of the ten nearest neighbours of a sentence.
  - With index i for the i-th sentence, training writes into a ring of float32 windows and stores each finished window, so no float32 matrix of all sentences exists; SIF and uSIF read the input twice to learn their components first. The stored vectors are bit-identical to a float32 training stored afterwards. Other inputs (custom or shared indices, no compiled extension, a replaced `_do_train_job` or `_post_train_calls`) train into a float32 matrix of the new rows first, and the log names the reason.
  - float16 and int8 vectors are searched and scored by a compiled kernel directly on the stored values, in parallel, instead of being converted to float32 block by block.
  - `SentenceVectors.convert(dtype)` changes the format of existing vectors, also of loaded and memory-mapped ones; `get_vectors` and `iter_blocks` read float32 rows, the latter in blocks for any number of vectors.
- **Smaller word vectors:** `wv_dtype="float16"` or `"int8"` on `Average`, `SIF` and `uSIF` keeps the word vectors (and FastText ngram vectors) the model averages in half or a quarter of the memory. The model quantizes a copy once; the passed word vectors stay unchanged. With `wv_mapfile_path` the codes are written to a file and memory-mapped, and `save`/`load` keep them. On the STS Benchmark over the 15 vector sets with CBOW, SIF-10 and uSIF, float16 changes the scores by at most 0.01 points and int8 by at most 0.12 points.
- **Prefetching and row kernels:** the kernel prefetches the rows of the next words while it adds one, which makes float32 training up to about 1.2 times as fast end to end without changing its results. float16 and int8 rows are added by routines chosen at import: AVX2, FMA and F16C on x86-64 Linux and macOS when the CPU has them, NEON on arm64, portable loops otherwise; float32 rows keep using BLAS `saxpy`.
- `SentenceVectors.score(weights, bias)` computes `X @ weights + bias` over all sentence vectors in blocks, for example the logits of a logistic regression, in any storage format and optionally into a memmap.
- `CorpusFile(path)` for a local UTF-8 text file with one sentence per line, and `TextList(strings)` for strings in memory. They give exactly the sentences of `IndexedLineDocument` and `SplitIndexedList`, but every worker reads, splits and looks up its part without the GIL, so training scales with `workers`.
- `min_similarity` for `most_similar` and the `similar_by_*` methods returns only results at or above a cosine similarity (#34).
- A `NOTICE` file documents the parts adapted from gensim (LGPL 2.1, used under the GPL 3) and fastText (MIT), with their original copyright notices.
- Pre-built wheels for Linux (x86_64, aarch64), macOS (arm64, x86_64) and Windows (x86_64) on Python 3.11 to 3.13.
- Support for numpy 2, Cython 3, current scipy, gensim 4.4 and huggingface-hub 2.x.
- A clear `ImportError` when gensim < 4 is installed.
- `__all__` in `fse` and `fse.models`.
- Type information: the package ships a `py.typed` marker and a stub for the Cython extension, so type checkers see the annotations of fse.

### Changed

- Arguments of the public entry points are validated strictly with pydantic: the model, `SentenceVectors` and `IndexedLineDocument` constructors, `train`, `infer`, `most_similar`, the `similar_by_*` methods and `from_pretrained`. Wrong types and out-of-range values such as `workers=0` or `alpha=-1` raise a `pydantic.ValidationError` (a `ValueError`) at the call, and nothing is coerced, so `workers="2"` is an error. Integer arguments accept numpy integer scalars, float arguments must be finite, and mapfile paths accept `str` and `pathlib.Path`.
- New dependency: `pydantic>=2.5`.
- **Python inputs scale with workers.** With two or more workers, an `IndexedList` or `CIndexedList` of lists of str is no longer encoded by the single producer thread: every worker copies the tokens of its own chunk while holding the GIL and looks them up and averages them without it. A `SplitIndexedList` whose items are a list of str is trained natively like a `TextList`. Word lookups in the native paths read one 32-byte slot per word. Results are bit-identical; one worker, `infer`, subclasses that change how items are read and other item types keep the previous path. A list that changes between the scan and training now raises. Measurements are in #88.
- **SIF and uSIF no longer slow down with more workers.** OpenBLAS started its own threads in every worker for the Gram matrix and the removal of components, so 16 workers could run 256 BLAS threads on 16 cores. During `train`, and while `infer` removes components, BLAS now gets `cores // workers` threads (at least one; the limit holds for the whole process during the call), and the components are removed by all workers in parallel. Results are unchanged.
- New dependency: `threadpoolctl>=3.1.0`, to limit the BLAS threads.
- At DEBUG level, every training logs how much of its time the producer and the workers spend reading, averaging and waiting, and which side limits it.
- A new logo, with a light and a dark variant that the README picks by color scheme. The sources and their generator are in `docs/assets/logo/`; `docs/assets/fse.png` stays for the READMEs of earlier releases.
- Unknown keyword arguments to `Average` and `BaseSentence2VecModel` raise a `pydantic.ValidationError` instead of being silently ignored, like at every other validated entry point.
- Sentence tuples must have exactly two elements, `(words, index)`; longer tuples raise a `ValueError` instead of losing the extra element. `restrict_size=(lo, hi)` with `hi < lo` raises a `ValueError` instead of returning nothing.
- The input classes reject sets with a `TypeError`. A set has no order, so the sentence indices would be arbitrary; pass `sorted(...)` instead.
- Every sentence is checked to be a list of `str`, not only the first one.
- `set_madvise_for_mmap` is no longer called on every model construction and load; it never applied any advice.
- Requires Python 3.11 or newer. Python 3.10 reached its end of life in October 2026; installations on 3.10 and older keep fse 1.0.0. Python 3.14 is not supported yet, because gensim does not build there.
- Minimum versions: numpy 1.26.4, scipy 1.11.4, gensim 4.3.3, smart_open 6.4.0, wordfreq 3.1.0, huggingface-hub 0.23.0, psutil 5.9.0.
- Packaging moved to `pyproject.toml`; the version now comes from git tags.
- The warning about a missing C extension is a `RuntimeWarning`.
- Faster preparation and input handling, with identical results: sentence vectors are initialized in blocks instead of one row at a time, the list input classes iterate directly instead of through `__getitem__`, and SIF and uSIF read all word counts at once.
- Removing principal components for SIF and uSIF works in blocks of rows. It used to allocate a second copy of the whole sentence matrix in RAM, also for vectors on disk (`sv_mapfile_path`).
- **Training writes the sentence vectors in one pass.** With index i for the i-th sentence (every input class except the `C*` lists with custom indices) and the compiled extension, each job sets its own rows to EPS instead of a separate pass over all rows, and SIF and uSIF sum the Gram matrix of the finished rows during training instead of reading them again. Results are bit-identical. For SIF and uSIF trained from scratch on a memmap larger than the RAM, this removes two separate full passes over the file (about 28 percent less time and 43 GB less read for 15 million sentences of dimension 300); measurements are in #83.
- **SIF and uSIF compute their principal components exactly, over all sentence vectors.** They used a randomized SVD from scikit-learn on a sample of at most `cache_size_gb` (one million vectors in 1.0). Now the Gram matrix of all vectors is summed over blocks in float64 and decomposed, without a random sample: every vector is read once, memory stays at about one block, and repeated runs give the same components. The components change, so SIF and uSIF embeddings differ from earlier versions; on the STS Benchmark, SIF-10 scores move by at most 0.04 points and uSIF scores not at all, and the README table is remeasured. Computing the components is about 6 times faster for one million vectors of dimension 300 in memory, and SIF and uSIF train 2.5 to 4.5 times faster end to end on that corpus; measurements are in #82. When a training computes new components, SIF and uSIF raise a `ValueError` before it starts, leaving the model unchanged, if `components` exceeds the number of sentence vectors or their dimension; `train(update=True)` with learned components reuses them and is not checked; `compute_principal_components` raises a `ValueError` for more components than vectors or dimensions and for NaN or infinite values, and a `TypeError` for vectors that do not hold real numbers.
- **More workers now help (#61).** The producer thread encodes each job and the workers average it without holding the GIL, so training no longer stalls at two workers; with the input in memory, the producer is the limit from two to four workers on. The input scan runs in Cython. With one row per sentence, results are bit-identical for any number of workers; when several sentences share a row, the order of additions can vary within float32 rounding. Before and after measurements are in the pull request; the throughput of the current release is in the README.
- `batch_ngrams` above 2^24 (`fse.models.average_inner.MAX_NGRAMS_LIMIT`) raises a `ValueError` in the Cython routines; no word has that many ngrams, and the bound keeps buffer sizes in range.
- The Cython routine averaged at most 10,000 words per sentence and always up to 40 ngrams per unknown FastText word; it now averages every word and uses `batch_ngrams`, like the numpy fallback.
- FastText ngrams of out-of-vocabulary words are hashed in C instead of Python, with the same buckets as gensim. For a FastText model without ngram buckets (`bucket=0`), both averaging routines give unknown words no vector instead of the `ZeroDivisionError` of the numpy fallback; `train` still requires ngram vectors.
- Jobs hold at most `batch_words` sentences as well as `batch_words` words, so long runs of empty sentences no longer form one large job.
- The training log reports the end-to-end time, including the scan and component removal, next to the time of the training phase.
- `IndexedLineDocument` stores its line offsets as an int64 array, 8 bytes per line instead of about 40 in a Python list, and finds them with numpy in blocks instead of line by line in Python.
- The scan tracks indices that are not the positions of their sentences in a bitmap instead of a Python set (60 to 70 bytes per sentence). For a permutation, the bitmap ends with an eighth to a quarter byte per sentence; on the way, up to about one byte per sentence of indices waits for it to grow, and merging them takes a few temporary arrays of that size. Indices above 2⁶³ - 2 raise a `ValueError`, since their output could not be allocated anyway.
- `most_similar` keeps a running top-N over blocks of rows instead of computing and sorting the similarities of all sentences at once, so with a positive `topn` the search needs memory for one block and the candidates instead of a similarity per sentence. The normalized vectors from `init_sims` are unchanged. Equally similar sentences are ordered by index; the order used to be arbitrary.

### Fixed

- `lang_freq` overwrote the word counts of the passed model, and `wv_mapfile_path` replaced its vectors with read-only memmaps, so the caller and every further model built from it saw the change. Models now work on a shallow copy of the word vectors in both cases, with their own vocabulary containers, so words added to the passed model later do not reach the copy; the vector arrays themselves are still shared, not copied. The compiled routines also check that the vocabulary has no more words than there are word vectors.
- An existing word mapfile (`wv_mapfile_path`) was reused without any check: a larger file was read as a prefix, and a file of the same size with other vectors gave wrong sentence vectors without an error. The file must now hold exactly the vectors of the model, checked by size and content, otherwise a `ValueError` asks to delete it or use another path; loading a model checks the sizes.
- `Average` failed with `KeyError: 'count'` for word vectors without frequency counts, such as `KeyedVectors` built with `add_vectors`, although averaging needs no frequencies. SIF and uSIF now raise a clear `ValueError` when counts are missing or all zero.
- FastText models without ngram buckets (`bucket=0`), which gensim supports, were rejected by `train`. Unknown words of such models add no vector.
- **uSIF results change.** uSIF removed each principal component weighted by λ² instead of λ, unlike the reference implementation ([kawine/usif](https://github.com/kawine/usif)). Embeddings from uSIF models trained with earlier versions differ from 1.1.0. On the STS Benchmark the fix raises uSIF scores on all 15 published vector sets, by 0.18 to 1.30 points (mean 0.75) when both formulas run in the same environment; the README table is remeasured. The previous table is in the [1.0.0 README](https://github.com/oborchers/Fast_Sentence_Embeddings/blob/v1.0.0/README.md#results).
  uSIF models saved by earlier versions keep the old weighting when loaded, so `infer` and `train(update=True)` produce vectors that match their stored ones; a warning recommends retraining.
- An exception in a worker thread or in the input iterable made `train()` hang forever. It is now raised in the calling thread after all threads have stopped.
- Only the first input item was validated. A negative or non-integer index later in the input could hang training or silently write into the wrong row. Every item is now checked, and `numpy` integers are accepted as indices, so `CIndexedList` works with an ndarray `custom_index` as documented.
- Generators and other one-shot iterators returned all-zero vectors from `infer` and failed with a misleading error in `train`, because the input is read twice. They are now rejected with a clear `TypeError`.
- `save()` with `wv_mapfile_path` set the word vectors of the live model to `None`, so later `infer` calls read invalid memory, and a second save and load cycle failed. The vectors are now only left out of the pickle.
- The Cython kernel now checks dtype, memory layout, writeability and shapes of the arrays it accesses through raw pointers, and the index of every sentence against the target rows, instead of reading or writing invalid memory.
- The FastText ngram buffer of `BaseSentence2VecModel` could be smaller than the kernel expects when `batch_words` or `batch_ngrams` were set below the defaults.
- `most_similar` and `init_sims` failed with a `TypeError` for sentence vectors stored on disk (`sv_mapfile_path`). The normalized vectors are now written into the mapfile in blocks.
- `init_sims(replace=True)` did not replace the vectors, and `get_vector(use_norm=True)` failed before `init_sims` was called.
- Normalizing a sentence without known words returned NaN; it now stays a zero vector.
- The Cython routine computed the position of a row as row times dimension in 32 bits. From about 14.3 million sentences at 300 dimensions (43 million at 100) on, sentence vectors were silently added to wrong rows near the start of the matrix. Offsets are now 64 bit, and more than 2³² - 1 rows or words raise a `ValueError`.
- `train(update=True)` wrote the new sentences into the existing rows and left the appended rows empty. New sentences keep their indices starting at 0 and are stored after the existing rows. SIF and uSIF remove the components of the first training from the appended rows only, instead of removing them from all rows again.
- SIF and uSIF with `components=0` could not be trained a second time.
- In the Cython path, a FastText out-of-vocabulary token without any ngrams (for example a token shorter than `min_n - 2` characters) added the vector of the first vocabulary word. It now adds nothing, as in the numpy fallback.
- Saving a model with `sv_mapfile_path` wrote the sentence vectors a second time into `.npy` files, and loading returned them in RAM instead of reopening the mapfile.
- `x in sentence_vectors` raised a `KeyError` for non-integer values and accepted negative indices; it now returns `False` for both. The `KeyError` for a missing index names the index.
- `str(model)` reported the number of sentences as `vector_size`.
- Scanning failed for an empty input and for corpora with less than one word per sentence on average.
- The numpy fallback counted empty sentences as effective sentences, unlike the Cython path.
- Interrupting training, for example with Ctrl+C, could leave worker threads blocked on a full queue.
- With several workers, sentences mapped to the same row (for example `CIndexedList` with repeated indices) could lose updates when two workers added into the row at the same time. Rows shared by several sentences are now updated under locks; unique indices stay lock-free.
- `pip install fse` failed on Python 3.11 and newer, because the shipped C source was generated by an old Cython version.
- Building under pip or poetry crashed with `AttributeError: 'dict' object has no attribute '__NUMPY_SETUP__'`.
- `import fse` failed in a clean environment, because `requests` was imported but not declared.
- `Vectors.from_pretrained` and `FTVectors.from_pretrained` raise `ValueError` again for a model that does not exist on the hub.
- The numpy fallback now accumulates many-to-one sentence mappings like the Cython routine instead of overwriting them.
- Training crashed with `ZeroDivisionError` when a run finished faster than the timer resolution, for example on Windows.
- Wheels and source distributions no longer install a top-level `test` package.
- `fse.__version__` reported 0.2.0.

### Deprecated

- `cache_size_gb` of `SIF`, `uSIF` and `fse.models.utils.compute_principal_components` has no effect, because the components are computed over all vectors. Passing it raises a `DeprecationWarning`; it will be removed in 2.0.
