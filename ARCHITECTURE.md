# Architecture

This document describes how fse is put together and the rules that keep it correct. It is the reference for changes to the contracts, the native kernel and the tests. When a change alters one of these rules, update this file in the same pull request.

master is the development branch of 2.0, the inference engine for finished static embeddings (such as POTION/Model2Vec tables and the StaticEmbedding of sentence-transformers): an encoder is a finished model, its table pooled per sentence by `weighted_mean@1` with an optional `normalize@1`. fse 2.0 trains nothing (maintainer decision of 29.10.2026): word weights, removed components and projections of a model such as SIF or uSIF are folded into its table offline, by a notebook with the 1.1.0 recipe that follows before the release. A linear head after the mean (`fse.Classifier`, `fse.Regressor`, PR 13) is imported from where it was trained (scikit-learn or arrays), never trained by fse, and runs in the worker as an operation of its own (`linear@1`, section "Linear heads"). The 1.x API (`Average`, `SIF`, `uSIF`, the inputs and `SentenceVectors`) was removed from master; it lives on the branch `1.x` and in fse 1.1.0 on PyPI, and accessing one of its names on `fse` raises an `AttributeError` that says so. Items marked 2.1 are additions that must fit without changing anything below.

## Native kernel

`_native_kernel.h` and the headers it includes implement `weighted_mean@1` (pool and accumulate), `dot16`, the step `normalize@1`, the linear score of the numerical contract below, storage quantization, inverse norms, cosine search and, for linear heads, the bias of folded logits, `exp@1`, the links and the labels (`_native_kernel_head.h`: scalar float32 code, one rounding per operation, the same on every instruction set). Each is one C loop, instantiated per ISA: portable (`fmaf`), AVX2 with FMA and F16C on x86 (selected at run time by cpuid and xgetbv, so one wheel serves every x86 machine) and NEON on arm64. `_native.pyx` validates all arrays before it releases the GIL, then calls the loop of the chosen ISA (`available_isas`, `default_isa`; `isa=` selects one for tests). The rules that make it bit-identical to `fse._reference`:

- Every multiply-add is an explicit fused multiply-add in token order; the compiler must not contract or reorder anything else. The extension is built with `-ffp-contract=off -fno-fast-math` (`/fp:precise` on MSVC), see `setup.py`. MinGW is refused, because its runtime computes `fmaf` with two roundings.
- The floating-point environment is fixed for the duration of every call: round to nearest, no flush-to-zero or denormals-are-zero (MXCSR on x86, FPCR on arm64). The previous state is restored afterwards, also after an error. Each Python entry point sets it for the whole call, so the numpy conversions of its arguments (such as `bias`) run in it too, and each C entry point sets it again and calls its arithmetic only through functions marked never to be inlined, so no compiler can move the arithmetic before it.
- Dimensions are limited to `MAX_DIM` (2**30), because the loops index a row with `int`. Batches are read-only views; the kernel checks their offsets again before it reads through raw pointers, and `out` must not overlap the rows, weights or the batch.
- Reductions over the dimension use `dot16`: 16 lanes, element i in lane i % 16, then a tree 8/4/2/1. Lanes are not padded with zeros, because a lane can hold -0.0.
- Word rows are prefetched 8 tokens ahead, also across sentence boundaries; prefetching changes no result.
- The NEON float32 loop (`_native_kernel_tiles.h`) cuts a sentence into tiles of at most K = 16 KiB / row bytes (at most 64) contributions and keeps the accumulators of each block of 32 values (then 16, 8, 4 and single values) in registers over a tile, storing them to the out row between tiles. Per value this is the same sequence of fused multiply-adds from +0.0 in token order, and a partial sum of -0.0 is stored and reloaded as such, so the bits are those of the row loop. Rows of more than 1024 values, and the other loops, add one row at a time into the out row. The header states the invariants of the tile builder (every contribution once, in order; g once per unknown word; the token count as divisor; the prefetches of the row loop), and no load reads past a row.
- A row that is not finite raises with its row number, as the reference does.

`tests/test_conformance.py` and `tests/test_conformance_steps.py` compare every CPU backend in `BACKENDS` (`tests/support/conformance.py`) with the reference bit for bit, and every device backend with the cpu backend under the tolerance contract (below), for every dtype, step list, empty, long and unknown-word sentences and subnormal values. Its meta-tests check that the bit-identical suite fails for a CPU kernel without fma, with `acc / n`, with an EPS start or with zero-padded `dot16`, so a weakened comparison cannot pass unnoticed; the meta-tests of device backends check the tolerance contract instead. `tests/test_conformance_head.py` runs every CPU backend through the runtime of linear heads against `fse._reference_head` bit for bit on every path (folded, normalized, unfolded with the vectors, standalone) for float32, float16 and int8 tables, FastText, k = 1, 2 and 17 and ties, with the errors of the fold and of `normalize@1`, and checks folded against unfolded logits within the bound of `tests/support/head_bound.py`; its meta-tests (`tests/test_conformance_head_meta.py`) show the cases catch a bias folded into the table, added before `1/n` or twice, a skipped norm or its errors, ties to the larger index, the naive sigmoid and another order of the softmax sum. `tests/test_conformance_tiles.py` adds block and tile edges, -0.0 witnesses in every block and across tiles, a late overflow and rows next to pages without access; its meta-tests run a numpy model of the tiled loop and check that the cases catch the mistakes of a tile builder and of the accumulators, in every block and for every K.

## Text sources

`fse._text` turns text into batches (stages 1 and 2). A source holds its sentences as one UTF-8 buffer: strings in memory with their offsets, or the memory-mapped lines of a file. `encode` takes texts in memory as a list, tuple or one-dimensional numpy array either of str or of lists or tuples of str (`fse._encoder._inputs`): the first row decides which, a row of the other kind raises with both rows named, and the tokenizer is checked before any row; a path and a stream are passed to it directly. (`fse.Corpus`, which held such a source for the passes of fit, was removed with fit: converting a list of str costs about 3 ms for 400,000 sentences since the native join.) Strings and token lists (the external tokenizer) are joined into that buffer in one native pass, a string as its UTF-8 (`join_strings`) and the tokens of a sentence separated by one space (`join_token_lists`): it reads exact lists, tuples and str through borrowed pointers, checks every str (no lone surrogate; a token also non-empty and without a code point of W) and writes its UTF-8 at once, in parts of at least 4,096 sentences that up to 8 native threads run while the calling thread holds the GIL and waits. No Python code can run during the pass (no calls, no references dropped, no Python object allocated, and no other Python thread gets the GIL; this is why the extension refuses to compile for free-threaded Python, `Py_GIL_DISABLED`), and every str object, scattered in memory, is read once: that read is what the pass costs. 85.7 million WikiText tokens take 0.65 s on an M1 Pro (2.1 s in one thread, 11 s in Python), and 400,000 strings of 20 tokens 3 ms instead of the 70 ms of `str.encode` per string, so `Encoder.encode` of such a list takes 0.64 of its former time on the cpu at 8 workers (every StringSource, so a list or tuple of str passed to `encode`; a `StreamSource` still encodes each string in the calling thread); a second pass to size the buffer first doubled the time, prefetching the next tokens gained nothing measurable; a buffer grows into a new block with a copy, not with `realloc`, because on macOS the blocks of a freed chain of large reallocs stayed resident and the RSS grew by about the joined bytes on every call. Other types (subclasses, which may override `encode` or `split`, a numpy array, a legacy string of 3.11) and every invalid str go through the Python path, which raises the errors in their order: for strings the type and then the UTF-8 of each sentence in turn, for token lists the types and tokens of all sentences first, then the UTF-8 of every sentence. `scan` validates the UTF-8 of every sentence in threads without the GIL and cuts the source into chunks of about 64 KiB to 1 MiB (at most `MAX_CHUNK_ROWS` sentences); `encode` turns one chunk into a Batch with a `TextLookup` (the tokenizer, the `VocabTable` built from the vocabulary bytes of the word vectors, and the FastText buckets) and a `Workspace`, the buffers one worker reuses. `make_vocabulary` builds the `VocabTable` of word vectors once as a `Vocabulary`; every lookup of the same words in the same order (checked by `WordVectors.vocabulary_fingerprint`, the fingerprint of `vocab.bytes` and `vocab.offsets` alone) can share it, so an encoder builds it once for all its backends and passes. `fse._text_file.FileSource` reads the lines of a file. Every sentence is one row, empty ones included. Tokens are matched to the vocabulary by their exact UTF-8 bytes, so with `fse_words@1` a word with uppercase letters or whitespace (such as `New_York` in GoogleNews) is never matched. `tools/make_unicode_tables.py` generates the lowercase tables from `UnicodeData.txt`; both generated files are checked in and compared with each other in the tests. With `wordpiece@1` the encoder's `TokenizerSpec` (`fse._tokenizer_spec`: the identifier, its parameters, `fse.unknown` and the length rule, immutable) goes through `EncodeSpec` and the `Pipeline` to `make_lookup`, which builds a `WordPieceState` once from it and the vocabulary: the `VocabTable` of all tokens, a byte trie of all tokens (`_native_wordpiece_trie.h`, a static double array built at load from the vocabulary bytes in about 14 ms and 0.7 MiB for potion-base-8M, 32 ms and 1.6 MiB for potion-base-32M; never persisted) with the node of the continuation prefix, and the added tokens; a sentence is then split at the added tokens, normalized and pre-tokenized into a buffer of the `Workspace` and matched word by word, without the GIL. The native path has fast paths that give the ids of the plain rules: the scan for added tokens jumps to the bytes they start with (`memchr` for one such byte); ASCII bytes are normalized through 128-byte tables derived from the composed Unicode table when the module loads (8 printable bytes lowercased at once), but only while no combining marks wait in a run (an ASCII byte ends a run, a removed one does not), and pre-tokenized by a class table (8 bytes of a-z and 0-9 skipped at once); the length rule counts 8 ASCII bytes at a time and still validates the whole sentence; the code points of a word are counted only when it has more bytes than the word limit; a word is first one lookup of the `VocabTable`, and after a miss each piece is the longest token the trie reads from the root or the prefix node at a code-point boundary, which is what the greedy loop of lookups returns. The module refuses to build a state when the Unicode table gives an ASCII byte a shape the tables cannot hold. A private switch (`_generic`, for the tests, never persisted) takes the plain rules for every step, and the tests compare both paths; on an M1 Pro the fast paths make the tokenizer alone 2.16 (WikiText-103) and 1.71 (MASSIVE) times as fast at one thread, and `Encoder.encode` of potion-base-8M 1.64 and 1.37 times at one worker.

**Arrow string columns.** `fse._text._arrow.ArrowSource` reads a column that any producer exports through the Arrow PyCapsule interface (`__arrow_c_stream__`, else `__arrow_c_array__`; https://arrow.apache.org/docs/format/CDataInterface/PyCapsuleInterface.html), so fse needs no pyarrow: pyarrow arrays and chunked arrays, pandas 3 Series (`large_string`), Polars Series (`string_view`, whatever schema is requested) and Hugging Face datasets in Arrow format (`string`, chunks of 1,000 rows, memory-mapped). `encode` and the heads check for the protocol before the collection rules, every batch of `encode_batches` may be such a column, and its rows come from the source, not from `len()`; a producer that cannot export (pandas without pyarrow) is read as a stream with a warning, and a `datasets` Column, which exports nothing, raises with the Arrow-format path. No schema is requested. The native part (`_native_arrow.pxi`, `_native_arrow_column.pxi`, `_native_arrow.h`) moves the arrays out of their capsules in the calling thread, with the GIL, and owns them until `ArrowSource.close` at the end of the call, when each is released once, with the GIL (never while a scan or encode reads it); the stream is read whole when the source is made, so its rows are known and the scan checks every row before the first is encoded. It reads `utf8` (`u`), `large_utf8` (`U`) and `utf8_view` (`vu`) where they are: a row is `(pointer, length)` from its int32 or int64 offsets or from its 16-byte view (inline up to 12 bytes, else a variadic buffer, index and offset). Rows are numbered across the chunks, and a chunk of the runtime may span many Arrow chunks, so the runtime plans an Arrow source like a `StringSource`, and its batches and rows are those of the same texts as a list, bit for bit (the conformance suites take Arrow columns as input classes). It refuses tables (naming their string columns), binary, dictionary-encoded and extension columns, and raises on the first null with its row, reading the validity bitmap whatever the null count says. Before it forms a pointer from a value it checks: the formats, children, dictionaries and capsule names; lengths, array offsets and every sum and product of them against `INT64_MAX`, `SIZE_MAX` and `PY_SSIZE_T_MAX`; the required buffers; the null count (from -1 to the length; without a bitmap only 0); the first and last offset of a chunk; the sizes of the view buffers (read with `memcpy`); and, per row as it is read, offsets within the data up to the chunk's last offset, and views within their buffer's stated size; then the UTF-8 and the tokens as for every source. Offsets or views that are not aligned are copied once into an aligned buffer and logged; the text is never copied. **The producer's obligations**, which the C Data Interface leaves to it and no consumer can check: every buffer is at least as large as its layout implies (the bitmap, the offsets or views up to `offset + length`, the data up to the last offset, each view buffer of its stated size), and no buffer changes while fse reads it. Under these obligations fse never reads outside a buffer; a producer that breaks them gives an error or wrong rows that fse cannot detect. The Arrow scan counts tokens with a copy of `_count_tokens` of its own, because a second caller changed the machine code of `scan_spans` (every existing source).

`fse._stream.StreamSource` takes sentences from any iterable (a queue consumer, a crawler, log lines) and is read once. The runtime reads it in the calling thread, a collection of at most `chunk_rows` sentences (65,536) or about `chunk_bytes` (8 MiB) at a time, and only when its window of tasks has room, so a slow sink slows the source and memory stays bounded by one collection and the window. A sentence that is no str or has no UTF-8 form, and an error of the iterator, are raised after the rows before them were committed, with the row number counted from the start of the stream. The iterator is never read from another thread. One thread reads a stream, so a stream gives at most what that thread can collect: about 2.8 million sentences per second on a 16-vCPU EPYC (`bench_runtime.py stream`), the same as a StringSource up to about 8 workers and 0.8 to 0.9 of it at 16; a native reader may lift this later.

## Rules

### Validate strictly, never fail silently

Invalid input raises a clear exception at the API boundary. Nothing is coerced, ignored or truncated without an error, and an unexpected keyword argument is an error (`pydantic.ValidationError` at validated entry points). A slower but correct fallback is logged as a warning.

Public entry points whose own work dwarfs a few microseconds use `fse._validation.validate_arguments`, a strict pydantic `validate_call`, with constraints such as `PositiveInt` in the signatures. Methods called per element in loops, and parameters that hold bulk data, check explicitly instead, because validation would add measurable overhead or copy the data; such parameters stay `Any` in validated signatures. Integer constraints accept numpy integer scalars, float constraints reject infinity and NaN.

### float32 throughout

Word vectors, weights and sentence vectors are computed in float32. Word vectors may be stored as float16 or int8 and are widened exactly; every sum runs in float32. The kernel takes raw pointers, so arrays must have the expected dtype and be C-contiguous, which `_native.pyx` checks before the GIL is released.

## Build

The extension is compiled from `_native.pyx`, the `.pxi` parts it includes (one translation unit, so `cdef inline` functions inline across parts) and the `_native*.h` headers at build time with Cython 3 against numpy 2 headers; generated C is never committed. Wheels built this way also run with numpy 1.x. `make rebuild-ext` rebuilds it in the development environment after edits to `.pyx`, `.pxi`, `.pxd` or `.h` files.

## Tests

- Tests mirror `src/`: `tests/test_wordvectors.py` tests `src/fse/_wordvectors.py`, `tests/test_container_npy.py` tests `src/fse/_container/_npy.py`. A long test module splits by topic into `test_<module>_<topic>.py`, such as `tests/test_conformance_steps.py`.
- Test modules never import each other. What several share (the conformance backends, word vectors and edits of saved files, container tensors) lives in `tests/support/`, which pytest puts on the path (`pythonpath`).
- Tests write files only into `tmp_path`; `tests/test_data` is read-only input.
- Expected values never depend on vocabulary positions, because gensim versions order words with equal counts differently. Derive them from `key_to_index`.
- Tests that download from the Hugging Face Hub are marked `network`.
- pytest treats warnings as errors. Narrow, commented ignores are allowed only for third-party warnings.
- gensim does not build on Python 3.14 and newer yet; the tests of `fse.gensim` are skipped there, everything else runs.

## 2.0 design

This section is binding for every 2.0 module.

### Principle and stages

A frozen encoder is a pure function from one sentence to one finished row. Every row is computed in five stages, all inside the worker that owns the sentence:

| Stage | What | Where | Owned by |
|---|---|---|---|
| 1 tokenize | split the text into token spans | CPU | the Source |
| 2 token rows and factors | look up vocabulary ids, hash FastText ngrams; the factor of each row is 1 for a word of the finished table (times its int8 scale), `oov_weight` shared by the ngrams of an unknown FastText word | CPU for ids and ngrams, the backend kernel applies the factor | Source (ids), Encoder (factors) |
| 3 aggregation | combine the weighted rows of a sentence into one row | backend | an `Aggregation` |
| 4 postprocessing | `normalize@1` or nothing | backend | the Encoder's steps |
| 4b head (optional) | a linear head `z = A x + b` and its outputs (logits, probabilities, labels); folded into the table for a head on raw means | backend (`logits`, `outputs`) | a Classifier or Regressor |
| 5 store | quantize per row and write | backend `store`, in the worker; then the Sink | the Sink |

The tokenizer is part of the encoder contract: the manifest names it with an identifier like the aggregation (`fse.tokenizer`), and reading an encoder with an unknown tokenizer raises. `external` means the tokens were given by the caller, who then owns reproducing them; `fse_words@1` is the native tokenizer specified under *Tokenizers*. A text Source runs stages 1 and 2 in one native pass without the GIL.

There are no Python hooks per row: they would hold the GIL, could not run on a device, could not be saved and would break bit-identity. Two escape hatches remain: own tokenization in Python inside the Source (stage 1, once per sentence, slower), and own processing of the finished output arrays. Models in which a row depends on more than its own sentence (attention over neighbors, sentence pairs) are out of scope.

Three rules keep new models possible without a new layer:

1. **An aggregation is not a sum.** It is defined by an initial accumulator, a combine step `combine(acc, f, x)` per weighted token row, a finish step `finish(acc, n)`, the result of an empty sentence and its output dimension. There is no group mode (many sentences to one row, as `CIndexedList` with repeated indices in 1.x): a document is encoded as one text, a mean over all its tokens, and a mean of equally weighted sentences is a reduction of their rows (`np.add.reduceat` over the group starts, then normalize), also over the batches of a stream; the migration guide shows both. It only adds, so it can come in a later 2.x if it is asked for.
2. **Factors (stage 2) are separate from the aggregation (stage 3).** Stage 2 supplies a factor and a stored row per contribution; the aggregation never sees weights or scales. A finished table has the factor 1 for every word, internally a ones array, so the kernels keep their arithmetic; removing that array from the kernel is a later optimization of its own, measured and compared bit for bit.
3. **The output dimension belongs to the encoder.** The aggregation gives the dimension of its rows (`Aggregation.output_dim(d)`: d for the weighted mean; a concatenation such as SWEM would give 2d), and `normalize` keeps it. The result is written into the manifest, and Sinks and Store read it from there, never from the word vectors. A head changes the dimension of its outputs (k instead of d): its rows are no encoder rows, so it is no step of the encoder but stage 4b of a model of its own, with its own targets and terms in the window (section "Runtime").

**Finished tables.** The weighted mean is linear: word weights, the removal of components and a projection (SIF, uSIF, PCA) applied to every word and ngram row before averaging give the same rows, within float32 rounding, as applied to every averaged row. A model therefore holds them in its table, made offline (the SIF and uSIF notebook with the 1.1.0 recipe), and encoding only averages; `normalize` is not linear and stays a step per row. Two promises are kept apart: a finished table gives, on every CPU backend, the bits of the reference applied to that table; how close it is to the model it was made from (rounding of the fold, quantization of float16 and int8 tables after it, the normalization rule of another library, such as the small value Model2Vec adds to the norm) is checked when the table is made, not by fse. `normalize` scales a row that a removal nearly cancels up to unit length, so for such rows the residues of rounding or quantization decide the direction. Heads: a head `A x` on the mean folds into the table, `A x + b` folds `A` and adds `b` separately (an empty sentence still gives `b`), and a head trained on normalized means runs as `A normalize(x) + b` on the full mean, a fused execution of the same algebra, never a different normalization; `normalize(A x)` is not `A normalize(x)`.

### Numerical contract (`transform_version` 2)

`fse._contract` holds the identifiers and versions, `fse._reference` the numpy reference that computes every rule below bit for bit; it is the oracle for every CPU backend (device backends follow the tolerance contract below), and tests compare by bit pattern (`view(np.uint32)`), because `array_equal` treats -0.0 and +0.0 as equal.

- **Arithmetic.** IEEE-754 float32 with round to nearest even and subnormals kept (no flush to zero). `fma(a, b, c)` rounds once. Native code calls `fmaf` or FMA intrinsics explicitly and is built without other contractions (`-ffp-contract=off`). Division and square root are correctly rounded; no reciprocal approximations or fast math.
- **Stage 2.** A known word w contributes the stored row `x` (float32 as is, float16 widened exactly, int8 codes converted exactly) with the factor `f = weight[w]` (1 for every word of a finished table), or `f = weight[w] * scale[w]` with one rounding for int8. An unknown FastText word with m >= 1 ngram buckets (in the order of the hashing, capped at `max_ngrams`) contributes each ngram row with `g = (1/m) * oov_weight`, each product rounded, times the ngram scale for int8; with m = 0 it counts for the length and adds nothing. Without FastText, unknown words are no tokens. The scale of int8 rows always goes into the factor, never into the row.
- **`weighted_mean@1`.** The accumulator starts at +0.0 per value; every contribution does `acc[i] = fma(f, x[i], acc[i])` in token order (ngrams in bucket order); `n` counts the tokens. The row is `(1/n) * acc` with `1/n` rounded first, not `acc / n`. An empty sentence is the zero row; there is no EPS.
- **`dot16`**, the dot product of every row reduction: 16 partial sums start at +0.0; index i goes into lane `i % 16` by fma in index order; the lanes are then added 8, 4, 2 and 1 lanes apart, and lane 0 is the result. It vectorizes on NEON, AVX2, AVX-512 and Metal. A lane can hold -0.0 (a product that rounds to zero keeps its sign), so implementations must not pad the reduction with zeros: a tail shorter than a vector updates only its own lanes.
- **`normalize@1`**: `s = dot16(row, row)`; an all-zero row stays zero; a nonzero row whose `s` underflows to 0 or overflows raises; otherwise every value is multiplied by `1 / sqrt(s)`.
- **Step lists.** None, or `normalize` once; anything else is rejected when an encoder is built or loaded. After stage 4 every row must be finite, otherwise the row id is reported.
- **Stage 5, storage.** float32 as is; float16 rounds to nearest even and raises beyond +-65504; int8 is symmetric per row: `s = absmax / 127` in float32, stepped down once with `nextafter` if `127 * s` overflows, `code = clip(rint(x / s), -127, 127)`; a row whose scale is 0 (a zero row, or one whose largest value divided by 127 underflows) has codes 0. Reading gives `code * s` with one rounding. These are the 1.x rules (`fse.models._quantize` in 1.1.0), which `fse._codes` and the reference reproduce bit for bit.
- **Reading stored rows.** The inverse norm of a stored row is `float32(1 / sqrt(s))`, where s is the sum of the squares of the stored values (int8 codes without their scale) in float64 and index order; a zero row has 0. A linear `score(w, bias)` of a row is `dot16(stored, w) * scale + bias` (scale 1 for float32 and float16). A cosine search normalizes the query by `normalize@1` (a zero query, or one whose norm underflows or overflows, raises) and scores `dot16(stored, q) * inverse norm`; the scale cancels and is not used. A score, inverse norm or cosine beyond float32 raises; top-k ties go to the smaller row id.
- **`linear@1`**, a head of k rows `a_j` and biases `b_j` (float32) on the pooled rows r of an encoder: *folded* (a head on raw means: `predict`, `predict_proba`, `decision_function` and standalone files) through the folded table `t[w, j] = score(stored_w, scale_w, a_j, 0)` of every word and ngram row (the int8 scale is in it; the factors are those of a float32 table, 1 per word and `(1/m) * oov_weight` per ngram), `z_j = weighted_mean@1(t)_j + b_j`, the bias added once after pooling; *normalized*: `z_j = dot16(normalize@1(r), a_j) + b_j`, every error of `normalize@1` kept; *unfolded* (`return_vectors=True`, and store mode): `z_j = dot16(r', a_j) + b_j`, r' the raw or normalized row by the head's flag, on a store `score(stored, scale, a_j, b_j)` of the stored rows. An empty sentence gives `z = b` on every path; a logit that is not finite raises with its row. Labels: for k = 1 `labels[1]` if `z > 0`, else `labels[0]` (scikit-learn's rule; -0.0 and 0.0 give `labels[0]`); for k >= 2 the first largest logit.
- **`exp@1`**, for x <= 0: below -104 it is +0.0; else `k = rint(x * log2e)` (to nearest even), `r = fma(-k, ln2_hi, x)`, `r = fma(-k, ln2_lo, r)`, `p` the polynomial of degree 7 in r by Horner with fused multiply-adds from `c_7` down, and `(p * 2**(k + 64)) * 2**-64`: the first product is exact, the second rounds once, also into the subnormal range. Constants (float32): log2e `0x1.715476p+0`, ln2_hi `0x1.62e430p-1`, ln2_lo `-0x1.05c610p-29`, `c_0 = c_1 = 1`, `c_2 = 0x1p-1`, `c_3 = 0x1.555556p-3`, `c_4 = 0x1.555556p-5`, `c_5 = 0x1.111112p-7`, `c_6 = 0x1.6c16c2p-10`, `c_7 = 0x1.a01a02p-13` (1/i! rounded). The contract promises 2 ulps against exp; over all 1,120,927,745 float32 inputs from -0.0 to -104 it is within 0.9371 ulp (`tools/check_exp.py`). Libraries' exp functions are not bit-identical across platforms, which is why the links use this one.
- **Links**, on finished logits, never adding the bias: `sigmoid@1`, with `e = exp@1(-|z|)`, is `1 / (1 + e)` for z >= 0 (-0.0 included) and `e / (1 + e)` else, and gives `[1 - p, p]` for one logit; `softmax@1` is `e_j / s` with `e_j = exp@1(z_j - max)` and s their sum in index order from +0.0, and of one logit z it is the softmax of `[-z, z]` (scikit-learn's binary multinomial model, whose decision is the one logit); `ovr@1` divides the `sigmoid@1` of every logit by their sum in index order, and a row whose sum is 0 is `1/k` everywhere (scikit-learn's one-vs-rest rule). A lookup table of the sigmoid would be an identifier of its own, made only if a profile shows the link.

What is bit-identical across what:

| Across | Guarantee |
|---|---|
| worker counts, job and batch sizes, input classes with the same tokens, shards, restarts | bit-identical: every row is a pure function of its sentence |
| CPU instruction sets and operating systems (portable, NEON, AVX2) | bit-identical, through explicit fma and `dot16` |
| the numpy reference and every CPU backend | bit-identical for every profile the conformance suite checks |
| CPU and a device backend (MLX, later CUDA) | within the tolerance contract (below); bit-identical run to run on one device and version |
| each path of a linear head (folded, normalized, unfolded, standalone, store mode) and its reference | bit-identical on every CPU backend; a standalone file gives the bits of its complete model |
| the folded and the unfolded path of a head on raw means (`predict` against `return_vectors=True` or a float32 store) | within the rounding of the fold, not bit-identical: folding changes the order of the roundings, so about half the logits differ in their last bits (maintainer decision); a head on normalized means has one path, so its store mode gives the bits of its texts |
| a head in fse and in scikit-learn | within the bound of `tests/support/head_bound.py` (the rounding of A and b, dot16, the fold, the pooling, the bias, in float64 per row); a label differs only where the top two logits are within their bounds, a probability by at most the bound through the link (`|dz| / 4` for sigmoid, `max |dz| / 2` for softmax) plus 8 u (sigmoid) or (k + 8) u (softmax) for the link's own roundings |
| 1.x and 2.0 | not identical (EPS, `saxpy`, BLAS in the removal); compared with tolerances, STS and MTEB |

### Tolerance contract of device backends

Decided by the maintainer on 29.10.2026: the CPU stays bit-identical to the reference, and every device backend (MLX, later CUDA) keeps a tolerance contract instead. No use of sentence vectors (regression, classification, approximate nearest neighbours, clustering) needs the last bit; what the bits buy is a test oracle and reproducibility, which the CPU keeps. Measured before the decision (M1 Pro, pooling alone, 8M tokens): a free summation order makes the CPU no faster (it is bound by reading the rows), while the exact subnormal checks of the MLX kernel took about 40 % of its time and most of its design.

- **Scope.** The work a device backend does on its device. An operation it leaves to its host (the cpu backend) is bit-identical to the cpu operation on the same input arrays; that is not bit identity with a cpu run end to end, whose pooled rows differ.
- **Kept exactly.** Shapes, dtypes and row order; the zero row (+0.0) of an empty sentence; which inputs are rejected; and every error of the whole operation as on the cpu backend, in the same order: overflow while pooling, the errors of the steps (such as a row whose norm underflows in `normalize@1`) and the range of the storage dtype. A device detects, conservatively, every row that could give another error or another success than the cpu row (a nonfinite accumulator, a zero row where the cpu row may be nonzero, values near an overflow or underflow limit of a step) and computes it again on the host from the original inputs. The choice of these rows is deterministic per row and independent of its neighbours, task boundaries and device grouping: the host may compute a whole task again (to raise the cpu error in its order), but on success only the chosen rows take the host's rows, and every other row keeps its device result. Before `normalize@1` this includes every row that is all zero on either side while its sentence is not empty, and, as an additional conservative fallback, every row whose squared norm on the device is below 2**-100 (a test of the device's own rows, once per row). The threshold does not replace the bound below: `2 E / r` uses the norm of the cpu row.
- **Determinism.** On a fixed device, driver and fse version, a device backend gives the same bits on every run, with every worker count, task and group size, input class with the same tokens, and after a restart (no atomics or reductions whose order varies).
- **Arithmetic.** Accumulators are float32 or wider. In pooling the order of the additions and whether products are fused are free, because the bound below holds for any order; a device that keeps the cpu's order (token order, ngrams in bucket order) and fused multiply-adds is in practice much closer than the bound. It may flush subnormal values to zero within the bound. Subnormal inputs and factors are checked once, when the encoder is prepared for the device, with the cpu's arithmetic: if a weight, an int8 or ngram scale, `oov_weight` or a value of a stored row is subnormal, or a stage-2 factor or its intermediate could be (`weight * scale` of every word; for FastText `(1/m) * oov_weight` for every m up to `max_ngrams`, and that times every ngram scale for int8), that encoder runs on the host for that backend (a fallback of its own); a flushed factor times a large value is not covered by the absolute term. A product or partial sum that underflows or flushes in pooling, after the factors are made, loses less than 2**-125 per contribution; with the rounding of every operation, which a flushed value can turn the other way later, this is covered by the bound below, which holds for any implementation of the sum, so the device needs no check per operation (decided by the maintainer on 29.10.2026). A device may use its own division and square root.
- **Bound.** A bound that holds for every float32 implementation of the pooling sum with the cpu's factors, and that the conformance suites check: per row `||g - c|| <= (τ + 2 γ_K) m + δ` with `τ = 1e-5`, `γ_K = K u / (1 - K u)`, u = 2**-24, and `δ = 2**-125 K sqrt(d)` (Euclidean norms; g the row of the device, c the row of the cpu backend, K the contributions of the sentence (its tokens plus its ngram buckets), d its number of values). Both rows are float32 sums of the same K contributions, each within `γ_K m` of the exact sum whatever the order of the additions, whether products are fused and however a flushed value turns later roundings (the classical bound of a sum, valid with K u < 1), and δ bounds the absolute errors of underflow and flushing on the way; so the bound holds for any device whose stage-2 factors, with every intermediate rounding (`weight * scale`, `1/m`, `(1/m) * oov_weight`, times the ngram scale), are bit-identical to the cpu's: a device's own division must give the same `1/m`, and the prepare check, which excludes subnormal inputs and factors, does not make factors identical by itself. τ leaves room for the final `1/n`, which both sides round once. `2 γ_K` is below τ for sentences of up to 80 contributions and grows with longer ones (about 1.2e-4 at 1,024, 0.12 at 2**20), as the error of a float32 sum against the exact value does. A device computes a sentence only with K < 2**24 and d <= 65,536, so δ is at most 2**-93 (about 1e-28); a larger sentence uses the host on its own, independent of its neighbours, and tasks are split between sentences without changing another sentence's fallback. For `weighted_mean@1`, m is the norm of `(1/n) Σ |f| |x|`, computed in float64 from the cpu's factors (`weight`, `weight * scale`, `(1/m) * oov_weight` and the ngram scales) and the stored rows widened exactly, with every ngram bucket a contribution of its own and n the number of tokens. An empty sentence (n = 0) must give the exact +0.0 row; m is not evaluated for it. After `normalize@1`, for rows that are nonzero on both sides, the bound is `2 E / r`, with E = `(τ + 2 γ_K) m + δ` the bound after pooling, plus the rounding bounds of both normalizations (the dot product, square root, reciprocal and products), r the norm of the cpu row before it; rows that are zero on either side, or whose squared norm could be subnormal, take the cpu rows (above). Rows for which the suite cannot establish such a bound are computed by the host.
- **Stored output.** Stage 5 applies `quantize_rows@1` exactly to the device's own float32 rows: its codes and scales are bit-identical to the cpu quantization of those rows. No bound on codes against the cpu's rows follows (after a cancellation a code may differ by any amount within one scale).
- **Search on a device** is not specified yet and runs on the host. Before it moves, it needs its own bounds for cosines (on normalized operands) and scores, and two rows may change places only where the cpu gap between them is at most the sum of their bounds. `mode="exact"` is reference-identical on the cpu backend.
- **Tests.** The conformance suites run a device backend on every case of the bit-identical suites and on cases made against it: long sentences and many ngrams, an overflow that depends on the order, a cancellation before `normalize@1`, subnormal factors, products and partial sums, normal inputs whose derived factors become subnormal and are then multiplied by a large scale or value, and a flushed early partial sum that turns a later rounding and is amplified by the contributions after it (without steps), and sentences of 2**24 - 1 and 2**24 contributions. They compute the bound stage by stage, require a launch on the device for every case that does not fall back by design (a backend that computes everything on its host fails), and compare the bits across repeated runs, fresh processes, worker counts, task sizes, device group sizes and input classes with the same tokens, including tasks that mix a row that falls back with rows that do not, in one task or group and in separate ones. Meta-tests run a witness case per mistake and show that the suite fails for a device that drops or repeats a token, divides by the wrong count, skips `1/n`, swaps rows, accumulates in float16, runs an encoder with subnormal inputs instead of handing it to the host, skips the check before `normalize@1`, or misses the bound by a factor of 10.
- **Versions.** A change of the CPU-defined arithmetic bumps the version of its operation; a change of a device implementation within the unchanged contract does not. Only the maintainer changes the contract (τ or these rules), recorded here with its date.

### Identifiers and versions

Aggregations, steps and tokenizers are written `"<name>@<version>"` (name `[a-z][a-z0-9_]*`, version a decimal integer without leading zeros), for example `weighted_mean@1`, `normalize@1`, `fse_words@1`. `transform_version` versions the shared rules above, the identifier versions the rules of one operation. Any change of the arithmetic the CPU defines bumps the matching version (a device implementation within the tolerance contract does not); from the first 2.0 release on, an identifier is never removed or given another meaning within 2.x. Before it, identifiers that are no longer needed are removed, not reserved (maintainer decision of 29.10.2026): `remove_components@1` and `project@1` went with fit, and an artifact that names them is refused like any unknown one. Reading an artifact with an unknown name, version or `transform_version`, or a disallowed step list, raises `UnsupportedArtifactError` (a `ValueError`) that names the supported ones; nothing is skipped.

### Batch

A `Batch` is the input of an aggregation: `first_row` (the row of its first sentence), `offsets` (int64, n + 1 entries, from 0 to the number of tokens), `tokens` (uint32 vocabulary ids, or `OOV_TOKEN` for an unknown FastText word) and, for FastText, `ngram_offsets` and `ngrams` (uint32 buckets, one range per unknown word, in order). Sentence s is row `first_row + s`. Weights are not part of a batch, so a Source does not depend on the encoder; 2.1 adds token ids from Arrow and `TokenIds` as further Sources of the same batches.

### Tokenizers

The manifest key `fse.tokenizer` holds `external` or the identifier of a native tokenizer; reading anything else raises `UnsupportedArtifactError` naming the supported ones (`fse._contract.check_tokenizer`). A tokenizer is part of the encoder contract like its aggregation: any change of its rules, its tables or its Unicode version is a new identifier. `fse._reference_text` defines the tokens of every tokenizer, and the native code gives the same bytes.

- `external`: the caller gives the tokens. Text input is split at the whitespace W below, as `str.split()` does, and the tokens are not changed.
- `fse_words@1`: the native tokenizer specified here.
- `wordpiece@1`: the WordPiece tokenizer of BERT vocabularies (POTION/Model2Vec, the static models of sentence-transformers), specified below; its parameters are data of the model.
- `unigram@1`: the Unigram tokenizer of SentencePiece vocabularies as Hugging Face tokenizers runs it (potion-multilingual-128M), specified below; its parameters, float64 scores and charsmap are data of the model.

**Input.** One sentence is a `str` that UTF-8 can encode (a lone surrogate raises), or one line of a UTF-8 file: a line ends at the byte `\n`, which is not part of it; the last line needs no `\n`, a final `\n` starts no empty line, and an empty file has no lines. A file must not start with a UTF-8 byte order mark, which would otherwise stick to the first token as U+FEFF; it raises. Bytes are decoded strictly, as CPython's UTF-8 decoder does, and invalid UTF-8 raises. Sentences are not split further and not normalized: NFC and NFD spellings stay different.

**Output.** A list of non-empty tokens, matched to the vocabulary by the exact equality of their UTF-8 bytes. `fse_words@1` computes it in five steps.

1. **Lowercase.** Every code point is replaced by its simple lowercase mapping (field 13 of `UnicodeData.txt` of Unicode 15.1.0, from the checked-in table `fse._unicode`); code points without a mapping stay. There is no SpecialCasing and no context: U+0130 becomes `i`, and Σ always becomes σ.
2. **Classes** of the lowercased code points:
   - whitespace W: U+0009 to U+000D, U+001C to U+0020, U+0085, U+00A0, U+1680, U+2000 to U+200A, U+2028, U+2029, U+202F, U+205F, U+3000;
   - separators S: ``! " # $ % & ( ) * ; < > ? @ [ ] ` { }`` and U+00AB, U+00BB, U+2012 to U+2015, U+2018, U+2019, U+201C, U+201D, U+201E;
   - token characters: every other code point, subject to step 3;
   - word characters: `a` to `z`, `0` to `9`, `_`, and every code point from U+0080 that is in neither W nor S;
   - digits: `0` to `9`.
3. **Context.** Applied from left to right; t(i) says whether s[i] is a token character.
   - A `.` directly before or after another `.` is not a token character; the same holds for `-`.
   - A `,` or `:` is a token character exactly if the next code point is a digit.
   - A `'` directly before or after another `'` is not a token character. Otherwise it is not one if i > 0, t(i-1) holds, s[i-1] is not a word character, and s[i+1] exists and is a word character.
4. **Spans.** Every maximal run of token characters is a candidate u.
5. **Per candidate u.** Strip `.` and `:` from both ends. Split u into parts by the first rule that applies:
   - the table: `cannot` to can, not; `gimme` to gim, me; `gonna` to gon, na; `gotta` to got, ta; `lemme` to lem, me; `wanna` to wan, na; `more'n` to more, n; `d'ye` to d, ye; `'tis` to t, is; `'twas` to t, was;
   - u is `n't`: the part `not`;
   - u ends with `n't` after a non-empty rest that does not end with `'`: the rest and `not`;
   - u ends with the first matching one of `'s`, `'m`, `'d`, `'ll`, `'re`, `'ve` after a non-empty rest that does not end with `'`: the rest and the clitic without `'`;
   - otherwise u itself.

   From every part, strip `.`, `:` and `'` from both ends; drop it if it holds no `a` to `z` and no `0` to `9`; otherwise split it at every `-` and emit the non-empty pieces in order.

Apart from W, S, the lowercase table and the word characters from U+0080, every rule refers to ASCII only, so an implementation may apply them to UTF-8 bytes.

**Stage 2** of `fse_words@1` and `external`: a token whose bytes are a vocabulary word becomes its id. Otherwise, with FastText it becomes `OOV_TOKEN` with the first `max_ngrams` `fasttext@1` buckets of `<token>` (possibly none, which still counts for the length); without FastText it is no token.

| Input | `fse_words@1` |
|---|---|
| `I don't know.` | i, do, not, know |
| `Can't, won't` | ca, not, wo, not |
| `'Tis` | t, is |
| `O'Reilly's` | o'reilly, s |
| `James' book` | james, book |
| `rock'n'roll` / `rock’n’roll` | rock'n'roll / rock, n, roll |
| `x='abc'` | x=, abc |

#### wordpiece@1

`wordpiece@1` gives the ids that Hugging Face tokenizers 0.23.3 gives for a `tokenizer.json` with a `BertNormalizer` (all four flags on), a `BertPreTokenizer` and a `WordPiece` model, whose added tokens are matched on the raw text (`normalized: false`, without `lstrip`, `rstrip` and `single_word`), encoded without special tokens (`add_special_tokens=False`), as model2vec and sentence-transformers call it. The rules are reimplemented from the source of tokenizers at tag v0.23.3 (`tokenizer/added_vocabulary.rs`, `normalizers/bert.rs`, `pre_tokenizers/bert.rs`, `models/wordpiece/mod.rs`) and from the Unicode data; no code is copied. Its parameters are data of the model, in `fse.tokenizer_config` (encoder 1), all required and no others:

| Parameter | Meaning |
|---|---|
| `added_tokens` | `[[id, content], ...]`, sorted by id: the tokens matched on the raw text; each content is the vocabulary string of its id, non-empty and unique |
| `unk_id` | the id of a word WordPiece cannot split |
| `continuing_subword_prefix` | the prefix of every piece of a word after its first, non-empty (`##`) |
| `max_input_chars_per_word` | a word of more code points is `unk_id` (100), at least 1 |
| `clean_text`, `handle_chinese_chars`, `strip_accents`, `lowercase` | the flags of the normalizer; this fse supports only all four true (every target model), so another value raises `UnsupportedArtifactError` |

Every id is an int (not a bool) with `0 <= id < n`, n the number of tokens. The encoder adds `fse.unknown` (`drop`: `unk_id` adds nothing and does not count in n, as model2vec; `keep`: it is a row like any other, as sentence-transformers), and optionally `fse.max_tokens` and `fse.max_chars`, the length rule of the format the model came from (model2vec: 512 tokens and 512 times the median token length in code points).

Input as for `fse_words@1`. Per sentence:

1. **Character cut.** With `fse.max_chars`, keep the first `max_chars` code points. The whole sentence is still decoded: invalid UTF-8 after the cut raises.
2. **Added tokens.** Split the text at the added tokens, leftmost-longest over the raw code points: at the first position where an added token starts, the longest one starting there is taken and gives its id; the search goes on after it. Each piece between them goes through steps 3 to 5 on its own.
3. **Normalize** a piece:
   1. remove U+0000, U+FFFD and every code point of general category Cc, Cf or Co in Unicode 8.0.0 except U+0009, U+000A and U+000D; then replace U+0009, U+000A, U+000D and every code point with the property White_Space of Unicode 17.0.0 by U+0020;
   2. put U+0020 before and after every code point in U+4E00 to U+9FFF, U+3400 to U+4DBF, U+20000 to U+2A6DF, U+2A700 to U+2B73F, U+2B740 to U+2B81F, U+2B920 to U+2CEAF, U+F900 to U+FAFF and U+2F800 to U+2FA1F (fixed ranges, not Unicode data);
   3. NFD of Unicode 9.0.0 over the whole piece: the full canonical decomposition (Hangul syllables by the algorithm of the standard), then canonical ordering: every maximal run of code points with a nonzero canonical combining class (9.0.0) is sorted stably by class;
   4. remove every code point of category Mn in Unicode 8.0.0. This follows step 3, so a removed mark of class 0 (U+034F COMBINING GRAPHEME JOINER) has ended a run, and the marks on either side of it were not reordered across it;
   5. replace every code point by its full lowercase mapping of Unicode 17.0.0: field 13 of `UnicodeData.txt`, replaced by the unconditional entries of `SpecialCasing.txt` (U+0130 becomes `i` U+0307), without context (Σ always becomes σ).
4. **Pre-tokenize.** Split at White_Space (17.0.0), which is removed; every ASCII punctuation character (`!` to `/`, `:` to `@`, `[` to `` ` ``, `{` to `~`) and every code point of category Pc, Pd, Ps, Pe, Pi, Pf or Po in Unicode 8.0.0 is a word of its own.
5. **WordPiece** per word. A word of more than `max_input_chars_per_word` code points is `unk_id`. Otherwise the word is split from the left: the longest prefix of the rest that is a token (a piece after the first with `continuing_subword_prefix` in front), shortened one code point at a time, is the next id; if no prefix is a token at some point, the whole word is one `unk_id`.
6. **Token cut and unknown tokens.** With `fse.max_tokens`, keep the first `max_tokens` ids of the whole sequence of steps 2 to 5 (added tokens and `unk_id` count). Every word is split whole before the cut, so a word whose split fails after the cut is one `unk_id` (vocabulary `[UNK]`, `a`, text `ab`, one token: `[UNK]`, not `a`). Then `fse.unknown=drop` removes every `unk_id`.

Golden ids (`tests/test_data/v2/wordpiece.json`, written by tokenizers 0.23.3 with a small vocabulary that holds the letters, digits and their continuation pieces; shown as tokens):

**Stage 2** of `wordpiece@1`: token id i is row i. The vocabulary of the table (`vocab.bytes`, `vocab.offsets`) holds the token strings in id order, continuation pieces with their prefix, so every id from 0 to n - 1 exists and the checks of word_vectors 1 cover the tokens.

The rules mix three Unicode versions, those of the libraries tokenizers 0.23.3 is built with:

| Rule | In tokenizers 0.23.3 | Unicode |
|---|---|---|
| Cc, Cf (clean), Mn (accents), P* (punctuation) | crate `unicode_categories` 0.1.1 | 8.0.0; Co by fixed ranges, unassigned code points are kept |
| decomposition and combining classes | crate `unicode-normalization-alignments` 0.1.12 | 9.0.0 |
| lowercase, White_Space | the Rust standard library that built the wheel | 17.0.0 |

So a code point that became Mn, Cf or P* after 8.0.0 is kept, and the 83 code points with a nonzero class in 9.0.0 that are not Mn in 8.0.0 survive and are reordered. A tokenizers wheel built with another Rust lowercases some rare code points differently; `wordpiece@1` stays fixed to these tables, and any change is a new identifier. `tools/make_wordpiece_tables.py` reads the five UCD files (pinned by sha256) and writes `fse._unicode_bert`, the data for the reference `fse._reference_wordpiece`, and `_native_unicode_bert.h`, the same composed per code point for the native code (steps 3.1 to 3.5 of one code point, with its combining class; only the ordering of runs is computed per piece).

#### unigram@1

`unigram@1` gives the ids that Hugging Face tokenizers 0.23.3 gives for a `tokenizer.json` with a `Unigram` model, a normalizer made of the steps below, a `Metaspace` pre-tokenizer and added tokens matched on the raw text, encoded without special tokens (the tokenizer of minishlab/potion-multilingual-128M). The rules are reimplemented from tokenizers at tag v0.23.3 (`models/unigram/model.rs`, `normalizers/precompiled.rs`, `normalizers/replace.rs`, `normalizers/strip.rs`, `pre_tokenizers/metaspace.rs`), from the crates its Cargo.lock pins (spm_precompiled 0.1.4 for the charsmap, unicode-segmentation 1.13.3 for graphemes, Oniguruma through onig 6.5.3 for the regexes) and from the Unicode data; no code is copied. `fse._reference_unigram` defines the ids, and the native tokenizer (`_native_unigram.h`, `_native_unigram.pxi`, `_native_unigram_steps.pxi`) gives the same without the GIL: the graphemes from the table `_native_unicode_graphemes.h`, the bounds-checked search of the charsmap, every step through a growing buffer that checks each write, the candidates of a start by one lookup of the pieces and one of their proper prefixes per code point (VocabTables; a trie is PR 12e), and the Viterbi in binary64 (checked when compiled: no extended precision) only in functions never inlined, inside the floating-point environment of the kernels, so a thread with another rounding mode gets the same ids. An encoder holds the parameters in `fse.tokenizer_config`, the scores in the F64 tensor `tokenizer.scores` and the charsmap verbatim in the U8 tensor `tokenizer.charsmap` (encoder 1).

Its parameters are data of the model: the added tokens and `unk_id` as for `wordpiece@1`; `byte_fallback`, which must be false; `normalizer`, a list of steps; `metaspace`, the replacement (`▁`, U+2581), the prepend scheme (`always`) and `split` (false), the only values this fse supports. The score of every piece is a float64 (tokenizers parses and sums them in float64), and the charsmap of a `precompiled` step is the decoded blob of the file, kept as it is. Only these forms are read; any other normalizer, regex, pre-tokenizer value, `byte_fallback: true` or `unk_id: null` raises `UnsupportedArtifactError` naming it.

Input as for `fse_words@1`. Per sentence:

1. **Character cut** and 2. **added tokens** as steps 1 and 2 of `wordpiece@1`. Every piece between added tokens goes through steps 3 to 5 on its own; an empty piece gives no id.
3. **Normalize** the piece by its steps, in order:
   - `precompiled`: cut the piece into extended grapheme clusters by UAX #29 of Unicode 17.0.0 (Grapheme_Cluster_Break, Extended_Pictographic and InCB of 17.0.0; rules GB3 to GB13 and GB999, with GB9c). A grapheme of fewer than 6 UTF-8 bytes is searched in the charsmap with its bytes: if any key is a prefix of it, the **shortest** such key wins and the whole grapheme becomes that key's value, so the rest of the grapheme is dropped (`Ａ` U+0301 becomes `A`). Otherwise every code point of the grapheme is searched alone and becomes its key's value, or stays. This is tokenizers' rule, not SentencePiece's (which takes the longest match over the text, without graphemes).
   - `replace`: every occurrence of a non-empty `pattern` becomes `content`, left to right without overlap (tokenizers' `Replace` with a `String` pattern).
   - `runs`: every maximal run of at least `min` code points of a class becomes `content`; the class `space` is U+0020 (the regex ` {2,}` is `min` 2), the class `white_space` is White_Space of Unicode 17.0.0 (the regex `\s+` is `min` 1: Oniguruma's `\s` matches exactly these 25 code points).
   - `strip`: leading and trailing White_Space code points (17.0.0) are removed.
4. **Metaspace.** Every U+0020 becomes the replacement, which is put in front of the piece unless it starts with it; the piece stays one pre-token.
5. **Unigram** on the UTF-8 bytes `b` of the pre-token, n bytes. `unk_score = min(scores) - 10.0` and every sum below are float64, round to nearest. `best[0] = 0.0`. For each code point boundary s from 0 up, with m the length of the code point at s: every piece that is a prefix of `b[s:]`, by increasing length, offers `score + best[s]` for its end; it is taken if that end holds nothing yet or the offer is strictly greater. If no piece is exactly the m bytes at s, `unk_score + best[s]` is offered for s + m in the same way, with the id `unk_id`. So a tie goes to the earliest start. Going back from n, consecutive nodes whose id is `unk_id` (unknown code points, and a piece that has that id) are joined into one string, and every string is the id of the piece it equals, else `unk_id`.
6. **Token cut and unknown tokens** as step 6 of `wordpiece@1`: every pre-token is tokenized whole, then the first `max_tokens` ids are kept and `fse.unknown=drop` removes every `unk_id`.

**The charsmap** (the blob of spm_precompiled 0.1.4, SentencePiece's double array): a little-endian u32 `size`, `size / 4` little-endian u32 units, then the values as UTF-8 strings, each ended by NUL. A unit u has `leaf = (u >> 8) & 1`, `label = u & (2**31 | 255)`, `offset = (u >> 10) << ((u & 512) >> 6)` and `value = u & (2**31 - 1)`. The search starts at `p = offset(a[0])` and takes the bytes of the key in turn, ending at a byte 0: `p ^= c`, it ends unless `label(a[p]) == c`, then `p ^= offset(a[p])`, and if that unit had `leaf`, `value(a[p])` is the offset of a match in the values, whose string runs to the next NUL or the end of the values. The keys are byte strings. A blob is checked completely when it is read, as tokenizers panics on a broken one: `size` a positive multiple of 4 within the blob, the values valid UTF-8, and every node reachable from the root (darts-clone shares the nodes of equal suffixes, so a node is checked once, and a cycle is refused) with every probe `p ^ c` inside the array and every value offset at most the length of the values and on a code point boundary.

| Input (potion-multilingual-128M) | `unigram@1` |
|---|---|
| `Hello, World!` | `▁Hello` `▁` `,` `▁World` `▁!` |
| `a[UNK]b` | `▁a` `[UNK]` `▁b` |
| `Ａ` U+0301 | `▁A` |
| `x` U+3000 `y` | `▁x` `▁y` |
| U+0000 `a` / `x` U+180E `y` | `▁` `[UNK]` `a` / `▁x` `[UNK]` `y` (no key, no White_Space) |
| `…` | `▁` `.` `▁` `.` `▁` `.` |

`tests/test_data/v2/unigram.json` holds such cases for small tokenizers written by tokenizers 0.23.3 (`make_unigram_golden.py`), including a tie (pieces `a`, `ab`, `bc`, `c` of score -1: `abc` is `a`, `bc`), joined unknowns that are a piece (scores above 20, so two unknown nodes beat the piece `xy`: `axya` is `a`, `xy`, `a`) and the case that needs float64 scores: `a` and `b` of score -1 and `ab` of `-2 - 2**-30` make `ab` `a`, `b`, while scores rounded to float32 tie and give `ab`. Scores rounded to float32 agree on a million texts for the target model, yet 16 of its Viterbi decisions on MASSIVE lie within one float32 rounding of a flip; float32 sums change 380 of those texts.

The Unicode data: `tools/make_grapheme_tables.py` reads `GraphemeBreakProperty.txt`, `emoji-data.txt`, `DerivedCoreProperties.txt` and `PropList.txt` of 17.0.0 (pinned by sha256) and writes `fse._unicode_graphemes`; `tests/test_data/GraphemeBreakTest-17.0.0.txt`, pinned the same way, holds the 766 cases of UAX #29 the segmentation passes. A tokenizers wheel with another unicode-segmentation, or a new form of Precompiled, can change ids; `unigram@1` stays fixed to these rules, and a change is a new identifier.

### Backends

A backend implements one contract (`fse._backends`) and is chosen by name from a fixed set (`"cpu"`, `"numpy"`, `"mlx"`, later `"cuda"`); there is no plugin registry and no `"auto"`:

- `prepare(pool, steps)`: once per encoder and backend, what it needs on that backend (the kernel's parameters, uploaded rows); `pool` holds the word rows, scales, weights (ones for a finished table) and FastText rows, `steps` the postprocessing steps (none or `normalize@1`).
- `rows(batch, prepared, out)`: stages 2 to 4 of one batch into `out`, the aggregation and then the postprocessing step on the rows of that batch, so every worker applies it to the finished rows of its own task. The cpu backend pools into `out` and normalizes there in place (`postprocess_pooled`: neither the copy nor the finiteness check of `postprocess`, as pooling raises for every row that is not finite). An error leaves part of `out` written: a task writes only its own target, and the runtime commits it only after the task succeeded, so a sink that keeps its targets to itself never publishes such rows. A device backend may fuse them.
- `score(stored, scales, weights, bias)`: the scores of stored rows.
- `inverse_norms(stored)`, `cosines(stored, inverse, queries)` and `scores(stored, scales, weights, bias)`: the search of the vector store on stored float32, float16 or int8 rows without a float32 copy: the inverse norm of every row, and the cosine with many queries or the linear score with many weight vectors as a (rows, vectors) array, column by column the rule of one vector. Every query is checked before any is used; errors name the query or weight vector and the row, in that order. The cpu backend computes them in the kernel (`_native_kernel_search.h`) in its own floating-point environment; the inverse norms of 8 rows at a time, each with its own float64 sum in index order, so the bits are those of one row at a time while the chains of dependent additions overlap (2.4 times as fast for float32, 3.2 times for int8 on an M1 Pro).
- `store(rows, codes, scales, first_row)`: stage 5 of finished float32 rows into float16 or int8 codes (and one scale per row for int8) by `quantize_rows@1`, in the worker that made them, so a compact storage dtype costs no work in the calling thread. It runs on the host, for the mlx backend too; a device backend may later fuse it with `rows`. The cpu backend stores each row in one pass in the kernel (`_native.store_rows`, in its own floating-point environment); within one call the first row that is not finite raises, else for float16 the first row beyond +-65504.
- `logits(rows, weights, bias, out, first_row)` and `outputs(logits, kind, link, out, first_row)`: stage 4b of `linear@1` on the host. `logits` scores float32 pooled rows with A and b (the rule of `score`), or adds b once to the pooled rows of a folded table, in place; `outputs` turns finished logits into the probabilities of a link or the label indices, adding no bias. Errors name the row from `first_row`. The cpu backend runs both in the kernel, the numpy backend in `fse._reference_head`.
- `capabilities()`: the word dtypes, aggregations, steps, FastText, the largest dimension, whether several threads may call `rows` at once (`concurrent`; otherwise the runtime runs one task at a time while encoding stays parallel), and whether it runs linear heads (`heads`; `check_heads` raises otherwise, before any input is read).

Arguments and outputs are host numpy arrays, checked the same way by every backend (shape, dtype, C order, writability, no overlap with the inputs). The kernels and the cpu backend set the floating-point environment of their thread themselves; the numpy backend is the oracle of the tests, not a production backend, and like `fse._reference` computes in the environment of its thread. Before reading any input, the runtime checks that the backend can run the encoder and raises otherwise, naming the backend and what it cannot run; it never falls back silently. The conformance suites run every backend through its contract and compare a CPU backend with the reference bit for bit, a device backend with the cpu backend under the tolerance contract, for every dtype, step list, FastText, source and worker count, including empty, long and unknown-word sentences and subnormal values; a new backend is done when it passes. accumulate and dot16 are kernel primitives, not contract operations, and are tested on the kernels directly.

### MLX

The mlx backend (`backend="mlx"`, `pip install "fse[mlx]"`, macOS 14 or newer on Apple silicon, MLX 0.32.4 or newer) runs stage 2, the weighted mean, and `normalize@1` in a Metal kernel, and everything else on its host, the cpu backend, which `get_backend` injects so that `_mlx` imports neither `_cpu` nor `_native`: stage 5 on the device's own rows, the inverse norms and the scores, with the bits of the cpu operation on the same input by construction. Where MLX, Metal or the platform is missing, making the backend raises `UnsupportedByBackendError` with the reason; it never falls back silently. Linear heads do not run on it yet (2.0 PR 13b): a model on `backend="mlx"` raises `UnsupportedByBackendError` before any input is read.

- **Contract.** The rows of the GPU keep the tolerance contract of device backends (the section "Tolerance contract of device backends" above, PRs #120 and #121): per row `||g - c|| <= (1e-5 + 2 γ_K) m + 2**-125 K sqrt(d)`, `γ_K = K u / (1 - K u)` with `u = 2**-24`, K the tokens and ngram buckets of the row and d its dimension, with shapes, empty rows, errors and their order as on the cpu backend. The kernel keeps the cpu's order of the contributions and its fused multiply-adds, so a row in which no flush meets a value has the cpu's bits (as for every row of the gate's data); a flush may turn later roundings (the term `2 γ_K`), so a row that meets one is only within the bound. The conformance suites compare the rows under the bound (`tests/support/bound.py`, computed from the cases independently of the backend), and bit for bit where no flush occurs.
- **Encoders on the device.** Every encoder (its step is none or `normalize`), except one with rows of more than 65,536 values (`dim`) or with subnormal inputs (`subnormal_input`, below), which runs on the host for this backend.
- **Kernel.** Four values per thread when the dimension is a multiple of four (float4, half4 or char4 loads, aligned because every row starts at a multiple of four values), else one; up to 256 threads of a threadgroup along a row (several groups along a longer one), the rest of the group in sentences. In token order with the ngram rows of an unknown word in bucket order: `acc = fma(factor, row[d], acc)`, then `(1 / n) * acc` with `1 / n` rounded first; the factors (`weight * scale`, `(1 / m) * oov_weight` times the ngram scale) are computed in the kernel as the cpu computes them, so no host thread that inherited flush-to-zero or another rounding computes them. Per row the kernel also sums `|f| ||x||` over the nonzero factors (one scalar fma per token, from the norms of the stored rows computed in float64 at prepare and rounded up to float32): an upper bound of every partial sum of every value and, divided by n, of m. With `normalize` and a row within one threadgroup (the dimension at most 1,024 when it is a multiple of four, else at most 256), the kernel normalizes as the cpu does: `dot16` of the row with itself in threadgroup memory (16 lanes by fma in index order, added 8, 4, 2 and 1 lanes apart), `1 / sqrt` with `precise::sqrt` and `precise::divide`, one product per value, and gives the sum of squares to the host; for wider rows the host normalizes the device's rows. Only explicit `fma`, `precise::divide` and `precise::sqrt`; contraction is off (`#pragma METAL fp contract(off)`, as `math_mode="safe"` alone fuses `x * y + z`) and fast math refuses to compile. float16 and int8 rows widen to float32 exactly. Offsets are uint32 (a task holds at most 2**24 tokens and buckets); row, bucket, output and flag addresses are 64-bit products.
- **Subnormal inputs.** The GPU flushes subnormal values to zero. `prepare` checks the inputs once, on bit patterns (no comparison of floats, which a thread that treats subnormal values as zero would get wrong): a subnormal weight, scale, ngram scale, oov weight or float32 row value, and the stage-2 factors as the cpu computes them that can be subnormal with normal inputs: `weight * scale` of every int8 word, and `(1 / m) * oov_weight` (times every ngram scale for int8) for any m up to 2**24. The products are exact in float64 (no float64 value there is subnormal, so no floating-point environment changes them); since `1 / m` rounds to at least 2**-24 and rounding is monotonic, the products with 2**-24 are the smallest factors. Such an encoder runs on the host for this backend (`subnormal_input`). float16 values widen to normal float32 values. What the GPU may still flush is a product of a normal factor and a normal value, or a partial sum, below 2**-126, and what that turns later; the bound covers both.
- **Fallback per row.** The kernel flags per sentence an accumulator that is not finite and a sentence or unknown word of 2**24 or more tokens. From the kernel's sum the host bounds every row (`_bounds`, in float64, rounded towards the safe side): `E = (τ + 2 γ_K) M / n + δ`, M at most `(sum + K 2**-126) / (1 - K u)`. It takes from the host the rows that could give another result or error than the cpu's, as `limit`: a bound that is not finite; partial sums that could reach 2**127 (a flush can turn the cpu's sum to infinity while the device's stays finite); before `normalize` a row with `||g|| <= 2 E` (it could be zero or tiny on the cpu), `||g|| - E` below 2**-50 (a sum of squares that could be subnormal on the cpu or below 2**-100 on the device) or `||g|| + E` from 2**60 on, `||g||` bracketed from the device's sum of squares when the kernel normalizes; and without normalize a row whose largest value plus E reaches 65,504, the float16 range, for every target (`rows` does not know the sink's dtype; with the cpu's row a float16 store raises the cpu's error, and `store` quantizes exactly the rows it is given). A task with such a row is computed again by the host from the original batch, so its error, if any, is the cpu's for the task (pooling before steps, in row order); on success only those rows take the host's rows, and every other row keeps the device's result. A batch of more tokens and buckets than one device group (2**24), or that may hold a sentence of K >= 2**24 (where γ_K is undefined), runs in runs of whole sentences of at most a group, after the host has computed it whole for its errors: a sentence of more than a group runs alone on the device, one of K >= 2**24 keeps the host's row (`large`); the group decides no row's path. The first fallback of an encoder logs a warning, and the backend counts them by reason (`fse._backends._mlx._backend.fallbacks`: `dim`, `subnormal_input`, `long`, `nonfinite`, `limit` and `large`). The conformance suites check that only the encoders with subnormal inputs fall back among their cases, that a backend computing everything on its host fails them, and that a flagged row changes no other row in any split of tasks or groups.
- **Canary.** The first `prepare` of a process runs the kernel, with one and with four values per thread, on inputs given as bit patterns (so the floating-point environment of the importing thread cannot change them) with fixed expected bit patterns and flags: a fused product, `1 / 3` rounded first, an overflow (flagged), an exact cancellation to +0.0, a row normalized in the kernel with its sum of squares, the bound of the magnitudes (at least the exact sum), and the smallest subnormal float16 widened exactly; it raises `UnsupportedByBackendError` on another GPU or compiler that differs.
- **Device thread.** `rows` blocks in the worker that calls it. One device thread per process owns all MLX work: the workers queue their calls, and the thread takes all calls waiting at that moment (up to 8 tasks or 2**24 tokens), queues one kernel per task and starts their evaluation together (`async_eval`), so the workers share one GPU round trip; it starts the next group before it waits for the one before, so at most two groups are in flight and the GPU computes one while the thread finishes the other. A finished job gives its caller a view of the MLX rows: the worker copies its rows (and the flags and bounds into buffers of its own), and the device thread lends the MLX arrays until the worker returns the lease, also on errors and interrupts, then drops them itself. It starts with the first call and ends when none is left and every lease is back; the callers of its last group join it, so no thread outlives the calls, and a new thread joins the one before before any MLX work (outside the queue's lock), so device threads never overlap; all such threads use one stream made for the hand-over (a thread's default stream costs about 1 ms to make). The host checks every token and bucket before a launch (an index out of range reads other memory on the GPU without an error) and gives such a batch to the cpu backend, which raises its error. An error of one call's launch fails that call; an error of the evaluation fails the calls evaluated with it. A caller interrupted anywhere from queueing to waiting cancels its call if the device thread has not taken it (queued or not yet), or waits until the device thread is done with it and returns its lease (through further interrupts), so nothing writes into its rows afterwards; a device thread that cannot start leaves the queue as it was. Each call is one job of the worker that waits for it, so a failing or interrupted `infer` leaves no job behind and other calls go on. The window of the runtime counts the pooled rows, flags and bounds of a task on the device (`Capabilities.device_rows`).

### Runtime

`fse._runtime` runs encoding on one executor (`run`):

- **Tasks.** A source is scanned into chunks, one task each: about `chunk_bytes` of text (64 KiB to 1 MiB by default, scan ranges never smaller than a chunk) and at most 16 MiB of finished rows (`TASK_ROW_BYTES`; a task has a fixed cost of about 0.2 ms for its checks, so smaller tasks cost throughput). A stream is read in collections of up to 65,536 sentences, each scanned into tasks with rows counted from the start of the stream.
- **Inline.** A source of at most 64 KiB, and `workers=1`, run in the calling thread without any thread; with the default workers such inputs are within 8 % of `workers=1` (`benchmarks/bench_runtime.py latency`).
- **Threads.** Otherwise a pool of `workers` threads, created per call, with one workspace per thread; the native routines release the GIL and set the floating-point environment of their thread themselves, so a worker that inherited flush-to-zero gives the same bits. The tasks are taken, and each task's output rows reserved (`Sink.target`), in the calling thread; results are committed in task order in the calling thread, so a sink needs no locks.
- **Window.** At most `2 * workers` tasks are in flight or waiting to be committed, and their rows take at most 512 MiB (`WINDOW_BYTES`; with many workers a task holds fewer rows; every row counts its target, the float32 rows before a float16 or int8 target is stored, and with `normalize` 12 bytes per value (`STEP_ROW_BYTES`): normalize runs in place, but without this term its tasks were up to twice as large and the peak RSS of a stream at 10 workers grew by 65 to 140 MiB for at most 10 % throughput on an M1 Pro, because the rest of a task grows with its rows too, so the term stays): a slow sink slows the source, and memory stays bounded by the window and one collection of a stream.
- **Storage.** A sink with a `dtype` of float16 or int8 reserves codes (and int8 scales); the worker of a task pools into a float32 buffer of its thread and stores the rows with the backend's `store`, so the calling thread only commits. On an M1 Pro float16 and int8 output run at 0.91 to 1.03 of float32 for 1 to 10 workers (`bench_runtime.py store`); in 1.1, int8 output ran at about 0.33. The window counts the stored target of a row besides its float32 rows; it bounds the rows in flight, not a result that joins all rows.
- **Sinks.** A sink (`fse.Sink`) takes the rows of a run: `target` and `commit` in the calling thread, in row order, each row once; a target is valid only until its commit. Optional parts: `dtype`, `inverse_norms` (the target ends with a float32 vector the worker fills with the inverse norm of every stored row, so a store computes none in the calling thread; the window counts it), `encoder_fingerprint` (the fingerprint of the only encoder it takes), `flush()` after the last commit of a successful run, `publish()`, which `encode_batches` calls after the rows of every batch are committed and before it reads `durable_rows`, and `durable_rows`, the leading rows of the run that are durable. A sink takes one run; a second run into it starts again at row 0, which it refuses. `Pipeline.infer` numbers the rows of a sink from `first_row`, so the batches of a stream continue the rows of a run. `Encoder.encode(texts, sink=)` commits to a sink and returns nothing; `encode_batches(batches)` encodes a stream batch by batch, each a finite list (as a queue consumer polls them), and gives one `EncodedBatch` per batch once its rows are finished: its rows without a sink, else the sink's `durable_rows`, so a consumer confirms its input only up to there (at least once: after a crash it reads again from the last confirmed offset). That count is a snapshot after the sink's `publish`: the sink's `flush` runs after the last batch, so after a successful full iteration the sink's own `durable_rows` says what is durable (for a ShardSink every row), and the last batch may report fewer. Stopping early does not flush; the owner of the sink closes it. `MemorySink` keeps the rows of a run in memory and has no `durable_rows`.
- **Errors.** The error raised does not depend on the task boundaries or the number of workers: of all rows of a run, the error of the earliest failing row in row order is raised, and for one row the error of its earliest failing stage (1 the scan and tokenizing, 2 and 3 pooling, 4 the steps, 4b a head, 5 storage). The stages of a task run one after the other over all its rows, so a task that fails is run again on shorter prefixes of its rows, by bisection, until the shortest failing prefix is found (`fse._runtime._errors.earliest`, every `ValueError` of a task); every row is a pure function of its sentence, so that prefix fails at its last row, in the first stage that row fails in. This costs nothing until a task fails, and then about log2 of its rows runs of its prefixes. The scan of a source does not raise before the first task: its tasks end before the first invalid sentence, and the scan's error follows them in order, so an earlier row that fails in a later stage is raised first; no row behind an invalid one is encoded. Messages name the row of the source, never the position within a task. Only rows of successful tasks are committed, in order; the size of the committed part before an error is not part of the contract and may depend on the task size and the workers. Tasks after a failed one are skipped where they have not started, and once a task has failed nothing more is read from the source. Every argument of `infer` is checked before the source is read. A bad sentence or an error of a stream's iterator is raised after the tasks before it. An error of the sink (reserving or committing rows) or an interrupt cancels what has not started, waits for running tasks and is raised. No thread outlives a call.

- **Heads.** A linear head runs in the worker of every task, after stages 1 to 3, as stage 4b (`fse._runtime._head`): the `HeadPipeline` reads the rows of one pipeline of the encoder, the pipeline of the folded table (made at the first prediction on a backend: every word and ngram row scored with A, in blocks of 16,384 rows over the usable CPUs) for a head on raw means, else the encoder's full mean with the head's step. The worker pools into a buffer of its thread (into the target itself for the logits of a folded head), computes the logits with the backend's `logits` and their outputs with `outputs`, so the sentence vector never leaves the worker. With the vectors (`return_vectors=True`), one pooling gives both where the head reads the encoder's own rows (the flags agree); a head whose flag overrides its encoder pools the vectors a second time on the encoder's pipeline. The window counts the rows the head reads (with the step term when it normalizes), the logits, the output target and, with the vectors, their target as the encoder's pipeline counts it. Outputs go to float32 sinks without inverse norms; a sink that names an `encoder_fingerprint` must name the output identity (`output_identity(output)`, the fingerprint of `{"model": the model's fingerprint, "output": "decision" | "proba" | "values"}`), since a model's fingerprint does not tell its decisions from its probabilities; labels go to no sink and come from `predict_batches`. A `ShardSink` takes the vectors of `return_vectors=True` but no head outputs in 2.0, as a store records the fingerprint of an encoder.

A `Pipeline` holds an encoder on one backend (prepared once, before any input is read) and is immutable, so several threads may call `infer` at once; a server that encodes many small requests in parallel sets `workers=1` per request. An `Encoder` builds its `EncodeSpec` once, the `VocabTable` of its vocabulary once (`Vocabulary`, shared by all its pipelines and passes), and one `Pipeline` per backend on first use.

### Artifacts

Word vectors, encoders and stored sentence vectors are sets of named tensors with a flat string map of metadata, written through a container:

```python
class TensorContainer(Protocol):
    def write(self, path, tensors: Mapping[str, ndarray], metadata: Mapping[str, str]) -> None: ...
    def open(self, path, *, mmap: bool) -> tuple[Mapping[str, ndarray], Mapping[str, str]]: ...
    def verify(self, path) -> None: ...
```

- **Tensors** follow the rules of safetensors: numeric dtypes only (F64, F32, F16, I8, U8, U32, I64; F64 only for the float64 scores of `unigram@1`, every format refuses it elsewhere), little-endian, C order, every tensor aligned to its type and the data of a file starting at a multiple of 64 bytes, names matching `[a-z0-9_]+(\.[a-z0-9_]+)*` except `__metadata__`, which safetensors reserves; dimensions are int64 and the product of the non-zero ones times the item size stays within int64, also for tensors with a zero dimension; writers check the same rule. Writers first take a snapshot of the mapping of tensors, of every array's shape and dtype (as a view) and of the metadata, so a caller that changes them during a write does not change the header or the fingerprint. The data are not copied as a whole: every block is copied once when it is written and that copy is hashed, so the checksums always describe the written bytes, and `expected` checksums detect data that changed since they were checked. Strings are UTF-8 bytes (U8) plus int64 offsets, so the vocabulary is `vocab.bytes` and `vocab.offsets`. Every floating-point number that affects the result, such as `oov_weight`, is a tensor, never a decimal string. Integer parameters (dimensions, `min_n`, `max_n`, `bucket`, `max_ngrams`) are metadata, written as decimal strings without sign or leading zeros, or as canonical JSON for a group of them.
- **Names.** Word vectors: `vectors`, `scales` (int8), `vocab.bytes`, `vocab.offsets`, and for FastText `ngrams` and `ngram_scales`. Encoder: its table under the names of word vectors, and `oov_weight` for FastText. Stored sentence vectors and shards: `vectors`, `scales`, `inv_norms`; `row_ids` is reserved for 2.1.
- **Metadata** (`fse.` keys, mapped one to one to the `__metadata__` of safetensors): `fse.kind`, `fse.format_version`, `fse.created_by` and a `fse.checksum.<tensor>` (xxh3-128, see Identities) per tensor for all; `fse.dim`, `fse.dtype`, `fse.fasttext` (min_n, max_n, bucket) and the quantization rule for word vectors; `fse.transform_version`, `fse.tokenizer`, `fse.aggregation`, `fse.steps`, `fse.output_dim`, `fse.max_ngrams` and the keys of its table for an encoder; the encoder fingerprint, `fse.transform_version`, the storage dtype, `fse.output_dim` and the range of rows for stored vectors.
- **Containers by purpose.** Every kind of artifact has exactly one container, enforced when it is read:

  | Artifact | Container | Path |
  |---|---|---|
  | word vectors, encoders, linear heads (models, the hub) | safetensors 1 | one `.safetensors` file |
  | stored sentence vectors and their shards (output) | NpyContainer 1 | a directory of `.npy` files and `manifest.json` |

  Models are shared and read: one standard file per model and dtype, which the hub shows and other tools read. Output is a large matrix written in parallel and read by numpy-based tools: every shard tensor is a plain `.npy` that `np.load(mmap_mode="r")` opens directly. Both containers record the same checksums and give the same fingerprint for the same content; a golden test writes the same tensors through both and checks content and fingerprint.

### safetensors 1

`fse._container.SafetensorsContainer`, in the package of both containers, whose modules import only the standard library, numpy, xxhash (in `_hash` alone), `UnsupportedArtifactError` and each other (relatively), so it can be copied into another project; `_npy` and `_safetensors` share only `_common`, and all of them hash through `_hash`.

- The checksums describe themselves, and they alone tell the artifacts of a pre-release of 2.0 apart, which had the same layout and versions but sha256 checksums (64 hex digits) and `sha256:` fingerprints; no version number does. Both containers reject an artifact whose checksums and fingerprint are all sha256 values with an `UnsupportedArtifactError` that names sha256 and xxh3-128, values of another algorithm (`<name>:<hex>`) with an `UnsupportedArtifactError` too, and a malformed value or a mix of algorithms with a `CorruptArtifactError`, before the content is used. There is no migration: such artifacts are written again.

- The file is safetensors: an 8-byte little-endian header length, a UTF-8 JSON header `{"__metadata__": {...}, name: {"dtype", "shape", "data_offsets"}, ...}`, then the data. The tensors lie by descending item size, then name, without gaps, so each is aligned to its type; the header is padded with spaces so that the data start at a multiple of 64 bytes. The reference implementation reads these files.
- Reading is strict: a header of at most 16 MiB and within the file, a JSON object padded with spaces only and data starting at a multiple of 8 bytes, no duplicate keys or NaN constants, exactly `dtype`, `shape` and `data_offsets` per tensor, only the dtypes above (others raise `UnsupportedArtifactError`), offsets that fit the shape (computed with Python integers), tensors aligned to their type and covering the data without gaps or overlaps up to the end of the file, and `__metadata__` mapping strings to strings with the checksums and the fingerprint of the content. Files from other writers lack these keys and are rejected.
- A normal open reads the data into one immutable `bytes` and checks every checksum; `open(mmap=True)` maps the data once, read-only, and the tensors are views of that map; `verify` hashes the tensors on disk. A normal open and `verify` raise if the size or modification time of the file changed while they read it. A mapped file must not be changed or truncated while it is mapped: a change is caught by the checksums the next time the data are checked, but a truncated file can end the process with SIGBUS on POSIX, which no reader can catch; copy files that other processes may change. The file is opened as described for the NpyContainer: a regular file, not followed if it is a link, checked against its path.
- Writing goes to a temporary sibling created exclusively (`tempfile.mkstemp`, `.<name>.writing-...`): the header is reserved (its length does not depend on the checksums), every block of data is copied once into immutable bytes, and that copy is hashed and written (and compared with `expected` checksums if given), so the file holds exactly what its checksums describe even if the source changes meanwhile; then the header is written and the file synced. It is published without ever replacing a file: `os.link` on POSIX (then the directory is synced), `MoveFileExW` with `MOVEFILE_WRITE_THROUGH` and without `MOVEFILE_REPLACE_EXISTING` on Windows. A failed write removes only its own temporary file. A path without `.safetensors` raises.

### NpyContainer 1

`fse._container.NpyContainer`, for stored sentence vectors.

- An artifact is a directory with `manifest.json` and one `<tensor name>.npy` per tensor. The manifest holds exactly `{"container": "npy", "container_version": 1, "tensors": {name: {"file", "dtype", "shape"}}, "metadata": {...}}`: `file` is the name plus `.npy`, `dtype` a code of the table above, `shape` a list of non-negative integers, metadata values strings. Duplicate keys, NaN constants, unknown or missing keys raise `CorruptArtifactError` (a `ValueError`); another container or version raises `UnsupportedArtifactError`; a pre-release artifact with sha256 checksums is rejected by its checksums (see safetensors 1). Unlisted files in the directory are ignored.
- The manifest and every `.npy` must be regular files, not symbolic links; each is opened once (without following links and without blocking), checked against the path it was found at, and read or mapped through that one handle; numpy parses one bounded copy of each header. The manifest may hold at most 16 MiB, a `.npy` header at most 64 KiB (checked before numpy reads it), a tensor at most 32 dimensions; sizes are computed with Python integers, so a shape cannot overflow.
- Every `.npy` is version 1.0 or 2.0 with the exact type description of its code (`<f4`, `<f2`, `|i1`, `|u1`, `<u4`, `<i8`), C order, the shape of the manifest, data at a multiple of 64 bytes and nothing after the data; pickled objects are never read.
- The writer enforces the limits of the reader, and with `expected` checksums it hashes every tensor while writing and commits only if they match. The container writes `fse.checksum.<name>` (the xxh3-128 checksum of the data, see Identities) for every tensor and `fse.fingerprint`, and rejects them from the caller. A normal open reads every tensor into immutable `bytes` and checks its checksum (hashed in 64 MiB chunks); `open(mmap=True)` checks the manifest, the headers, the sizes and the fingerprint against the recorded checksums, and maps the data read-only; `verify` hashes the data on disk. Tensors with no elements are empty arrays, as nothing can be mapped.
- Writing creates the target directory exclusively (an existing one raises `FileExistsError`, also when another writer created it first; artifacts are never overwritten, which also avoids replacing mapped files on Windows), writes and syncs every tensor, syncs the directory, and commits by renaming the manifest from a temporary name into place; a directory without a manifest is no artifact. Any failure removes the directory.

### word_vectors 1

`fse.WordVectors` (`fse._wordvectors`), one `.safetensors` file, created by `from_arrays`, `fse.gensim.from_gensim` (extra `fse[gensim]`; gensim is imported only there) or `load`. Immutable: the arrays it returns are new read-only headers on its data, and a normal load reads every tensor into immutable `bytes`; making an internal array writable again through `.base` is outside the contract. Read as float32, never pickled. `verify` checks the data the object holds against the checksums it was loaded with, then the files on disk. `save` of loaded vectors compares every tensor with those checksums while writing it, and `quantize` reads every block once and hashes and quantizes that same copy, so damaged or changed data never gets new checksums; for mapped vectors these checks are never skipped, as the file can change underneath the map. Quantized vectors own all their arrays.

- Tensors: `vectors` (n x dim, F32, F16 or I8), `scales` (F32, n) exactly for int8, `vocab.bytes` (U8), `vocab.offsets` (I64, n + 1, from 0 to the number of bytes), and for FastText `ngrams` (bucket x dim, the dtype of the vectors) with `ngram_scales` exactly for int8. 1 <= n < 2**32 - 2 (word ids stay below the reserved token ids), dim >= 1.
- Metadata (closed: any other key raises): `fse.kind=word_vectors`, `fse.format_version=1`, `fse.created_by`, `fse.dim`, `fse.dtype` (`float32`, `float16`, `int8`), `fse.quantization=quantize_rows@1` exactly for float16 and int8 (the storage rules of the numerical contract), optional `fse.quantized_from` (the fingerprint of the float32 vectors, only for float16 and int8), and for FastText `fse.fasttext` (canonical JSON of `bucket`, `max_n` and `min_n`, 1 <= min_n <= max_n, 1 <= bucket <= 2**32 - 1) with `fse.ngram_hash=fasttext@1`.
- The vocabulary is UTF-8; a word is found by the exact match of its bytes (NFC and NFD spellings are different words, a string without a UTF-8 form is no word). Every open checks the structure, the offsets and the UTF-8 of the vocabulary in chunks; `verify` and every writer also check that words are unique, floats finite, int8 codes within -127 to 127, scales finite and not negative, and every int8 row times its scale finite.
- Version 1 was redefined before the first release (maintainer decision of 29.10.2026; no version was bumped, as nothing was released): word vectors hold no word counts. A file of a pre-release with a `counts` tensor raises `UnsupportedArtifactError` naming it ("written by a pre-release of 2.0; rebuild the model"). A file of a pre-release without counts is not told apart and needs no marker, because it is the same artifact: the same tensors, keys and dtype rules, xxh3-128 checksums and the same fingerprint document, so it has the fingerprint today's writer gives the same content (`tests/test_wordvectors_format.py` checks it on the pre-release golden with its counts removed). Only sha256 artifacts, refused by their checksums, are older.
- For FastText, the row of a known word is the word's own row (gensim's `vectors_vocab`), not gensim's average of it with its ngrams; combining ngrams for unknown words belongs to the encoder.
- `quantize` makes float16 or int8 vectors from float32 ones in blocks, without a float32 copy; quantized vectors are never quantized again. Loading int8 vectors allocates about their codes; a test checks it with `tracemalloc`.
- `tests/test_data/v2/finished/` holds golden float32 and int8 vectors (`.safetensors`) with pinned fingerprints, written by `tests/test_data/v2/make_golden.py` (with the golden encoders, see encoder 1); the pinned files are never rewritten. `tests/test_data/v2/word_vectors_{float32,int8}.safetensors` are the goldens of a pre-release, with word counts, and `tests/test_data/v2/sha256/` the same with sha256 checksums; both are kept byte for byte only as files that must be rejected, by their counts and by their checksums.

### encoder 1

An encoder (`fse._encoder`) is a finished model in one self-contained `.safetensors` file: its table, its tokenizer, `weighted_mean@1` and whether every row is normalized. The keys and tensors are a closed set (`fse._encoder._format`); anything else raises. Version 1 was redefined before the first release (maintainer decision of 29.10.2026; no version was bumped, as nothing was released).

- Metadata: `fse.kind=encoder`, `fse.format_version=1`, `fse.created_by`; `fse.transform_version=2`; `fse.tokenizer`; `fse.aggregation=weighted_mean@1`; `fse.steps`, the canonical JSON list of the steps applied per row, `[]` or `["normalize@1"]`; `fse.output_dim`, the dimension of the rows (that of the table for the weighted mean); `fse.max_ngrams` exactly for FastText; and the keys of the table as in word_vectors 1: `fse.dim`, `fse.dtype`, `fse.quantization`, `fse.quantized_from`, `fse.fasttext`, `fse.ngram_hash`.
- The keys of a tokenizer with parameters (`wordpiece@1`, `unigram@1`; the closed set is derived from `fse.tokenizer`, any other key raises): `fse.tokenizer_config`, the canonical JSON object of its parameters (*Tokenizers*); `fse.unknown`, `drop` or `keep`; optional `fse.max_tokens`, a decimal integer of at least 1, and `fse.max_chars`, the same, only with `fse.max_tokens`. An encoder of either has a float32 table without FastText (model2vec computes the mean of a float16 table in float16, so the bound of a comparison would not hold; other dtypes come with a bound of their own). A tokenizer with data beyond its vocabulary stores it as tensors `tokenizer.<name>`, exactly those it defines: `unigram@1` the F64 vector `tokenizer.scores` (one float64 per piece, finite) and, exactly with a `precompiled` step, the U8 vector `tokenizer.charsmap` (the blob of the tokenizer.json, checked on every read); scores of another dtype, shape or length, a missing or extra tensor, and these tensors with another tokenizer raise. Optional provenance, never read to compute and covered by the fingerprint: `fse.source`, the canonical JSON `{"format": <str>, "repo": <str or null>, "revision": <str or null>}` of the model it was converted from, with `"dims": [<width>, <kept>]` (two ints, 1 <= kept < width, kept equal to `fse.dim`) exactly when its table was cut to its first dimensions (`truncate_dim`), and `fse.license`, the license of that model as its card states it: one license id, or the canonical JSON list of the ids it lists.
- Tensors: the table under the names of word_vectors 1 (`vectors`, `scales` for int8, `vocab.bytes`, `vocab.offsets`, and for FastText `ngrams` and `ngram_scales`), checked by the rules of word_vectors 1 on every open; `oov_weight` (F32, a scalar, exactly with `fse.max_ngrams`). There are no word weights: every word weighs 1 (a ones array inside, so the kernels keep their arithmetic).
- `Encoder.from_word_vectors(wv, *, tokenizer="fse_words@1", normalize=True, max_ngrams=None, oov_weight=None)` makes one of `fse.WordVectors`; FastText vectors take `max_ngrams` (default 40) and `oov_weight` (default 1), other vectors neither. `Encoder.from_arrays(vectors, *, words=..., ...)` is the same of `WordVectors.from_arrays` of its arrays. `Encoder.load(path, mmap=False)` reads one, `save` writes one (loaded data compared with the checksums they were loaded with); `encoder.word_vectors` is the table, with the fingerprint of the same tensors and keys as word_vectors 1.
- Refused as a file of a pre-release ("written by a pre-release of 2.0; rebuild the model", `UnsupportedArtifactError` naming what it holds): the keys `fse.recipe`, `fse.folded`, `fse.folded_from`, `fse.input_dim`, `fse.word_vectors` and `fse.vocabulary`, the tensors `weights`, `step.<i>.*` and `folded.<i>.*`, and an encoder without a `vectors` table of its own. A step list with another identifier (such as the removed `remove_components@1` or `project@1`) raises as an unknown step. There are no converters: such models are made again.
- Golden files: `tests/test_data/v2/finished/encoder_float32.safetensors` (FastText, `fse_words@1`, normalized) and `encoder_int8.safetensors` (int8, FastText, `external`, not normalized), written by `make_golden.py`, with pinned fingerprints and the pinned bits of the rows they give; they are never rewritten. `tests/test_data/v2/encoder_sif_unfolded.safetensors` and `encoder_usif_folded_int8.safetensors` (and their sha256 forms in `sha256/`) are the encoders of a pre-release, kept byte for byte only as files that must be rejected.

**The tokenizer part of a model.** Everything that decides which rows a text pools is in the file:

- **Identity.** `fse.tokenizer` names the tokenizer: `fse_words@1`, whose rules and table (simple lowercase of Unicode 15.1.0, checked in) are fixed by the identifier, so the file needs no data of it; or `external`, where the caller gives the tokens (or text split at whitespace W) and owns reproducing them, so the file promises nothing about tokenization. `wordpiece@1` has its rules and tables fixed by the identifier and its parameters (vocabulary aside) in `fse.tokenizer_config`, covered by the fingerprint. Any change of rules, tables or Unicode version is a new identifier.
- **Token to row.** For `wordpiece@1` the token id is the row. Otherwise a token is matched by the exact equality of its UTF-8 bytes with a word of `vocab.bytes`/`vocab.offsets`; the index of that word is the row of `vectors` (no separate map, no normalization of the bytes). For FastText, a token that is no word maps to the rows of its first `max_ngrams` `fasttext@1` buckets.
- **Special tokens.** No tokenizer adds any (no [CLS], [SEP] or padding). With `fse_words@1` and `external` a vocabulary word that looks like one (such as `[UNK]`) is an ordinary word, matched only by its exact bytes; with `wordpiece@1` the added tokens of its parameters are matched in the raw text, as tokenizers does without special tokens.
- **Unknown tokens.** Without FastText a token that is no word is no token: it adds nothing and does not count in n, and a sentence of only unknown tokens is the zero row. With FastText an unknown token counts once and adds its ngram rows with `g = (1/m) * oov_weight` (stage 2 above); with no bucket it only counts. There is no row for unknown tokens. With `wordpiece@1` an unknown word is `unk_id`, which `fse.unknown` drops or keeps as its row.
- **Length.** No limit, unless a `wordpiece@1` model states one: `fse.max_chars` and `fse.max_tokens` are the documented length rule of the format the model was converted from (model2vec: 512 tokens and a character cut), visible in its metadata and its `repr`; a converted model can be made without them (PR 12a2, `truncate=False`). Otherwise every token of a sentence counts, nothing is truncated, and a sentence is one row whatever its length.
- **Normalization.** `fse.steps` of the file says whether every row is normalized by `normalize@1`; `normalize=` sets it when a model is made (default True). A model converted from another library takes the setting of its source, and its rule is `normalize@1` (no epsilon in the norm).

The converted models of PR 12 must state where they differ from their source: per the source code reviewed for this plan, Model2Vec drops unknown token ids, applies length rules and adds a small value to the norm, while StaticEmbedding pools every id its tokenizer gives, and both disable the special tokens of their tokenizers ([Model2Vec](https://github.com/MinishLab/model2vec/blob/main/model2vec/model.py), [StaticEmbedding](https://github.com/huggingface/sentence-transformers/blob/main/sentence_transformers/sentence_transformer/modules/static_embedding.py)). The keys above say all of it for `wordpiece@1` models (`fse.unknown`, the length rule; the epsilon of Model2Vec is not reproduced, so a row whose sum of squares underflows or overflows raises in `normalize@1`, where Model2Vec gives a row that is not of unit length).

### Model2Vec models and from_pretrained

`Encoder.from_pretrained(repo_or_path, *, revision=None, token=None, cache_dir=None, local_files_only=False, truncate=True, max_length="model", truncate_dim="model", normalize="model", mmap=False)` gives the encoder of a pretrained model. It converts a model of another library on every call, in memory (nothing is hosted, the license of the model applies unchanged), or loads an fse encoder.

- **Where.** An existing local path is a `.safetensors` file (an fse encoder, `Encoder.load`) or a folder. Anything else must be a Hub id `namespace/name`, read by `fse._hub` with the extra `fse[hub]` (huggingface-hub 1.0 or newer, imported only there); without it, an ImportError names the extra. `revision`, `token`, `cache_dir` and `local_files_only` are for the Hub and raise with a local path.
- **What** (`fse._encoder._pretrained`), in this order:
  - `"model_type": "fse"`: an fse encoder; the config holds exactly `model_type`, `fse_kind` (`encoder`), `fse_format_version` (1) and `encoder`, the name of its `.safetensors` file. `mmap` maps a local one. This schema is provisional: it is fixed with the first upload of fse models to the Hub (with the maintainer's approval), which may add keys, such as a file per dtype.
  - a `config.json` with model_type `model2vec` or none: a Model2Vec model, as model2vec 0.10.0 finds one (`config.json`, `model.safetensors` and `tokenizer.json`; a missing file raises), also with a `modules.json` next to it (as the potion repos have), which must then list only StaticEmbedding and Normalize: behaviour is defined per format, and this one is model2vec's;
  - otherwise a `modules.json`: a sentence-transformers model (*sentence-transformers models*); a `config.json` of another model_type next to it is ignored, as sentence-transformers ignores it, and only named in errors;
  - `config_sentence_transformers.json` without `modules.json`: refused (sentence-transformers builds a Transformer and Pooling for it);
  - anything else: "no static embedding model", naming the model_type and files.

  `truncate` and `max_length` are for Model2Vec and sentence-transformers models, `truncate_dim` and `normalize` for sentence-transformers models, `mmap` for fse encoders; the other combinations raise.
- **One read per file.** Every file of a model is read once, through one handle of a regular file (never a link, FIFO or other kind), within its size limit (`config.json` and `modules.json` 1 MiB, `README.md` 16 MiB, `tokenizer.json` 64 MiB), into immutable bytes, and a file that changes while it is read raises. Those bytes are what is checked against the Hub commit and what is parsed, so a blob changed after its check changes nothing. An fse encoder of the Hub is therefore read into memory; `mmap` is for local files and raises for a Hub repository (save the encoder and load the file with `mmap`).
- **The Hub at one commit.** `revision` (None: the default branch) is resolved to its commit by `model_info` once, and every file comes from that commit (`hf_hub_download(revision=<commit>)`). The commit pins every file, and each is checked after the download: an LFS file by its `lfs.sha256`, any other by its git blob sha1, both computed in `fse._container._hash`. Every `.safetensors` file (the table of a Model2Vec model, an fse encoder) must be an LFS file; one without `lfs.sha256` raises. A file may lie in a folder of the repository (`0_StaticEmbedding/model.safetensors`). With `local_files_only` nothing is asked of the Hub: the commit is the cached snapshot of `revision` (`snapshot_download(local_files_only=True)`, no file of the model is needed for it) and the files are those below the snapshot, and every blob is checked against its name, which is its sha256 or git sha1 (this detects damage, not forgery); a snapshot that holds a copy instead of a link raises then.
- **Cache links.** A snapshot file of the Hugging Face cache is a link to `<repo>/blobs/<etag>`, the blobs of the same cached repository; with huggingface-hub 2 that entry is itself a link into the cache-wide store of Xet files, `<cache>/blobs/<2 hex digits>/<64 hex digits>`. Exactly these two steps are followed, compared as written and never resolved, and no folder from the cached repository down to a blob (`<repo>`, `snapshots`, the snapshot, `<repo>/blobs`, `<cache>/blobs` and its prefix folder) may be a link, so nothing leads out of the cache (the cache folder itself may be one). The per-repository etag is the name that is checked, and the regular file at the end is read; any other link raises. The folders are checked before the blob is opened by its path, not through held descriptors; a folder swapped in between is no gap of integrity, because the bytes that are read are hashed and compared with the commit (with `local_files_only`, with the etag resolved before), so a swap yields the pinned bytes or a refusal. Local folders make no such claim: their files are the caller's. A local folder that is a snapshot of the cache is read the same way.
- **The Model2Vec reader** (`fse._encoder._model2vec`, the rules of model2vec 0.10.0, `model.py` and `persistence/`):
  - `config.json`: strict JSON. `normalize` (default false) sets the step `normalize@1`; `max_length` (an int of at least 1, or null for none; default 512) the length rule; `hidden_dim` and `embedding_dtype` must match the table. `model_type`, `architectures`, `tokenizer_name`, `apply_pca`, `apply_zipf`, `sif_coefficient`, `seq_length` and `pooling` are provenance and ignored (`seq_length` is no length rule). `vocabulary_quantization` and `head_config` raise, and so does any other key, so a new key that changes encoding cannot be ignored silently.
  - `model.safetensors` (`fse._container._foreign`: the structural checks of safetensors 1 without fse's integrity keys; `__metadata__` may be absent and is ignored) holds exactly the tensor `embeddings`, a float32 matrix with one row per token. `weights` and `mapping` (vocabulary quantization) raise. float16 and int8 tables raise: model2vec computes their mean in their own dtype, so the bound of a comparison would not hold.
  - `tokenizer.json` (`fse._tokenizer_json`, strict JSON of at most 64 MiB with exactly its keys): a Unigram model gives `unigram@1` with the rules of `fse._tokenizer_json_unigram` (only the forms of potion-multilingual-128M; *Tokenizers*); otherwise a WordPiece model with dense ids and its unknown token in the vocabulary, a BertNormalizer (`strip_accents` null follows `lowercase`), a BertPreTokenizer, added tokens with `normalized`, `lstrip`, `rstrip` and `single_word` false that are vocabulary tokens with the same id, and a post-processor that is null or a TemplateProcessing whose template of a single text holds the sequence `$A` once. tokenizers 0.23.3 runs the post-processor also without special tokens: it then drops the special tokens but keeps every sequence, so `[CLS] $A [SEP]` leaves the ids unchanged while `$A $A` doubles them (tested); other templates and post-processors raise until their path is checked. `truncation` and `padding` are ignored, as model2vec overrides both (the sentence-transformers reader reads `truncation`), and `decoder`, as nothing decodes.
  - The encoder: `wordpiece@1` with `fse.unknown=drop` (model2vec removes every unknown id after the cut). With `truncate`, `fse.max_tokens` is `max_length` (the model's, or the argument; None: none) and `fse.max_chars` is `max_length` times the median length of the tokens in code points, as model2vec computes it (`int(np.median(...))` over every token in id order, in integers). `truncate=False` reads texts whole. `fse.source` records the format, repo and commit, and `fse.license` the `license` of the YAML front matter of `README.md` (at most 16 MiB; a larger card raises): a quoted or plain license id, or a block or flow list of them (all kept, in order); null, `~` or no value is no license, and so is a card without front matter or without the key; YAML values that are no string (bools, numbers), an empty list, the key twice and anything else raise.
- **Equality with model2vec.** The ids are those of the model's tokenizer (wordpiece@1). The rows are model2vec's within the tolerance bound (`tests/support/converted.py`: `(τ + 2 γ_K) m + δ K sqrt(d)` before normalize and `2 E / r` plus the rounding of both normalizations after it), because both are float32 sums of the same K rows in another order: model2vec takes numpy's mean and divides by `norm + 1e-32`. Not reproduced: a nonzero row whose sum of squares underflows or overflows float32 raises in `normalize@1` (the step is unchanged), where model2vec gives `[1e-30, 0]` as `[100, 0]` and a huge row as no unit row. Rows that tiny or that large do not occur with the POTION tables.

### sentence-transformers models

`fse._encoder._sentence_transformers` reads a sentence-transformers model of one StaticEmbedding with the rules of sentence-transformers 6.2.0 (`StaticEmbedding`, `SentenceTransformer.encode`); parity is defined against that version and tested against it (the group `st`, `make test-st`, the CI job `test-st`).

- `modules.json` (strict JSON, 1 MiB): a non-empty list of modules, each with exactly `idx`, `name`, `path` and `type` (and optionally `kwargs`, which is refused), taken in list order as sentence-transformers does. Exactly one module, a StaticEmbedding, spelled as sentence-transformers up to 5.3 writes it (`sentence_transformers.models.StaticEmbedding`, both target repos) or as 5.4 and later do (`sentence_transformers.sentence_transformer.modules.static_embedding.StaticEmbedding`). Its `name` is a non-empty str without `.` (sentence-transformers keys modules by name); its `path` is the model's folder (`""` or `"."`) or one folder in it, nothing that leads out. Refused, with the reason: a Normalize module after it (in any of its three spellings: sentence-transformers divides by `max(norm, 1e-12)`, which `normalize@1` does not reproduce for tiny rows; `normalize=True` is fse's own choice instead), a Dense module after it (without an activation: "not folded into the table"; the fold would round `W x` per token and needs a bias step), and any other module or sequence: "no static embedding model", naming the modules.
- `config_sentence_transformers.json` (optional, strict JSON, 1 MiB), every key known: `model_type` absent or `SentenceTransformer`; `prompts` only empty strings (sentence-transformers 6.2 writes `{"query": "", "document": ""}`) and `default_prompt_name` null or one of them, so encoding needs no prompt; `truncate_dim` null or an int of at least 1; `__version__`, `similarity_fn_name` and `requirements` are provenance; any other key raises.
- In the folder of the StaticEmbedding: `model.safetensors` with exactly one float32 matrix, `embedding.weight` or `embeddings` (the two names sentence-transformers 5.4 to 6.2 load alone), one row per token, checked by its header before its data, `mapping` or `weights` refused as vocabulary quantization; without it a `pytorch_model.bin` is refused as pickle. `tokenizer.json` as for Model2Vec, except `truncation`: null, or the plain form `{"direction": "Right", "max_length": n, "strategy": "LongestFirst", "stride": 0}` that keeps the first n ids (`fse.max_tokens`, no `fse.max_chars`), as tokenizers applies it in sentence-transformers (which disables only padding); any other form raises.
- The encoder: `wordpiece@1` with `fse.unknown=keep` (sentence-transformers pools the row of `[UNK]`; added tokens typed in the text, such as `[CLS]` or `[PAD]`, are matched and pooled as there), no length rule but the plain truncation (`truncate=False` reads texts whole; `max_length` raises), the mean of every id (`EmbeddingBag` in mode mean, an empty text the zero row). `truncate_dim` (the argument; `"model"` the config's; None all) keeps the first k columns of the table, which is sentence-transformers' `truncate_dim`, the prefix of the mean, value for value; k equal to the width keeps all, a larger k raises. `fse.source` records the format `sentence-transformers`, repo, commit and the `dims` of a cut. `normalize=True` adds `normalize@1` after the cut (sentence-transformers' `encode(truncate_dim=k, normalize_embeddings=True)`, up to its floor of 1e-12); without, rows are not normalized, as the target models are not.
- **Equality with sentence-transformers.** The ids are those of the model's tokenizer, `[UNK]` included. `EmbeddingBag` sums the rows in token order in float32 and divides by n, fse sums them in the same order (`fma` with the factor 1 is the same addition) and multiplies by `1/n` rounded once, so the rows differ by at most about one ulp (measured on torch 2.15.0, macOS arm64: at most 1 ulp). The tests rely on the bound of the tolerance contract only (`tests/support/converted.py`), which holds for any order of the sum. Rows that are zero before normalize (an empty text, a zero table, opposite rows) are zero on both sides.

| | Model2Vec format | sentence-transformers format |
|---|---|---|
| `[UNK]` | dropped after the cut | pooled |
| length | 512 tokens and a character cut | none, or the plain tokenizer.json truncation |
| normalize | `config.json`, `norm + 1e-32` in model2vec | a Normalize module (refused); `normalize=True` is fse's |
| first dimensions | none | `truncate_dim` |

### linear_head 1

A linear model (`fse._head`, `fse.Classifier` and `fse.Regressor`) in one `.safetensors` file: an encoder and one head, made with `from_sklearn` (the attributes of a fitted scikit-learn estimator, read without importing scikit-learn), `from_arrays` or `load`. fse trains no head (maintainer decision of 29.10.2026): the result of a trainer depends on the order of its updates, its solver and BLAS, while imported numbers are fixed in the file, so inference stays bit-exact.

- **Complete file** (`save(path)`): the tensors and keys of encoder 1 unchanged, with `fse.kind=linear_head` and `fse.format_version=1`, and the closed set of keys `fse.head` (`linear@1`), `fse.head.task` (`classification` or `regression`), `fse.head.normalized` (`true` or `false`: the head was trained on normalized rows), `fse.head.link` (`sigmoid@1`, `softmax@1`, `ovr@1` or `none`; always `none` for regression), `fse.head.labels` (canonical JSON list of int or str labels, exactly for classification: two for one output, negative first, else one per output), `fse.head.standalone`, `fse.head.flat` (exactly for a regression head of one output: `true` if it predicts (n,), as scikit-learn does for `coef_` of shape (d,), `false` for (n, 1)) and `fse.encoder_fingerprint` (the fingerprint of the encoder part); tensors `head.weight` (F32, k x d) and `head.bias` (F32, k), finite.
- **Standalone file** (`save(path, standalone=True)`, only for a head on raw means; a normalized head raises): the encoder part is the folded table (`vectors` F32 of k values per word, FastText `ngrams` folded the same way, no scales, `fse.steps=[]`, `fse.dim` and `fse.output_dim` k), with `head.bias` and no `head.weight`; it predicts the bits of the complete model and has no vectors, no encoder and no weights. The export folds a copy of a loaded table checked against the checksums it was loaded with, and compares the tensors it keeps while it writes them, so rows that changed since the load (a mapped file) raise `CorruptArtifactError` instead of getting new checksums.
- **Reading through the encoder parser.** `fse._head._format` checks the head schema, takes its keys and tensors off, sets `fse.kind=encoder`, hands the rest to `fse._encoder._format.from_artifact` (so the rules of encoder 1 apply unchanged) and compares the fingerprint of that encoder artifact, from its recorded checksums, with `fse.encoder_fingerprint`; a mismatch raises `CorruptArtifactError`. `Encoder.load` of a head file raises `UnsupportedArtifactError` naming the classes that open it, `Classifier.load` of a regression file names `Regressor.load`.
- **The flag.** `normalized` defaults to the encoder's setting (`"normalize@1" in encoder.steps`); a `StandardScaler` in a scikit-learn pipeline folds into A and b in float64 (the mean only with `with_mean`, the scale only with `with_std`) before they are rounded once to float32. A pipeline with a `Normalizer` is refused: scikit-learn leaves rows whose norm is below 10 * eps as they are, where `normalize@1` scales every nonzero row, so the head would read other rows; such heads are trained on the vectors of a normalizing encoder, or imported with `from_arrays(..., normalized=True)`. A wrong flag gives plausible but wrong predictions; a model whose flag overrides its encoder cannot predict from a store, which holds the encoder's rows as the encoder made them.
- **Store mode.** `predict*` of a `VectorStore` computes the logits from the stored rows by `score` block by block in row order (`fse._store._search.score_blocks`), in worker threads that also make the outputs, so `predict_batches` of a store holds a few blocks whatever its size. The store must hold the model's encoder (`encoder_fingerprint`) and the head's flag must equal the encoder's normalization; a standalone model has no weights for it.
- **Golden files**: `tests/test_data/v2/finished/classifier_float32.safetensors` (on `encoder_float32`: FastText, `fse_words@1`, normalized, softmax, three str labels), `regressor_int8.safetensors` (on `encoder_int8`: int8, `external`, raw means, two targets) and `classifier_standalone.safetensors` (a binary classifier on raw means, standalone), written by `make_golden.py` with pinned fingerprints and output bits; never rewritten.

### Identities

- A **row id** is the int64 position of a sentence in its source, from 0.
- A **shard** is a contiguous range of rows; 2.1 splits sources with `shard=(i, n)` at multiples of 16,384 rows.
- A **checksum** is `xxh3-128:` and the 32 lowercase hex digits of XXH3-128 with seed 0 (in the canonical big-endian form, as `xxhash.xxh3_128().hexdigest()` gives it) of bytes fed in order; a tensor's checksum is that of its little-endian C-order bytes, and a tensor without elements has the checksum of no bytes, `xxh3-128:99aa06d3014798d86001c324468d497f`. `fse._container._hash` is the only module that computes one and the only one that imports a hash library (`hash-importers` of the guardrails); it streams (`update` releases the GIL for large inputs), takes bytes, C-contiguous memory and C-contiguous little-endian arrays only, and the containers feed it in chunks. Values are compared as whole strings, the algorithm included.
- A **fingerprint** is the checksum of the UTF-8 bytes of the canonical JSON (keys sorted, separators `,` and `:`, no whitespace, non-ASCII characters unescaped) of `{"fingerprint": 1, "metadata": {...}, "tensors": [[name, dtype, shape, checksum], ...]}`: the metadata without `fse.created_by`, `fse.fingerprint` and the `fse.checksum.` keys; the tensors sorted by name, with the dtype code (such as `"F32"`), the shape as a list of integers and the checksum of the tensor. It describes the content, not the container, so every container gives the same fingerprint. A pre-release of 2.0 hashed the same document with sha256; its values are not read. The test vector (`tests/test_container_common.py`): tensors `vectors` F32 `[[1, -0.0], [0.5, 2]]`, `vocab.bytes` U8 of `"aé"`, `vocab.offsets` I64 `[0, 1, 3]` with metadata `fse.kind=word_vectors`, `fse.format_version=1`, `fse.dim=2`, `fse.dtype=float32` give `xxh3-128:8011e82efda8fabff21969cbaad4fae3`, and with `fse.note=é` added `xxh3-128:9e1f9e8737c4b9c190d5600af20953e0`.
- **What the hashes guarantee.** Checksums and fingerprints identify content against accidents: damaged, truncated or changed files and data that changed since they were checked (with 128 bits, a chance collision needs about 2**64 artifacts). They are no authentication: xxh3 promises neither collision resistance nor second-preimage resistance, so someone who can write a file can make different content with the same checksums and fingerprint, and no security-relevant binding may rest on them, such as a store's `fse.encoder`, a Vocabulary's fingerprint or the `expected` checksums of `save` and `quantize`. Anyone who can write a file could always recompute its values anyway, as no key is involved; the files are free of pickle and read strictly, so a forged file gives wrong data, not code execution. Authenticity needs a trusted reference: a cryptographic hash of the whole file from a trusted source, or a pinned revision; a hash computed from the file itself authenticates nothing. The Hub loader (`fse._hub`, *Model2Vec models and from_pretrained*) takes this from the Hub: registry artifacts must be LFS files, whose sha256 (`lfs.sha256`) a commit pins; a missing `lfs.sha256` is rejected, and a cached file is checked against it at its first trusted use.
- An encoder holds its table; stored vectors reference their encoder by fingerprint; opening them with a mismatch raises. 2.1 adds the fingerprint of the source for resuming.

### Persistence names replace class paths

Saved 2.0 artifacts contain no Python class paths. Their persistence API is the set of strings above: `fse.kind` values, identifiers, dtype codes, tensor and metadata names. From the first 2.0 release on, these are never renamed or reused with another meaning; before it, names that are no longer needed are removed, not reserved, and artifacts of a pre-release that hold them are refused (maintainer decision of 29.10.2026). The public Python API is `fse.__all__`; private modules (with a leading underscore) may move freely.

### Migration

2.0 has no pickle loader and no converter of 1.x models: 2.0 models are finished tables, made of word vectors (`fse.gensim.from_gensim`, `Encoder.from_word_vectors`) or, for SIF and uSIF, by the offline notebook with the 1.1.0 recipe (word weights, the uncentered removal of principal components, folded into the table, then quantized), which follows before the release and is checked against the 1.1.0 results of the README. The hub will carry such finished models.

### sentence_vectors 1

A store of sentence vectors (`fse._store`), a directory written by `fse.ShardSink` and read by `fse.VectorStore`.

- **`store.json`**, written once when the store is created and never changed: strict JSON, exactly `{"store": "fse_shards", "store_version": 1, "metadata": {...}}` with `fse.kind=sentence_vectors`, `fse.format_version=1`, `fse.transform_version=2`, `fse.encoder` (the fingerprint of the encoder of every row), `fse.dtype` (float32, float16 or int8; one per store) and `fse.output_dim`. It is created in a temporary directory beside the store, synced, and renamed into place without replacing anything, then the parent directory is synced; a store another writer created first is kept and checked. Another store or version raises `UnsupportedArtifactError`.
- **Shards**, each an NpyContainer 1 artifact `shard-<first row>` (the row as at least 16 decimal digits): `vectors` (rows of the dtype), `inv_norms` (F32, from the stored values, see the numerical contract) and for int8 `scales` (F32); `row_ids` is reserved for 2.1. Their metadata repeat those of `store.json` and add `fse.created_by`, `fse.quantization=quantize_rows@1` for float16 and int8, `fse.first_row` and `fse.rows`. Shards are immutable; an append adds shards after the last row, nothing is rewritten.
- **Reading** follows the shards from row 0 by looking up the name of the next one (`shard-<rows so far>`), so a shard published while a reader lists the store is either seen whole or not at all, and the rows always run without a gap; every shard must match `store.json` and hold exactly its tensors (the vectors in the dtype of the store, the inverse norms and scales as F32) and exactly its metadata keys; a float16 or int8 shard names `fse.quantization=quantize_rows@1` (another rule of that family raises `UnsupportedArtifactError`). `store.json` is read whole (at most 64 KiB) with exactly its keys and the integer version 1. Entries starting with a dot (shards being written, or left by a crash) and other names are ignored; remove leftovers only while no writer runs. `VectorStore.open` maps the shards published at that time (a snapshot).
- **Writing.** The ShardSink writes a shard in `.shard-<first row>.writing-<hex>`: `vectors.npy` gets the header of the full shard (by default the largest multiple of 16,384 rows within 256 MiB of vectors, at most 2**20 rows). The worker of a task writes its rows into a buffer of the task, which the window of the runtime bounds; the commit hands them to three threads of the sink, each behind a bounded queue (at most 16 pieces waiting and 64 MiB of rows waiting and running, except that one larger piece passes alone to an idle thread, so a full queue makes the calling thread wait): `fse-shard-write` writes them into the file at their offset (`pwrite`; a full disk raises an OSError there, which the calling thread raises at its next call of the sink, and the work after it is dropped), `fse-shard-hash` feeds the checksum of the vectors in row order, and `fse-shard-publish` publishes the finished shards (below), so the syncs of one shard do not stop the writing of the next; a task that crosses the end of a shard is split over the shards at its commit. One thread writes on purpose: two or four write threads into the same shard were not faster (`bench_length.py`, sentences, SIF float32 into a store at 10 workers, 1.33 GB in pieces of about 12 MB: median 0.59 s with one, 0.61 to 0.82 with two, 0.58 to 0.78 with four, M1 Pro at a load of 2.6 to 5.5), because each thread then spends about as long in `pwrite` into the fresh pages of the one file as the single one did, and the drive's durable write rate (with `F_FULLFSYNC`, at most 3.4 GB/s measured, so 0.39 s for these rows) bounds such a run anyway; gathering pieces into larger writes gains nothing either. When `close` runs in the main thread and SIGINT has Python's default handler (`signal.default_int_handler`), an interrupt (Ctrl+C) meanwhile is only noted: its handler abandons all three threads at once, so each finishes the piece it runs and drops the rest; further interrupts are noted too, and one KeyboardInterrupt is raised after every thread has ended (an event each sets as its last step, since an interrupted `Thread.join` of Python 3.11 and 3.12 can report a running thread as ended) and the temporary directories of the shards not published are removed. A shard whose publication was running is published if all its rows were written (else dropped), so `durable_rows` can still grow until `close` raises, and not after. There is no time bound: a piece that blocks (a write to a drive that hangs) keeps `close` waiting. With another handler, or from another thread, nothing is deferred. The queues hold no counters: the waiting pieces and the one running, under one condition, are their state, so an interrupt of the calling thread at any point leaves a piece queued or not. Writing through a mapping of the file from the workers instead cost about half the throughput (page faults on fresh file pages and a mapping per task: 1.04 against 1.96 million int8 rows per second at 10 workers on an M1 Pro, `bench_store.py`), and needed a zero-filled preallocation so a full disk could not end the process with SIGBUS. A shard whose rows are all committed is finished at once: a shard that ends early is shrunk to the header of its rows at the same data offset, the file is synced, the inverse norms, scales and manifest are written and synced, and the directory is renamed into place without ever replacing one, not even an empty one (`renameat2` with `RENAME_NOREPLACE` on Linux, `renamex_np` with `RENAME_EXCL` on macOS, `MoveFileExW` without replacing and with `MOVEFILE_WRITE_THROUGH` on Windows), then the store directory is synced (Windows has no directory sync, so its rename writes through). Only then `durable_rows` grows. On macOS `fsync` reaches only the drive cache, and `F_FULLFSYNC` does an `fsync` and then asks the drive to flush all its buffered data (fcntl(2)), which costs milliseconds. So a shard makes two: the files, the manifest and the first sync of the temporary directory are plain `fsync`s, the sync of that directory after the manifest is in place is the full one that makes all of them durable before the rename, and the sync of the store after the rename is the second (`write_manifest(..., staged=True)`; before, a shard made six or seven). Elsewhere every sync is the `fsync` it was. `seal` ends the current shard early, so a stream can make its rows durable before a shard is full; `publish` publishes what is finished; `flush` does both and needs every reserved row committed.
- **Errors and concurrency.** Leaving a ShardSink (`close` or its context) publishes the committed rows and drops the rest, also after an error (maintainer decision). Two writers that append at the same time race for the name of the next shard: exactly one rename succeeds, the other raises a FileExistsError naming the rows it already published, and removes its temporary data. The crash model is the local filesystem: a process that dies leaves the published shards as a valid prefix and its temporary directories, which readers ignore; durability against power loss rests on the syncs above; network filesystems are not covered.
- **Search.** `VectorStore.search(queries, k)` runs block by block in worker threads on the stored rows, through the inverse norms, without a normalized float32 copy, for blocks of rows and of queries that hold at most about 4 MiB of scores. `mode="exact"` uses the backend's `cosines` (the contract) and gives the ids and bits of the reference on the cpu backend (a device search would follow its own tolerance, see the tolerance contract). `mode="blas"` decodes each block to float32 (at most 16 MiB per task) and multiplies with BLAS: close to the contract, not bit-defined, so ties and nearly equal scores may order differently; it is faster for many queries, since BLAS uses the matrix units of the CPU (Accelerate on Apple silicon) and the contract fixes the order of every sum. For a few queries the kernel is as fast or faster, since every row is read once and need not be decoded. `mode="auto"`, the default, takes the contract for at most 8 queries and BLAS above (equal at 8 to 12 on 859,346 rows), so its bits depend on how many queries are asked at once; reproducible results need `mode="exact"` (maintainer decisions). Each block keeps the candidates of every query at or above its floor, the k-th best score merged so far, by the order of `top_k` (the larger score first, equal scores, -0.0 equal to 0.0, by the smaller row), which is total, so merging the blocks in any order gives the same ids. Every query is checked before any block is searched. `score(weights, bias)` gives the linear score with one or many weight vectors, with the same modes. `verify` hashes every shard and checks its values (finite scales and inverse norms of at least 0, finite float rows, int8 codes within +-127). A store cannot be closed while it is searched.

### Layout

New 2.0 code goes into private modules of `fse`: `_contract` and `_reference` (contracts and reference), `_codes` (storage arithmetic in blocks), `_container`, `_wordvectors` and `_wordvectors_format`, the gensim adapter `fse.gensim` (extra `fse[gensim]`), then the runtime and backends, the encoder, sinks and store. gensim is not a dependency of fse: `import fse` and every 2.0 class work without it (tests check it in a subprocess that blocks gensim and scipy).

The modules form layers, and a module imports only from layers below it. The import contracts in `pyproject.toml` (`[tool.importlinter]`, run by `make lint`) enforce this, and every new module must take a layer there:

1. `_head` (linear heads; they read stores in store mode)
2. `gensim` (the adapter, the only module that imports gensim) and `_store` (the shard sink and the vector store, which take an encoder), independent of each other
3. `_encoder` (the encoder; `fse` loads its names on first access, because import-linter counts every import of the native extension as an import of `fse` itself, so a static import in `fse/__init__.py` would read as a cycle through every layer)
4. `_runtime`
5. `_backends`, `_stream`, `_text_file`, `_hub`, independent of each other
6. `_text`
7. `_wordvectors`
8. `_wordvectors_format`, `_tokenizer_json`
9. `_reference_head` (the reference of linear heads, on the reference of the encoder)
10. `_container`, `_codes`, `_reference`, `_reference_text`, `_reference_wordpiece`, `_tokenizer_spec`, `_validation`, independent of each other: the references never share code with what they check
11. `_contract`, `_cpus`, `_unicode`, `_unicode_bert`

Inside a package, an import contract keeps its parts apart: `_npy` and `_safetensors` share only `_common`, which sits on `_hash`, each backend shares only `_base`, the runtime's pipeline sits on its tasks, sinks, spec and executor, in the encoder the encoder sits on `_pretrained`, that on the readers `_model2vec` and `_sentence_transformers`, those on `_files`, that on its batches and format and those on its inputs, in the containers the in-place writer `_npy_inplace` sits on `_npy` and the reader of foreign files `_foreign` on `_safetensors`, in the store the sink and the vector store sit on the shard writer and the search, those on the layout, the runtime's head sits on its pipeline, and in the heads the classes sit on the model, that on its runs, those on the scikit-learn reader, the format and the outputs, and those on the content.

The native extension `_native` is invisible to import-linter. `tools/check_guardrails.py` checks that only `_text` (stages 1 and 2) and the cpu backend `_backends._cpu` (the kernels) import it and that it imports only `_contract` from fse. It also checks that only `_container._hash` imports a hash library (hashlib or xxhash), and that the library of each device backend (`device-libraries` in `[tool.fse.guardrails]`: mlx, later CUDA's) is imported, by an import statement or `importlib`, only by that backend's `_backends._<name>._load`; `get_backend` imports that backend's package only when it makes the backend, so that `import fse` and the other backends never load it. A further contract forbids gensim, scipy, smart_open, psutil, threadpoolctl, wordfreq, torch and sklearn in all of fse, except gensim in `fse.gensim`; the checker applies the same list, with the device libraries, to the extension. Inside the mlx backend the backend sits on the device thread, that on the kernels, those on the Metal source and the loader.

### Defaults

Defaults are part of the API and chosen for speed: `workers` is the number of usable CPUs (`fse._cpus.usable_cpus`: an explicit `PYTHON_CPU_COUNT` or `-X cpu_count`, else the CPUs of the process affinity limited by the CPU quota of its Linux cgroup and every visible ancestor, rounded up (the quota is read once per process); `PYTHON_CPU_COUNT` thus also sets the default workers; small inputs run inline in the calling thread), and new encoders, also the pretrained ones on the hub, end with `normalize`, so the cosine of two rows is their dot product. A server that encodes many small requests in parallel sets `workers=1`.

### Baseline

`benchmarks/baseline/` records the values of fse 1.1.0 from PyPI that 2.0 is compared with: STS, an MTEB selection, training throughput, memory and a lifecycle benchmark. Its README holds the tables and the commands to reproduce them.
